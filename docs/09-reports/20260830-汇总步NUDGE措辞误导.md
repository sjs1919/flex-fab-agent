# 汇总步 NUDGE 措辞误导：LLM 误读「工具已不可用」为故障而拒绝任务

## 日期 / 场景

2026-08-30 · 问题「帮我查一下所有待排产的订单」产出答非所问（「抱歉，我无法完成这个查询…工具已不可用」），trace `8516ffd28bfa4789` / `231d41428f7e4482`。

## 根因

1. `query_orders` 空结果「未找到匹配的订单。」→ evaluate 空结果拦截 → 直接 `generate_answer`
2. 汇总步 LLM 第一次输出 DSML 标记文本（想再调工具确认）→ `ToolMarkupOutput` 捕获
3. 注入 `_SUMMARY_NUDGE`，措辞含「**工具已不可用**，请勿输出任何工具调用语法…」
4. **LLM 把「工具已不可用」误读为系统故障**，输出「抱歉，我无法完成这个查询…工具已不可用」拒绝话术
5. 护栏段落缺失仅告警不拦截（`guardrails/__init__.py:61`）→ 拒绝话术成为 `final_answer`

## 教训

**给 LLM 的系统提示/纠错话术，不得使用「工具不可用」「无法完成」等会被模型理解为系统故障的表述**——模型会据此拒绝任务，而不是纠正行为。应正向引导：「工具结果已收集齐全，请直接基于结果作答」。

另：护栏的「缺少必要段落」检查只告警不拦截（`is_valid=True`），LLM 的拒绝/答非所问文本无法被拦下。

## 规避动作

- `_SUMMARY_NUDGE` 措辞去掉「工具已不可用」，改为「工具结果已收集齐全，请勿再次调用工具，直接基于上述工具查询结果用中文给出最终回答」
- 重试时附已收集工具结果摘要（`tool_results` 前 200 字符/条），引导 LLM 基于数据作答
- 单测锁定：NUDGE 不含「工具已不可用」、重试附工具结果（`test_summary_nudge_no_fault_implication` / `test_summary_nudge_includes_tool_results`）
