## 1. 目标与非目标

### 1.1 目标

在 flex-fab-agent 中导入 PDF / Word / 图片多模态手册（设备使用 / 运维 / 故障恢复），经三级图片处理入库，调试台「手册库」单 tab 管理，Agent 经 `search_manual` 检索并带可定位溯源。

### 1.2 非目标（延续需求规格 4.2）

- 不做 .doc/.xlsx/.pptx；不做手册正文编辑器；不做多模态 embedding（图片以文本代理入索引）；不做跨版本内容 diff。
- **不重构现有合同 RAG 的数据结构**；合同库只做权限判定路径的最小适配。

## 2. 总体架构

```
┌─ 前端 ManualView（单 tab「手册库」三块）─────────────────────────────┐
│  手册列表 │ 解析详情+图片标注 │ 问答试验(role 下拉)                    │
└──────────────┬──────────────────────────────────────┬───────────────┘
               │ GET/POST/PUT/DELETE /manuals/*        │ POST /ask {query,role}
┌──────────────▼──────────────────────────────────────▼───────────────┐
│ api.py  手册路由段(插在 :675 静态块前) · AskRequest.role              │
│   ├─ 导入端点：落盘 inbox + 建 doc(queued) + job → 立即返回            │
│   └─ manual_import_worker.py  daemon 线程（startup 启动，串行消费）    │
│         parse → ocr → caption → index（stage_progress / failed_stage）│
└───────┬───────────────────────────────┬──────────────────────────────┘
        │ read/write                    │ call_vision
┌───────▼──────────────────────┐   ┌────▼───────────────────────────┐
│ rag/manual_retriever.py       │   │ core/vision_client.py           │
│  kb_manuals collection        │   │  VISION_PROVIDERS 遍历回落      │
│  incremental upsert/invalidate│   │  独立缓存(图hash+提示词版本)     │
│  过滤：metadata access+is_active│   └──────────────┬─────────────────┘
└───────┬──────────────────────┘              ┌──────▼──────────────┐
        │ search_manual 工具                    │ volc-vision / 海外  │
└───────▼──────────────────────────────────┘  └─────────────────────┘
 graph 读工具按会话 role 签 token → registry.execute 注入 → 权限过滤
```

分层：**API/worker → 导入编排 → 解析(loaders/ocr/caption) → 向量(index/retriever) → vision client → 权限(grapth token) → 前端**。

## 3. 关键设计决策（含选型论证）

### D1 权限修复选「方案一」：graph 按会话 role 给 RAG 读工具签 token

**代码事实**：
- `single_agent_graph.py:247-254`：`token=None`；仅当 `not schema.read_only` 才自签 admin。→ 只读的 `search_knowledge_base` 恒拿 `token=None`。
- `registry.execute`（`tools/registry.py:144`）：只在 `token is not None and name in _TOOLS_NEED_TOKEN` 才把 token 注入 handler。token 是 RAG 权限过滤**唯一传递通道**。
- `guard.check_tool_permission`（`registry.execute` 无条件调用，`:123`）：读工具 + token=None 放行（R-2 兼容）；读工具 + 有 token 会走 RBAC 校验。

**为什么不是方案二（retriever 读会话角色）**：RAG handler 既被 HTTP `/ask` 的 graph 调，也可能被 CLI `main.py` / 后台线程调，无统一请求上下文；方案二需新造一条「会话角色 → handler」的旁路，反而引入新全局态。方案一是现状形态的顺势扩展。

**角色来源（单机部署无登录）**：给 `AskRequest` 加 `role`（`api.py:141`），默认 `"admin"`——对齐 `/debug/admin-token` 匿名签发 admin 的既有惯例（调试台操作者视为管理员）。调试台/手册问答提供角色下拉，可模拟 operator/viewer 验证低权限过滤。

**改动**：
1. `api.py:467 _run_agent_round(query, thread_id=None, role="admin")` 透传 role。
2. `agents/single_agent.py run_single_agent` 增 `role` 参数 → 写入 graph `state["role"]`。
3. `single_agent_graph.py:247-254` 工具执行段改为：
   ```
   if schema and not schema.read_only:            # 写工具：现状不变
       sign "admin"
   elif schema and state.get("role") and name in _TOOLS_NEED_TOKEN:  # RAG 读工具
       sign state["role"]
   ```
   沿用 `STS().issue_user_token(subject, role)` 机制（同一段已有）。
4. `tools/registry.py:25 _TOOLS_NEED_TOKEN` 加 `"search_manual"`。
5. RBAC 白名单 `auth/token_exchange.py:35-41` 加 `search_manual`，对 admin/reviewer/operator/viewer **全角色放行**（与 `search_knowledge_base` 现状一致）——**guard 层不做 confidential 判定**，confidential 内容过滤在 RAG 层 `_allowed_sources` 按 role 做（同现状 `search_knowledge_base` 语义）。

**验收回归点**：默认 role=admin 提问手册内 confidential 内容 → 可命中（修复前永不命中）；role=operator → 过滤掉。spec 10.1 两条权限测试落地于此。

### D2 手册向量库与状态独立 + 增量灌库

**现状**：合同 collection `kb_contracts_delay` 一次性灌库（`knowledge_base.py:82 count>0 即复用`），`_rag_state` 单例冻结 BM25（`retriever.py:135`）。

**设计**：
- 新增 `rag/manual_index.py` 管理手册向量库（collection `kb_manuals`），**不触碰合同 collection 与 `_rag_state`**。
- Chroma id 约定 `doc:{doc_id}:{seq}`，保证跨手册全局唯一、按 doc_id 可整体 delete/重建。
- 增量语义：灌录用 `collection.upsert(ids=..., documents=..., metadatas=...)`（Chroma 按 id 覆盖）；删手册/删版本用 `collection.delete(where={"doc_id": X})`。
- 手册态独立：`manual_retriever._manual_state`（collection + bm25 + chunks + metas + reranker），与合同 `_rag_state` 分离。灌库/删库后调 `manual_retriever.invalidate()` 置空，下次检索重建——**只影响手册，不动合同 BM25**。
- 合同知识库的「count>0 整体复用」语义**保持现状不改**（合同语料静态）；手册走全新增量模块，不复用那段代码，避免为老代码引入新状态。

### D3 检索过滤：融合后 rerank 前，按 chunk metadata 过滤（access 冗余进 metadata）

**权限数据驱动落地的务实收敛**：手册量多、权限按手册配，因此手册 chunk 在**灌库时**把 `access`（来自 `manual_doc.access`）与 `is_active` 冗余写入每块 metadata——检索过滤直接读 metadata，**不查库、不建权限映射表**。合同的 `DOC_PERMISSION`（`knowledge_base.py:30`，仅 1 条 confidential）保留现状文件级 dict 不动。这比「把 DOC_PERMISSION 改数据驱动 + 新建映射表」更小、达成同样效果（手册权限在导入/编辑 `manual_doc.access` 即一次生效），spec 2.6 那条「改数据驱动」以满足语义、不做结构推翻收尾。

- 检索过滤发生在 `retrieve_hybrid` 的融合后、rerank 前位置（`retriever.py:130` 现有 `doc_permission` 过滤同处），两库统一谓词：`allowed_meta(meta, role) = meta["access"] ∈ (role in {admin,reviewer} ? {public,confidential} : {public}) AND meta.get("is_active","1")=="1"`。
- **两路召回都预过滤**，避免无谓召回：向量路用 chroma `query(where={"is_active":"1", "access": allowed 列表})`；BM25 路在 `bm25_search` 出结果后按 metadata 过滤（历史版/越权块不进 RRF）。
- 手册检索实现放 `rag/manual_retriever.py`，复用 `retriever.py` 导出的 `bm25_search / rrf_fuse / rerank / load_reranker / _role_from_token / _allowed_sources`（这些已是模块函数，可 import）。

### D4 异步导入 worker：daemon 线程 + startup，串行消费，分阶段进度，可续跑

**代码事实**：现有后台线程模式 = `@app.on_event("startup")`（`api.py:127`）+ `threading.Thread(daemon=True)`（`auto_scheduler.py:48`）；进程级单例 `get_scheduler()`（`auto_scheduler.py:240`）。

**设计**（新 `rag/manual_import_worker.py`，同类结构）：
- `get_import_worker()` 单例 + `start()`：先清僵尸（DB 残留 `status='running'` → `failed` + 记录，覆盖容器重启场景），再起单 daemon 线程消费。
- 串行队列：`SELECT * FROM manual_import_job WHERE status='queued' ORDER BY id LIMIT 1` → 置 running → 按阶段执行 → done/failed。**并发 1**（v1 防 OCR/图注打满 CPU；阶段 1 spike 后如需再配 concurrency）。
- 阶段流转：`parse → ocr → caption → index`，每阶段开始把当前阶段写入 `failed_stage`，失败留 `failed_stage` 供 retry 从该阶段续跑，不整份重解析。
- `stage_progress` 存当前阶段 `done/total`（如 `ocr 12/56`），前端展示阶段进度条。
- **单图失败降级**：ocr/caption 阶段逐 asset `try/except`，单张失败置 `manual_asset.review_status='flagged'` / `caption_source='none'`，继续下一张，不使整份失败。
- LLM 阶段限时：单张 call_vision 带 timeout；连续 N 张失败则整份标 failed（含 `failed_stage='caption'`）可重试。
- index 阶段失败（chroma 写失败）整体回滚该手册已建向量？不——chroma 无事务；失败则标记 failed，重试从 index 续跑（upsert 幂等，按 id 覆盖）。

### D5 `core/vision_client.py`：独立多模态 provider 抽象 + 独立缓存

- `config.py` 紧随 `PROVIDERS`（:116）新增 `VISION_PROVIDERS` / `PRIMARY_VISION_PROVIDER` / `available_vision_providers()`，条目同构 `{name, enabled, api_key, base_url, model, note}`。预置条目见 spec 3.1（火山标准端点 / 海外 vision / 本地 VLM 末位）。
- `call_vision(prompt, image_paths, bypass_cache=False) -> str`：
  - 图片读为 base64，入参走 OpenAI 兼容 `user content = [{"type":"text"...}, {"type":"image_url","image_url":{"url":"data:image/{fmt};base64,..."}}]`。
  - **独立 client 缓存**（不复用文本 `_client_cache`，模型/端点不同）；遍历 `available_vision_providers()` 首个成功即返回；超时/失败切下一个；全失败 raise（上层降级为 `caption_source=none`）。
  - **独立缓存**：落 `RUNTIME_DIR/vision_cache.sqlite`，键 = `sha256(拼接 base64)` + `CAPTION_PROMPT_VERSION` + provider.model。`bypass_cache=True`（L3 重生成）跳过读+跳过写。
  - 文本 provider 的 `thinking` extra / 精确缓存语义不适用，**不走 `call_llm`**，单独一套（理由见上）。
- `CAPTION_PROMPT_VERSION` 常量：改提示词模板即 bump，旧缓存自然失效。
- 单测 monkeypatch `lc.VISION_PROVIDERS`（照 `core/test_llm_client.py:68`），mock HTTP 不发真实调用。

### D6 解析/OCR/切分选型（阶段 1 spike 验证，此处给默认）

| 能力 | 默认选型 | 备选 | 判据 |
|------|---------|------|------|
| PDF（文本层+内嵌图+扫描页判定） | **PyMuPDF(fitz)** | pypdf | 页级文本/图片/渲染一站式，扫描页文本字符数判定易实现 |
| Word .docx（正文+标题层级+内嵌图） | **python-docx** | — | 样式驱动 heading 层级标准 |
| 本地 OCR（中文，离线） | **RapidOCR(onnxruntime)** | PaddleOCR | 离线、轻、CPU 可跑；PaddleOCR 依赖重 |
| 独立图片 | 同一 OCR 管线 | — | — |

- 扫描页判定：页提取文本层后 `len(净文本) < 阈值`（如 20 字）→ 该页渲染成图走 OCR。
- 解析库**离线安装验证**是阶段 1 必须项（`requirements-flex-fab-agent.txt` 追加，容器需可 pip 装）。

### D7 图片 asset 落库、文本切片不落库（标注流程驱动）

- `manual_asset`（DB）承载三级策略与人工标注闭环——**图片需要被检索到、被人工修正、重灌向量**，必须落库。
- 文本切片不落 DB，存 chroma（`collection.get(where={"doc_id"})` 可回查）。「切片预览」改为：详情接口实时取该手册全部 chunk 摘要（`meta.doc_id 过滤 + text[:200]`），分页在前端；**不建 manual_chunk 表**——避免把 chroma 已存文本再存一份 DB 的双写。
- 手册原文件 / 渲染图落盘：`RUNTIME_DIR/manuals/{doc_id}/原文件`、`RUNTIME_DIR/manuals/{doc_id}/images/page_{n}_{i}.png`；上传中转目录 `RUNTIME_DIR/manuals_inbox/`。RUNTIME_DIR 容器内挂卷（`docker-compose.yml:14`），重启不丢。

## 4. 数据层 schema v6

> 迁移范式照 `schema/migrate.py`：`CURRENT_VERSION 5→6`，`_MIGRATIONS[6]=(_up_v6,_down_v6)`；DDL 常量放 migrate.py 顶部并同步 `schema.sql`。沿用 utf8mb4_unicode_ci、`TEXT` 存 JSON、显式 KEY 命名。

### 4.1 `manual_doc` —— 手册主记录

```sql
CREATE TABLE IF NOT EXISTS manual_doc (
    id           BIGINT AUTO_INCREMENT COMMENT '手册 id',
    title        VARCHAR(200) NOT NULL COMMENT '手册名',
    device_model VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '设备型号（版本分组键，D 版 v1.2）',
    version      VARCHAR(32)  NOT NULL DEFAULT 'v1' COMMENT '版本号',
    is_active    TINYINT(1)   NOT NULL DEFAULT 1 COMMENT '是否激活版（同型号仅一个=1，检索只命中它）',
    category     ENUM('machine','ops','recovery','other') NOT NULL DEFAULT 'other'
                 COMMENT 'machine=设备使用/ops=生产运维/recovery=故障恢复/other',
    access       ENUM('public','confidential') NOT NULL DEFAULT 'public' COMMENT '权限（D1 冗余进 chunk metadata）',
    file_path    VARCHAR(500) NOT NULL COMMENT '原文件路径（RUNTIME_DIR/manuals/{id}/）',
    file_type    ENUM('pdf','docx','image') NOT NULL COMMENT '格式',
    file_size    BIGINT       NOT NULL DEFAULT 0 COMMENT '字节',
    file_hash    CHAR(64)     NOT NULL COMMENT 'SHA256（同文件重复导入幂等）',
    page_count   INT          NOT NULL DEFAULT 0 COMMENT '页数（图片/扫描按渲染页）',
    status       ENUM('pending','parsing','indexed','failed','archived') NOT NULL DEFAULT 'pending'
                 COMMENT 'pending=待处理/parsing=解析中/indexed=已入向量库/failed/archived',
    chunk_count  INT          NOT NULL DEFAULT 0 COMMENT '文本切片数（落 chroma）',
    asset_count  INT          NOT NULL DEFAULT 0 COMMENT '图片资产数（落 manual_asset）',
    error_msg    VARCHAR(500) NULL COMMENT '失败原因（failed 时）',
    created_at   DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    indexed_at   DATETIME     NULL,
    PRIMARY KEY (id),
    UNIQUE KEY uk_doc_model_version (device_model, version),
    KEY idx_doc_status (status),
    KEY idx_doc_active (is_active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='手册主记录（所有权：manual import）';
```

- 同型号激活唯一由应用层保证：激活/导入事务内先 `UPDATE manual_doc SET is_active=0 WHERE device_model=? AND id<>?` 再置 1（DB 无法用单列唯一约束表达「同型号一个激活」，设计不做 DB 级约束，用事务保证）。
- `device_model+version` 唯一：同型号同版本再导入 = 覆盖更新该版本（新文件重解析替换），保留唯一约束做冲突提示。

### 4.2 `manual_asset` —— 图片资产（三级策略载体）

```sql
CREATE TABLE IF NOT EXISTS manual_asset (
    id             BIGINT AUTO_INCREMENT COMMENT '资产 id',
    doc_id         BIGINT NOT NULL COMMENT '归属手册',
    page_no        INT    NOT NULL DEFAULT 0 COMMENT '所在页（扫描/独立图=渲染页）',
    image_path     VARCHAR(500) NOT NULL COMMENT '渲染图/原图路径',
    ocr_text       TEXT   NULL COMMENT 'L1 OCR 原文',
    ocr_confidence DECIMAL(5,4) NULL COMMENT 'OCR 平均置信 0-1',
    caption        TEXT   NULL COMMENT '最终入索引文本（OCR 摘要 / 图注 / 人工说明）',
    caption_source ENUM('ocr','vlm','human','vlm_regen','none') NOT NULL DEFAULT 'none'
                 COMMENT '来源：ocr=L1/vlm=L2 自动图注/human=L3 人工/vlm_regen=L3 LLM 重生成/none=降级未处理',
    review_status  ENUM('ok','flagged','fixed') NOT NULL DEFAULT 'ok'
                 COMMENT 'flagged=人工标「识别不准」待处理/fixed=已人工修正',
    vector_id      VARCHAR(96) NULL COMMENT 'chroma id（doc:{doc_id}:img:{id}，upsert 幂等键）',
    updated_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_asset_doc (doc_id),
    KEY idx_asset_review (review_status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='手册图片资产（三级处理，所有权：manual import + 人工标注）';
```

### 4.3 `manual_import_job` —— 导入任务（D4）

```sql
CREATE TABLE IF NOT EXISTS manual_import_job (
    id            BIGINT AUTO_INCREMENT COMMENT '任务 id',
    doc_id        BIGINT NOT NULL COMMENT '目标手册',
    stage         ENUM('parse','ocr','caption','index') NOT NULL COMMENT '当前阶段',
    stage_progress VARCHAR(64) NULL COMMENT '阶段内进度，如 ocr 12/56',
    status        ENUM('queued','running','done','failed') NOT NULL DEFAULT 'queued',
    message       VARCHAR(500) NULL COMMENT '结果/失败原因',
    retry_count   INT NOT NULL DEFAULT 0,
    failed_stage  ENUM('parse','ocr','caption','index') NULL COMMENT '失败阶段（retry 从这里续跑）',
    created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    finished_at   DATETIME NULL,
    PRIMARY KEY (id),
    KEY idx_job_status (status),
    KEY idx_job_doc (doc_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='手册导入任务（异步 worker，所有权：manual import）';
```

### 5.1 三级图片处理流程（落地）

```
doc parse → 收集 pages + images 落盘 RUNTIME_DIR/manuals/{doc_id}/
  ocr 阶段: 每张图 ocr_image
     ├─ 有文字且 conf 达标 → caption=OCR摘要文本(取前 N 行/首屏文本) caption_source=ocr
     └─ needs_caption(text,conf)=true（空/字数<MIN/conf<TH）→ caption 阶段队列
  caption 阶段: 每张待处理图 generate_caption（call_vision，无 provider 时降级 none+flagged）
  index 阶段: 全部 chunk（文本块 + 图片块 caption）按 doc_id upsert 进 kb_manuals
              → invalidate manual 检索态 → doc.status=indexed + job done
```

- 图片入索引的 chunk：`{text: caption, doc_id, access, is_active, page_no, asset_id, chunk_type:'image'}`；检索命中图片时返回「图 N · 原图 URL」。

## 10. 实施顺序建议（对接待办阶段 1→7）

1. **阶段 1 spike**（不可跳）：解析库离线安装 + 一份真实大扫描件端到端测耗时 → 反推并发与超时，敲定 PyMuPDF/python-docx/RapidOCR 型号。
2. **权限先行**（D1，独立可合入）：因为 C3 牵的 token bug 与 `search_manual` 一并解决收益最大；先做 graph role 注入 + AskRequest.role，手动验证 `/ask role=operator` 过滤。
3. **schema v6 + 模块骨架**：migrate 三表 + manual_index/manual_retriever/vision_client 空实现跑通检索不炸。
4. **vision/OCR/loaders/captioner/chunker**：从图片三级处理最小闭环（独立图 → OCR → 入向量 → 检索到）做起，再扩 PDF/docx。
5. **异步 worker + 导入 API**：scan/upload → job → worker 阶段机。
6. **前端 ManualView + 挂载**。
7. **收尾**：操作日志动作映射、冒烟、RAGAS 可选门禁、验收清单走查。

每步产出「步骤→验证」：后端单测 + `run_all_tests.py` 全过 + 前端 `npm run build` 才进下一步。

## 12. 风险与注意（承接 spec §11，落地到本设计）

- **解析库离线安装**：WSL/容器无外网或受限，PyMuPDF/RapidOCR 的 wheel 需提前下载或走代理（`HTTPS_PROXY=127.0.0.1:3450`）；阶段 1 spike 第一验证项。
- **大扫描件解析时长**：单 worker 串行下 OCR 是全瓶颈；几十份若真到小时级，需接受「导入是后台慢慢跑」的定位 + 前端清晰进度，spike 拿到真数后把超时/进度粒度定死。
- **chroma 双 collection**：同 DB_DIR（`RUNTIME_DIR/chroma_db`）两个 collection 并行无冲突；文档删改只 invalidate 手册态，合同态稳定。
- **role=admin 默认值**：保持既有惯例，但要防「管理员默认看全部」掩盖过滤逻辑缺陷——验收必须有 role=operator/viewer 用例（T3）。
- **图片原图访问**：`GET /manuals/assets/{id}/image` 走显式路由（先注册），不被 catch-all 吞；读取路径仅限 `RUNTIME_DIR/manuals/`，防路径穿越（照 `api.py:686` 的 `is_relative_to` 防护）。
- **cache 一致**：L3 重生成若 bypass 失败（读了缓存）会返回旧图注、看起来像没反应——`bypass_cache` 必须同时跳过读与写，T5 显式断言。
- **目录扫描写操作**：扫描会批量建任务，需 admin + 确认对话框（避免误扫入无关文件——inbox 固定目录降低风险）。
