## 2. 部署路径选择

| 路径 | 适配性 | 结论 |
|------|--------|------|
| **A. Docker Compose（host 网络）** | ✅ 服务器有 Docker；compose host 网络直连宿主 MySQL | **推荐**（与 v2 一致） |
| **B. 本地构建镜像推服务器** | ⚠️ 服务器内存不足以 `docker build`（npm/pip 依赖安装内存峰值） | **备选**（见 §6 内存风险） |
| C. 服务器原生 venv | 需另装依赖、与现有容器混跑无隔离 | 不推荐 |

> **结论**：内存仅 1.6Gi，`docker compose build` 大概率内存不足。**推荐本地构建镜像 `docker save` 导出 → 服务器 `docker load` 导入**（§4 路径 B），或服务器先加 swap 再构建。

## 3. 前置准备（服务器）

### 3.1 MySQL 建库 + 用户

服务器 MySQL 8.0（`127.0.0.1:3306`）已运行。用 root 建 flex-fab-agent 专用库与用户（口令按实际填，写入凭据文件）：

```sql
CREATE DATABASE IF NOT EXISTS flex_fab_agent
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'flex_fab_agent'@'localhost' IDENTIFIED BY '<你的口令>';
GRANT ALL PRIVILEGES ON flex_fab_agent.* TO 'flex_fab_agent'@'localhost';
FLUSH PRIVILEGES;
```

### 3.2 模型缓存目录（reranker / embedding）

compose 挂载 `HF_CACHE_HOST` 到容器 `/root/.cache/huggingface`。**服务器上目录默认 `/home/wenext` 不存在（v2 教训）**，必须设为真实路径：

```bash
# 服务器创建缓存目录（root 用户）
mkdir -p /root/.cache/huggingface /root/.cache/chroma
# reranker（bge-reranker-base ~1.1GB）+ embedding（bge-small-zh-v1.5）需缓存；
# 未缓存时容器内走 HF_ENDPOINT=https://hf-mirror.com 下载（RAG 问才触发，普通问不受影响）
```

### 3.3 凭据配置

服务器上创建（**gitignored，不入库**）：

| 文件 | 内容 |
|------|------|
| `.env` | LLM key（DEEPSEEK_API_KEY / VOLC_API_KEY）、`FLEX_FAB_AGENT_DATA_SOURCE=mysql`、`MYSQL_HOST=127.0.0.1`（host 网络）、`MYSQL_DB=flex_fab_agent`、`MYSQL_USER=flex_fab_agent` |
| `docs/demo/credentials.local.md` | 从本机 flex-fab-agent 复制（含 MYSQL_PASSWORD / LLM key 真实值）或按 `.example` 模板填写 |

## 4. 部署步骤

### 路径 A：服务器直接构建（内存充足时）

```bash
# 1. clone（服务器）
git clone https://github.com/sjs1919/flex-fab-agent.git /opt/flex-fab-agent
cd /opt/flex-fab-agent

# 2. 配置（见 §3.3）
cp .env.example .env        # 填真实 key
# credentials.local.md 从本机复制或按模板填

# 3. 构建 + 启动（host 网络，8000 直连）
docker compose build
docker compose up -d

# 4. 建表 + 种子（首次）
docker exec flex-fab-agent-api python -m flex_fab_agent.schema.migrate --up
docker exec flex-fab-agent-api python -m flex_fab_agent.simulator.seed --reset
```

### 路径 B：本地构建镜像推服务器（推荐，规避服务器内存不足）

```bash
# 本机（WSL，flex-fab-agent 目录）
docker build -t sjs1919/flex-fab-agent:20260830 .
docker save sjs1919/flex-fab-agent:20260830 | gzip > flex-fab-agent.tar.gz
scp flex-fab-agent.tar.gz token_hub_120:/tmp/

# 服务器
docker load < /tmp/flex-fab-agent.tar.gz
cd /opt/flex-fab-agent   # clone + 配置后（§4 路径 A 的 1-2 步）
docker compose up -d     # compose 已 build: . 指向本地镜像，up 即用
```

## 6. 风险与注意事项

| 风险 | 影响 | 缓解 |
|------|------|------|
| **内存 1.6Gi 不足** | `docker build` OOM；reranker 加载 OOM | ① 路径 B 本地构建推镜像；② 服务器加 swap（`fallocate` 2G + mkswap + swapon）；③ reranker 未缓存时 RAG 问受限（非 RAG 功能正常） |
| reranker 1.1GB 下载/加载 | RAG 合同检索慢/失败 | 预热缓存（`docker exec ... python -c "from flex_fab_agent.rag.retriever import load_reranker; load_reranker()"`）；或接受 RAG 降级 |
| host 网络 | 容器直连宿主网络栈，8000 无端口映射 | 确保 8000 未被占用（实测空闲）；防火墙放行 8000 |
| 与现有容器共存 | trade-api:6000 / trade-server:6060 / token-hub-portal:8081 | 端口不冲突；资源竞争靠 swap + 限制（compose `mem_limit` 可设 `512m`） |
| MySQL 连接 | host 网络下容器直连 `127.0.0.1:3306` | 确认 MySQL 监听 127.0.0.1 且 `flex_fab_agent` 用户 `@localhost` 可连 |

## 7. 部署实操记录（2026-08-30，token_hub_120）

### 7.1 本次部署变更（已执行）

1. **服务器环境**：
   - 加 swap 2G：`fallocate -l 2G /swapfile && mkswap /swapfile && swapon /swapfile`，fstab 持久化 `/swapfile none swap sw 0 0`（内存 1.6Gi 实测极紧，无 swap 时可用仅 ~344Mi）
   - 停止 token* 容器：`token-hub` / `token-hub-portal` / `token-hub-frontend`（仅释放 ~49Mi，主要靠 swap 兜底）
2. **MySQL**：SSH 用户 `token_hub`（UID 1000，非 root）。用 `token` 用户（`token@%` ON *.* 全权限，密码取自 token-hub 容器 env）建库 `flex_fab_agent`（utf8mb4_unicode_ci）。应用 DB 用户沿用 `token`。
3. **前端入镜像**（原 web/dist 为 compose 宿主挂载，改为打进镜像）：
   - `Dockerfile` 追加 `COPY web/dist ./web/dist`
   - `docker-compose.yml` 删除 `./web/dist:/app/web/dist` 挂载行
4. **子路径部署 `https://dev.wzhlink.cn/flex-fab-agent/`**（nginx 去前缀 → 应用根，后端零改动）：
   - `web/vite.config.ts`：`base: command === 'build' ? '/flex-fab-agent/' : '/'`（dev 保持根路径）
   - `web/src/router/index.ts`：`createWebHistory(import.meta.env.BASE_URL)`
   - `web/src/api/*.ts`（5 文件）：axios `baseURL: import.meta.env.BASE_URL`
   - 新增 `web/src/vite-env.d.ts`：`/// <reference types="vite/client" />`（启用 import.meta.env 类型）
   - nginx：`server_name dev.wzhlink.cn`，`location /flex-fab-agent/ { proxy_pass http://127.0.0.1:8000/; }`（证书 `dev.wzhlink.cn.pem/.key` 已存在 `/etc/nginx/ssl/`）
5. **HF 缓存路径**：SSH 用户非 root 且 `/root` 不可写 → 挂载改 `/home/token_hub/.cache/{huggingface,chroma}`，compose 用 `HF_CACHE_HOST`/`CHROMA_CACHE_HOST` 环境变量覆盖默认 `/home/wenext`。

### 7.2 部署命令序列（路径 B：本地构建 → 推服务器）

```bash
# ① 本地（WSL，勿在 Windows 构建）
cd /mnt/c/workspace/projects/flex-fab-agent
cd web && npm run build && cd ..        # 前端带 /flex-fab-agent/ base
docker build -t sjs1919/flex-fab-agent:20260830 .
docker save sjs1919/flex-fab-agent:20260830 | gzip > flex-fab-agent.tar.gz

# ② 传输（.env / credentials.local.md 均 gitignored，scp 直传；勿走 git）
scp flex-fab-agent.tar.gz token_hub_120:/tmp/
scp docker-compose.yml .env docs/demo/credentials.local.md token_hub_120:/home/token_hub/flex-fab-agent/

> ⚠️ **scp 路径坑（实测踩过）**：多文件 scp 到目标目录会**扁平化路径**，`docs/demo/credentials.local.md` 会落到项目根目录而非 `docs/demo/` 下 → compose 挂载源缺失，docker 会自建一个 root 目录 → 应用启动报 `IsADirectoryError`。修正：
> `rmdir <项目根>/docs/demo/credentials.local.md && mv <项目根>/credentials.local.md <项目根>/docs/demo/credentials.local.md`
> （先删 docker 建的挂载空目录，再放真实文件，最后 `docker compose up -d --force-recreate`）

# ③ 服务器 .env 覆盖（密码取 token-hub 容器 env，不回显）
#   MYSQL_HOST=127.0.0.1 / MYSQL_PORT=3306 / MYSQL_DB=flex_fab_agent / MYSQL_USER=token
#   MYSQL_PASSWORD=<token DB 密码>  （.env 原无此键，需追加，env 优先于 credentials 兜底）
#   FLEX_FAB_AGENT_DATA_SOURCE=mysql
#   HF_CACHE_HOST=/home/token_hub/.cache/huggingface
#   CHROMA_CACHE_HOST=/home/token_hub/.cache/chroma

# ④ 服务器（docker 免密，无需 sudo）
docker load < /tmp/flex-fab-agent.tar.gz
cd /home/token_hub/flex-fab-agent
docker compose up -d
docker exec flex-fab-agent-api python -m flex_fab_agent.schema.migrate --up
docker exec flex-fab-agent-api python -m flex_fab_agent.simulator.seed --reset

> ⚠️ **compose 必须声明 `image:` 标签**（服务加 `image: sjs1919/flex-fab-agent:20260830`）：若仅有 `build: .`，`docker compose up` 会在服务器重新构建镜像（1.6Gi 内存不足会 OOM）。`build` + `image` 并存时，`up` 优先用已 `docker load` 的镜像。

# ⑤ nginx 反代（需 sudo，root 权限，见 §7.1-4）
#   vim /etc/nginx/sites-enabled/flex-fab-agent.conf   ← 用户执行
#   nginx -t && systemctl reload nginx
```

### 7.4 内存评估（已加 swap 后）

| 项 | 值 |
|----|-----|
| RAM 1.6Gi + swap 2G | 虚拟 ~2.4GB |
| 基础应用 | ~300-500MB ✅ 物理内存可容纳 |
| reranker ~1.1GB | 懒加载（RAG 合同检索触发），走 swap 变慢但不 OOM；普通问不受影响 |
| CP-SAT 求解 | 2 核够用，内存中等 |

可选优化：`docker exec flex-fab-agent-api python -c "from flex_fab_agent.rag.retriever import load_reranker; load_reranker()"` 预热缓存；或 compose 加 `mem_limit`。

### 7.5 故障记录（2026-08-30 整机冻结事件）

**现象**：容器 `sim/start` 后约 2 分钟，服务器整机无响应 —— Ping 通但 SSH banner / 全部 HTTP 端口（8000/80/6060）超时，trade 服务连带不可用。

**取证**：重启后查容器 `OOMKilled=false`、ExitCode 255、日志无错误。内核未 OOM 杀容器，属**整机资源耗尽（进程层饿死）**。

**根因候选**（叠加或二选一）：
1. **内存换页抖动**：容器启动即导入 transformers/sentence-transformers/chromadb（RSS 1-2GB）+ CP-SAT 求解峰值 → 超 1.6Gi RAM，2G swap 持续换页 → 全系统冻结（内核 OOM 只在分配失败触发，换页压力不触发）
2. **CPU 忙循环**：auto_scheduler/CP-SAT 求解不终止 → 2 核打满 → sshd 抢不到 CPU → banner 超时

**恢复**：阿里云控制台强制重启（flex-fab-agent compose 无 restart 策略，重启后不自启）。恢复后 load 0.21、trade healthy、swap 未用。

**护栏（再部署必须）**：
- `AUTO_SCHEDULE_ENABLED=off`（config.py:206，关闭 CP-SAT 自动排产循环）
- compose 加 `mem_limit`（如 1024m）+ `memswap_limit`（如 1536m）→ cgroup 限流，超限只杀容器不冻宿主
- compose 加 `cpus: 1.5` → 限制 CPU 不占满双核
- 模拟器不自动启动（启动即触发重负载），需要时手动 `POST /sim/start`
- 接受 RAG/reranker 降级（~1.1GB 模型在 1024m 下不可加载）
