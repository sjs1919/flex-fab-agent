## 3. 路径 B 实操步骤（推荐）

### 3.1 启动 MySQL（宿主，仅一次）

WSL2 的 systemd 兼容性差，用 `mysqld_safe` 手动启动（详细踩坑见 `docs/demo/09-reports/20260825-WSL-MySQL-systemd踩坑.md`）：

```bash
# 1. /var/run 每次 WSL 重启会清空，先重建
sudo mkdir -p /var/run/mysqld
sudo chown mysql:mysql /var/run/mysqld

# 2. 后台启动
sudo mysqld_safe --datadir=/var/lib/mysql --pid-file=/var/run/mysqld/mysqld.pid &

# 3. 等就绪并验证
sleep 10 && sudo mysqladmin ping
```

验证库已存在（数据目录已初始化，demo_scheduling 库与业务用户 **08-26 已固化**，正常应存在）：

```bash
sudo mysql -u root -e "SHOW DATABASES LIKE 'demo_scheduling'; SELECT COUNT(*) FROM demo_scheduling.orders\G" 2>&1
```

> ⚠️ 若库不存在或 orders=0（WSL 重置后），执行**建库+迁移+种子**，口令取自 `docs/demo/credentials.local.md`：
> 💡 seed 产出 orders=20，满足冒烟断言（`demo/smoke_test.py:245` 为 `>=20`）；部署指南 v1 §9 写的「订单 ≥30」为过时值，以实测为准。
> ```bash
> sudo mysql -u root -e "CREATE DATABASE IF NOT EXISTS demo_scheduling CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
> CREATE USER IF NOT EXISTS 'demo_sched'@'127.0.0.1' IDENTIFIED BY 'w9AbsWcOuP9AUm71NqtYyYk1';
> GRANT ALL PRIVILEGES ON demo_scheduling.* TO 'demo_sched'@'127.0.0.1'; FLUSH PRIVILEGES;"
> docker exec demo-api python -m demo.schema.migrate --up
> docker exec demo-api python -m demo.simulator.seed --reset
> ```

### 3.2 构建并启动后端容器

```bash
cd /mnt/c/workspace/projects/agent-training

# ⚠️ 关键：本机 WSL 用户是 root，必须覆盖 compose 默认挂载路径（/home/wenext 不存在）
export HF_CACHE_HOST=/root/.cache/huggingface
export CHROMA_CACHE_HOST=/root/.cache/chroma

# 首次构建较慢（pip + torch CPU 版）；容器内 Python 3.11 自动满足
docker compose up -d --build

# 看启动日志，确认无报错
docker logs -f demo-api        # 看到 "Uvicorn running on 0.0.0.0:8000" 即成功
```

> 容器 `network_mode: host` → 宿主 `8000` 直通容器；`MYSQL_HOST=127.0.0.1` 直连宿主 MySQL（已启动）。

### 3.3 前端（二选一）

| 方式 | 命令 | 地址 | 适合 |
|------|------|------|------|
| **A. Vite dev（HMR）** | `cd web && npm run dev` | `http://localhost:5173` | 开发/改前端 |

> 方式 A 的 vite 代理已把 `/dashboard /kpi /debug /config /ask /schedule` 指向 `127.0.0.1:8000`（vite.config.ts），WSL 内 dev server 与 host 网络容器同网段，直连即可。

### 4.3 失败排查速查

| 失败项 | 常见原因 | 排查命令 |
|--------|---------|---------|
| S1 provider 为空 | 凭据文件没加载 / 容器挂载失效 | `docker exec demo-api python -c "from demo.config import available_providers; print(available_providers())"` |
| S2/S3 数据为空 | MySQL 未启动 / 没 seed | `mysqladmin ping`；`docker exec demo-api python -m demo.simulator.seed --reset` |
| S4 /health 不通 | 容器没起来 / 端口占用 | `docker logs demo-api`；`curl http://localhost:8000/health` |
| S7 排产失败 | ortools 缺失（容器已含）/ 数据为空 | `docker exec demo-api python -c "from demo.scheduler.solver import run_scheduling; print(run_scheduling())"` |
| S10 /ask 失败 | LLM key 失效 / 网络不通 | 看日志 trace 里 provider 错误信息；确认 Clash 代理（家里 7890）已开 |
| S11 前端白屏 | CORS / 端口错 | 浏览器 F12 Network 看报错；确认 :8000 或 :5173 可达 |
