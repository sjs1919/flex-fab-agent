# demo 部署指南 v1（WSL / Docker 双路径）

> **定位**：把 agent-training 的 demo 项目（排产多 Agent 助手）从零部署到 WSL 环境的端到端操作手册。部署完成后必须执行 **§9 冒烟测试**，全部通过才进入界面验收。
> **适用版本**：demo v2（M1~M6 全量模块 + Vue 3 调试台）
> **生成日期**：2026-08-25
> **前置文档**：[生产化差距与部署蓝图 v1](生产化差距与部署蓝图-v1-2026-08-22.md)、[验收清单](../08-test/验收清单.md)

## 1. 部署架构

```
前端 (Vue 3 + Vite, :5173)
    │
    ▼
后端 API (FastAPI + Python 3.11, :8000)
    │            ├── LLM Provider（豆包 / DeepSeek 主备 fallback）
    │            ├── SQLite（checkpoints / LLM 缓存 / Chroma 语义缓存）
    ├────────────┼── MySQL 8.0（业务库 demo_scheduling，可选，CSV 为默认）
    │            └── Redis（可选，暂未启用）
    ▼
 模拟器线程（同进程，demo 级；生产态需独立进程，见蓝图 D1）
```

部署路径二选一：

| 路径 | 适用场景 | 启动速度 |
|------|---------|---------|
| A. WSL 原生（Python venv + MySQL） | 开发调试、改代码 | 慢（但改完直接生效） |
| B. Docker Compose | 快速体验、演示 | 快（首次构建慢） |

### 3.4 环境配置

#### 3.4.1 敏感信息初始化（部署第一步，必做）

本项目遵循「代码与密钥分离」行业实践：**所有口令 / API Key / 密钥统一存入 `credentials.local.md`，`.env` 只放非敏感开关和占位符**。

```bash
# 1. 从模板复制凭据文件（已在 .gitignore，不会被提交）
cp docs/demo/credentials.local.md.example docs/demo/credentials.local.md

# 2. 按表格填入真实值（至少填 L1/L2 级；不用的留「（未用）」）
vim docs/demo/credentials.local.md

# 3. 收紧文件权限（WSL / Linux）
chmod 600 docs/demo/credentials.local.md

# 4. 校验不入库（必须看不到 credentials.local.md）
git status --porcelain docs/demo/credentials.local.md
# 预期输出为空（文件被忽略）
```

**分级速查**（完整清单见 `credentials.local.md.example`）：

| 级别 | 项 | 示例 |
|------|----|------|
| 🔴 L1 高危 | LLM API Key / JWT Secret / MySQL root | 泄露 = 直接经济损失，90 天轮换 |
| 🟡 L2 中危 | MySQL 业务口令 / Redis 口令 / SMTP 授权码 | 泄露 = 单系统沦陷，180 天轮换 |
| 🟢 L3 低危 | 主机地址 / 端口 / 库名 / 用户名 | 信息泄漏但无操作权限，365 天轮换 |

**加载机制**：`demo/config.py` 中 `_env_or_cred()` 函数实现「`.env` 优先 → 回落 credentials.local.md → 默认值」三级 fallback。开发态可直接写 `.env`，部署态一律走凭据文件。

#### 3.4.2 `.env` 非敏感配置

`.env` 存放非敏感开关、URL、模型名等，示例：

```ini
# 数据源：csv（默认）或 mysql
DEMO_DATA_SOURCE=csv

# 主备切换（可选，把指定 provider 提到最前）
# PRIMARY_PROVIDER=DeepSeek

# Kimi 开关（会员过期，默认禁用）
KIMI_ENABLED=false

# HuggingFace 国内镜像（加速模型下载）
HF_ENDPOINT=https://hf-mirror.com
```

> ⚠️ **`.env` 安全红线**：`.env` 已在 `.gitignore`，但仍**不建议放 L1/L2 级明文口令**。生产部署必须走 `credentials.local.md`。

### 3.5 数据库初始化（MySQL 模式）

```bash
# 建库建用户（一次）。MYSQL_ROOT_PASSWORD 来自 credentials.local.md
MYSQL_ROOT_PW=$(grep '{{MYSQL_ROOT_PASSWORD}}' docs/demo/credentials.local.md | awk -F'|' '{print $3}' | xargs)

sudo mysql -u root -p"$MYSQL_ROOT_PW" <<'EOF'
CREATE DATABASE demo_scheduling CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'demo_sched'@'127.0.0.1' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON demo_scheduling.* TO 'demo_sched'@'127.0.0.1';
FLUSH PRIVILEGES;
EOF

# 迁移 + 种子
python -m demo.schema.migrate --up
python -m demo.simulator.seed --reset
```

### 3.6 模型缓存（RAG 用）

```bash

```

## 4. 路径 B：Docker Compose 一键部署

### 4.1 前置：WSL 装 Docker

```bash
# 方式一：Docker Desktop（推荐，Windows 侧安装后 WSL 自动集成）
# 方式二：docker.io
sudo apt install -y docker.io docker-compose
sudo usermod -aG docker $USER
# 重新登录后生效
```

### 4.2 构建并启动

```bash
cd ~/workspace/agent-training

# 模型缓存宿主路径（按需修改；没有就先空着，RAG 功能会报加载错）
export HF_CACHE_HOST=/home/$USER/.cache/huggingface
export CHROMA_CACHE_HOST=/home/$USER/.cache/chroma

docker compose up -d --build
docker logs -f demo-api   # 看启动日志
```

### 4.3 Docker 模式说明

- **数据源**：容器内默认 CSV 模式（`.env` 没设 `DEMO_DATA_SOURCE=mysql`）
- **持久化**：`demo-runtime` 卷存放 checkpoints.db / cache_db / chroma_db，容器重建不丢失
- **端口**：宿主 `8000 → 容器 8000`
- **前端**：Docker 方式未打包前端，前端需本机 `cd web && npm install && npm run dev`

> 要用 MySQL：需把 WSL 的 MySQL 暴露给容器（用 `host.docker.internal` 或 network_mode: host），并在 credentials.local.md 里改 `MYSQL_HOST`。

## 9. 冒烟测试策略（部署后必做，不通过不进界面验收）

### 9.1 策略原则

- **分层递进**：地基 → 数据 → API → 核心功能 → 前端，每层过了再进下一层
- **不烧 LLM token**：基础层用 mock / 健康检查，仅核心功能层调一次真实 LLM
- **幂等可重复**：任何时候重跑结果一致
- **自动化脚本**：`demo/smoke_test.py` 一键执行，退出码 0 = 全部通过

### 9.2 冒烟用例清单

| # | 层级 | 用例 | 验证点 | 调 LLM |
|---|------|------|--------|--------|
| S0 | 安全 | 敏感信息扫描 | credentials.local.md 不入库 + .env 无明文 L1/L2 口令 | 否 |
| S1 | 地基 | 环境自检 `--check` | provider 可用 + 工具注册表非空 + 数据加载成功 | 否 |
| S2 | 数据 | 迁移状态 | schema_version = 3 + 表数 ≥ 18（MySQL） 或 CSV 文件齐全 | 否 |
| S3 | 数据 | 数据完整性 | 订单 ≥ 30 / 设备 = 7 / 零件 ≥ 100 / 客户 = 5 | 否 |
| S4 | API | `/health` 探针 | status=ok + providers 非空 + tools>0 + sim 状态可查 | 否 |
| S5 | API | `/kpi` 端点 | 返回 KPI 指标且字段齐全（on_time / utilization / yield） | 否 |
| S6 | API | `/config` 端点 | 返回系统配置分类列表 | 否 |
| S7 | 排产 | 初始排产 | `run_scheduling` 生成 schedule_version + batches，无异常 | 否 |
| S8 | 排产 | `/schedule/latest` | 返回最新版本 + 批次列表 | 否 |
| S9 | 模拟器 | `/sim/start` + `/sim/status` | 模拟器启动，tick 递增 | 否 |
| S10 | Agent | `/ask` 简单问题 | 回答非空 + tool_results 非空 + trace_id 存在 | 是 |
| S11 | 前端 | 页面可达 + 关键接口 | Dashboard / Debug / Cases / Config 页 200，API 调用成功 | 否 |

## 10. 敏感信息管理（行业实践）

### 10.1 分级模型

所有口令 / 密钥 / 凭证按泄露影响分为三级：

| 级别 | 定义 | 存储位置 | 轮换周期 | 示例 |
|------|------|---------|---------|------|
| 🔴 L1 高危 | 泄露可直接造成经济损失或系统接管 | `credentials.local.md` + 密码管理器 | 90 天 | LLM API Key、JWT Secret、MySQL root |
| 🟡 L2 中危 | 泄露可导致单一业务系统沦陷 | `credentials.local.md` | 180 天 | MySQL 业务口令、Redis 口令、SMTP 授权码 |
| 🟢 L3 低危 | 仅信息泄漏，无操作权限 | `.env` / `credentials.local.md` 均可 | 365 天 | 主机地址、端口、库名、只读账号 |

### 10.2 存放与访问

- **唯一真实源**：`docs/demo/credentials.local.md`（L1 + L2 + L3 全量）
- **运行时加载**：`demo/config.py` 的 `_env_or_cred()` 函数，优先级 `.env` > `credentials.local.md` > 默认值
- **文件权限**（WSL/Linux）：`chmod 600 docs/demo/credentials.local.md`，仅所有者可读
- **不入库保障**：`.gitignore` 覆盖 `*.local.md`；提交前执行 `git status` 确认无该文件
- **备份**：加密存储在个人密码管理器中，不存明文盘、不贴聊天、不发邮件

### 10.3 部署时填充流程（标准动作）

```
复制模板 → 填充真实值 → 收紧权限 → 校验不入库 → 冒烟扫描 → 进入功能验证
  │            │           │            │             │
  ▼            ▼           ▼            ▼             ▼
cp example   vim 编辑   chmod 600   git status  smoke_test --scan-secrets
```

对应命令：

```bash
# 1. 从模板复制
cp docs/demo/credentials.local.md.example docs/demo/credentials.local.md

# 2. 填入真实值（建议用密码管理器生成强口令，16 位以上，大小写+数字+符号）
vim docs/demo/credentials.local.md

# 3. 收紧权限
chmod 600 docs/demo/credentials.local.md

# 4. 校验不入库（输出应为空）
git status --porcelain docs/demo/credentials.local.md

# 5. 敏感信息扫描（冒烟测试 S0）
python demo/smoke_test.py --scan-secrets
```

### 10.4 Redis 配置说明

Redis 默认无密码也可运行，但**部署态强烈建议启用 AUTH**：

```bash
# WSL 下设置 Redis 口令
sudo redis-cli CONFIG SET requirepass "你的强口令"
# 持久化到 redis.conf（重启生效）
echo 'requirepass 你的强口令' | sudo tee -a /etc/redis/redis.conf
sudo systemctl restart redis-server
```

然后在 `credentials.local.md` 填入 `{{REDIS_PASSWORD}}`。`config.py` 的 `get_redis_config()` 会自动读取（无口令时返回 `password=None`）。

> 当前 demo 的缓存层走 SQLite + Chroma，Redis 未启用。预留配置接口，生产化切换时直接用。

### 10.5 轮换与应急

**常规轮换**（建议日历提醒）：

```bash
# 例：轮换 MySQL 业务口令
# 1. 改 MySQL 侧
mysql -u root -p -e "ALTER USER 'demo_sched'@'127.0.0.1' IDENTIFIED BY '新口令';"
# 2. 改 credentials.local.md 的 {{MYSQL_PASSWORD}}
# 3. 重启服务进程
# 4. 跑冒烟测试验证连通性
```

**应急轮换**（怀疑泄露时）：立即撤换 L1 全部 + L2 关联项，然后跑冒烟 + 查审计日志。

### 10.6 不在此列的信息

以下内容**不视为敏感**，可放 `.env` 或代码注释：
- 服务端口（8000 / 5173 / 3306）
- 模型名称（`ark-code-latest` / `deepseek-v4-flash`）
- Provider 基础 URL（不含 key 部分）
- 功能开关（`KIMI_ENABLED=false` / `DEMO_DATA_SOURCE=csv`）

### 10.7 WSL MySQL 启动注意事项（重要 ⚠️）

WSL2 下 MySQL 的 systemd 兼容性差，容易出现「启动几秒就挂掉」「socket 文件找不到」等问题。推荐方案：

**1. 关闭 systemd**

```bash
# 写 /etc/wsl.conf
cat <<EOF | sudo tee /etc/wsl.conf
[boot]
systemd=false

[automount]
options = "metadata"
EOF

# 重启 WSL 生效（PowerShell 侧）
# wsl --shutdown
```

**2. 用 `mysqld_safe` 手动启动**

```bash
# /var/run 每次 WSL 重启会清空，需要重建
sudo mkdir -p /var/run/mysqld
sudo chown mysql:mysql /var/run/mysqld

# 后台启动
sudo mysqld_safe --datadir=/var/lib/mysql --pid-file=/var/run/mysqld/mysqld.pid &

# 等 7-15 秒就绪
sleep 10 && sudo mysqladmin ping
```

**3. root 免密登录（auth_socket）**

```bash
# socket 方式，sudo 身份直接进
sudo mysql -u root -S /var/run/mysqld/mysqld.sock
```

详细踩坑记录见 [`docs/pitfalls/20260825-WSL-MySQL-systemd踩坑.md`](../09-reports/20260825-WSL-MySQL-systemd踩坑.md)。
