# 循环守卫误判与缓存投毒修复 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:test-driven-development 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法跟踪进度。

**目标：** 修复「有没有订单已经打印完成？」这类状态查询产出垃圾答案的根因——循环守卫误判 + 原始 dump 泄漏 + 垃圾写入语义缓存。修复后：状态筛选空结果即终态答案（不再追问补数据）、循环守卫只对「同参数连续重复」触发且产出面向用户的兜底、循环守卫 dump 永不入语义缓存。

**方案（TDD，先写失败测试再改实现）：**
- ③ 筛选空结果即答案：`query_orders` 带筛选条件且干净返回「未找到匹配的订单。」→ `ready_for_answer=True`，直接进 `generate_answer`
- ① 循环守卫按「同工具 + 同参数连续 ≥3 次」判定（`itertools.groupby`）；触发时产出 `LOOP_GUARD_FALLBACK_PREFIX` 前缀的简洁兜底，去掉「检测到重复检索」内部诊断
- ② 缓存写入门禁追加拦截 `LOOP_GUARD_FALLBACK_PREFIX` 前缀答案（与既有 DSML 标记 / 优雅兜底拦截并列）

**技术栈：** Python 3 / LangGraph StateGraph / pytest（mock call_llm + FakeRegistry）。

**关联现状：**
- `demo/graph/single_agent_graph.py`：`evaluate_results`（L211-286）循环守卫用 `Counter(tool_seq).most_common()` 全局计数（L232-246）；`generate_answer`（L317-401）复用末条 assistant 文本
- `demo/agents/single_agent.py`：缓存写入条件（L119-125）只拦 `_looks_like_tool_markup` 与 `_GRACEFUL_FALLBACK`
- `demo/cache/semantic_cache.py` / `demo/cache/manager.py`：语义缓存 L2 facade
- 既有测试：`demo/graph/test_single_agent_graph.py`（FakeRegistry/FakeResponse/`_make_tool_call`/`_disable_compression`）、`demo/agents/test_single_agent.py`（StubApp + cache_manager stub）

## 任务 1：筛选空结果识别为终态答案（graph）

**文件：**
- 修改：`demo/graph/single_agent_graph.py`（evaluate_results）
- 测试：`demo/graph/test_single_agent_graph.py`

- [x] **步骤 1：编写失败测试**

`test_status_empty_result_is_terminal_answer`：
- 新 `FakeEmptyRegistry`：`execute` 对 `query_orders` 返回「未找到匹配的订单。」（其余走父类）
- LLM 轮次：第 1 轮 `query_orders(status="完成")` → 第 2 轮干净文本「当前没有打印完成的订单。」
- 断言：`final_answer == "当前没有打印完成的订单。"`；`len(tool_results) == 1`（空结果即答案，不追问更多工具）；`final_answer` 不含「检测到重复检索」

- [x] **步骤 2：实现（evaluate_results 顶部，早于循环检测）**

```python
# ③ 筛选空结果即答案（2026-08-27 修复）：query_orders 带筛选条件且干净返回
# 「未找到匹配的订单。」= 该筛选无匹配订单，直接据此作答。否则 evaluate 会
# 以「数据不足」怂恿 LLM 继续补数据，不同参数的探索最终被循环守卫误判成
# 循环（坑：有没有订单已经打印完成？→ 3 次 query_orders → 原始 dump 进缓存）。
for tr in results:
    if tr.get("tool") != "query_orders":
        continue
    args = tr.get("arguments") or {}
    if not any(args.values()):
        continue  # 无筛选条件（全量查询），空结果另有含义，不拦截
    if (tr.get("result") or "").strip() == "未找到匹配的订单。":
        state["evaluation_notes"] = "订单筛选无匹配（未找到），可直接据此作答"
        state["ready_for_answer"] = True
        state["needs_more"] = False
        state["needs_retry"] = False
        return state
```

**文件：**
- 修改：`demo/graph/single_agent_graph.py`
- 测试：`demo/graph/test_single_agent_graph.py`

- [x] **步骤 1：编写失败测试**

`test_loop_guard_distinct_args_not_loop`：
- LLM 第 1-3 轮分别 `query_orders(status=待排队/已审核/打印中)`（参数不同，FakeRegistry 返回数据）→ 第 4 轮干净文本「订单汇总」
- 断言：`final_answer == "订单汇总"`（**旧实现**在 3 次 query_orders 后 Counter 计数=3 触发循环守卫，产出原始 dump，干净文本被截断；**新实现**按参数分组每组 len 1，不触发循环）

- [x] **步骤 2：实现（替换 L232-246 循环检测块）**

模块级常量：
```python
# 循环守卫兜底前缀（2026-08-27 修复）：不再泄漏「检测到重复检索」内部诊断，
# 改为面向用户的简洁兜底；该前缀答案一律不得写入语义缓存（缓存投毒纵深防御）。
LOOP_GUARD_FALLBACK_PREFIX = "已多次检索未获得新的有效结果，基于已收集数据作答：\n"
```

循环检测改为 groupby（同工具 + 同参数连续 ≥3 次）：
```python
LOOP_THRESHOLD = 3
from itertools import groupby
seq = [(_tr.get("tool", ""),
        json.dumps(_tr.get("arguments", {}), sort_keys=True, ensure_ascii=False))
       for _tr in results]
looped_tool = next((k for k, grp in groupby(seq) if len(list(grp)) >= LOOP_THRESHOLD), None)
if looped_tool:
    state["evaluation_notes"] = (f"检测到循环：工具 {looped_tool} 连续重复调用 "
                                 f"≥{LOOP_THRESHOLD} 次（相同参数），停止检索，基于已有数据作答")
    state["needs_more"] = False
    state["needs_retry"] = False
    state["ready_for_answer"] = True
    parts = [f"- {tr.get('tool')}: {tr.get('result', '')[:200]}" for tr in results]
    state["final_answer"] = LOOP_GUARD_FALLBACK_PREFIX + "\n".join(parts)
    state["messages"].append({"role": "assistant", "content": state["final_answer"]})
    return state
```
