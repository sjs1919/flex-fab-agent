# 公共组件与连接池改造方案 v1.0

> **定位**：demo 基础设施层专项重构——把"该公共不公共"的代码抽到统一组件，消除重复、统一入口、收口配置。
> **触发**：2026-08-25 代码走读发现"语义缓存和精确缓存各自走一套"等架构异味，详见走读报告。
> **范围**：P0（必做 3 项）+ P1（推荐 4 项），共 7 项改造。P2 留待后续迭代。
> **原则**：外科手术式改造，不改变业务逻辑，只动基础设施层；每一步可独立验证。
> **日期**：2026-08-25 · 版本 v1.0

## 3. P0-3：缓存层统一入口 CacheManager

### 现状

- L1 精确缓存（SQLite + MD5 key）：嵌在 `llm_client.py` 里，调用 `llm_cache.get()/put()`
- L2 语义缓存（Chroma + cosine 相似度）：散在 `agents/single_agent.py` 里手动调 `semantic_cache.get()/put()`
- 两层缓存各自有 `is_enabled()`、各自管理连接、各自的 stats/clear 接口
- 没有统一的缓存策略管理，新增 L3（如 Redis）会继续碎片化

### 改造方案

新增 `demo/cache/manager.py`，提供 `CacheManager` facade：

```python
class CacheManager:
    """两级缓存统一入口：L1 精确 + L2 语义。

    查询策略：
      1. 先查 L1（精确匹配）→ 命中直接返回完整结果
      2. L1 miss → 查 L2（语义匹配）→ 返回候选 + 相似度，供调用方决策
      3. 都 miss → 返回 None，调用方走真实 LLM
    """

    def lookup_exact(self, messages: list, tools: list, model: str,
                     max_tokens: int, temperature: float,
                     scene_version: str = "") -> dict | None:
        """L1 精确查找。命中返回 {"content": ..., "tool_calls": ...}。"""

    def lookup_semantic(self, query: str) -> list[dict] | None:
        """L2 语义查找。返回 [{query, response, similarity}] 或 None。"""

    def store_exact(self, messages, tools, model, max_tokens, temperature,
                    result, scene_version: str = ""):
        """写入 L1 精确缓存。"""

    def store_semantic(self, query: str, response: str):
        """写入 L2 语义缓存。"""

    def stats(self) -> dict:
        """两层缓存统计。"""

    def clear(self):
        """清空两层缓存。"""

cache_manager = CacheManager()  # 模块级单例
```

`llm_client.py` 改造：
- 移除直接调用 `llm_cache.get()/put()` 的代码
- 改用 `cache_manager.lookup_exact()/store_exact()`
- L2 语义缓存的查询/写入也通过 cache_manager，agent 层不再手动调 semantic_cache

`agents/single_agent.py` 改造：
- 移除手动 `semantic_cache.get()/put()` 调用
- 由 llm_client / cache_manager 统一处理

### 关键设计决策

**L2 语义缓存不直接替代 LLM 调用**。语义缓存返回的是"相似问题的历史回答"，供 agent 参考（作为 system prompt 补充或 tool result 形式），但最终回答仍由 LLM 生成。原因：语义匹配 ≠ 完全相同，直接返回可能答非所问（尤其是上下文不同时）。

L1 精确缓存则可以 100% 替代，因为 messages 完全相同 → 输出应该相同。

### 改动文件

| 文件 | 动作 |
|------|------|
| `demo/cache/manager.py` | 新增（CacheManager + 单例） |
| `demo/core/llm_client.py` | L1 缓存调用改走 cache_manager |
| `demo/agents/single_agent.py` | 移除手动 semantic_cache 调用 |
| `demo/api.py` | 缓存管理端点（如有）走 cache_manager |

### 验证

- 两次相同查询 → 第二次 L1 命中（日志显示 `⚡ [L1缓存命中]`）
- 相似问题查询 → L2 语义命中返回候选
- 冒烟测试 S10 Agent 问答通过

## 7.5. P1-4：trace_id 统一贯通 + contextvars 隔离

### 现状

- **tracer**（`observability/tracer.py`）：模块级单例，trace_id 16 位 hex，每次 `reset()` 重新生成，非线程安全
- **audit_logger**（`auth/audit_logger.py`）：每个实例一个 trace_id，12 位 hex，构造时生成
- **两者不关联**：同一个请求的 tracer.trace_id 和 audit_logger.trace_id 不一样，无法串联
- **线程安全隐患**：全局 tracer 单例 + 模拟器线程已经发现问题（runner.py 用独立 Tracer 实例规避），API 并发请求也会有同样问题

### 改造方案

#### 7.5.1 trace_id 用 contextvars 做请求级隔离

新增 `demo/observability/request_context.py`：

```python
import contextvars
import uuid

# 请求级 trace_id，每个请求一个，自动隔离
_request_trace_id: contextvars.ContextVar[str] = contextvars.ContextVar(
    "request_trace_id", default=""
)

def get_trace_id() -> str:
    """获取当前请求的 trace_id，没有则生成一个。"""
    tid = _request_trace_id.get()
    if not tid:
        tid = uuid.uuid4().hex[:16]
        _request_trace_id.set(tid)
    return tid

def set_trace_id(trace_id: str) -> None:
    """设置当前请求的 trace_id（请求入口处调用）。"""
    _request_trace_id.set(trace_id)

def new_trace_id() -> str:
    """生成并设置新的 trace_id，返回它。"""
    tid = uuid.uuid4().hex[:16]
    _request_trace_id.set(tid)
    return tid
```

#### 7.5.2 Tracer 改造

- `Tracer` 不再自己持有 `_trace_id`，改为从 `request_context.get_trace_id()` 取
- 模块级单例保留，但内部状态（spans/stack）也用 contextvars 隔离
- `reset()` 改为调用 `new_trace_id()` + 清空当前上下文的 spans
- 模拟器线程继续使用独立 Tracer 实例（不影响）

#### 7.5.3 AuditLogger 改造

- 不再自己生成 `_trace_id`，改为从 `request_context.get_trace_id()` 取
- 构造时可选传入 trace_id，默认用当前上下文的
- 统一长度为 16 位 hex（与 tracer 一致）

#### 7.5.4 API 中间件

在 `api.py` 中新增 FastAPI 中间件，每个请求入口自动生成 trace_id：

```python
@app.middleware("http")
async def trace_middleware(request: Request, call_next):
    trace_id = request.headers.get("X-Trace-Id") or uuid.uuid4().hex[:16]
    set_trace_id(trace_id)
    response = await call_next(request)
    response.headers["X-Trace-Id"] = trace_id
    return response
```

这样所有下游模块（tracer / audit_logger / cost_tracker）都共享同一个 trace_id。

#### 7.5.5 cost_tracker 同步

`observability/cost.py` 的 cost_tracker 如果有自己的 trace_id 概念，也同步改为从 request_context 取。

## 7.6. P1-5：API 层统一响应 + 全局异常 handler + Depends 鉴权

### 现状

- 20+ 个端点直接返回裸 dict，无统一响应格式
- 11 处手动 `raise HTTPException(...)`，错误响应格式不统一
- `_require_admin()` 手动调用，5 个写端点各写一遍
- `/ask` 和 `/debug/rerun` 有大量重复的 agent 执行流程

### 改造方案

#### 7.6.1 统一响应格式

新增 `demo/core/response.py`：

```python
from pydantic import BaseModel, Generic, TypeVar
from typing import Generic, TypeVar

T = TypeVar("T")

class ApiResponse(BaseModel, Generic[T]):
    code: int = 0          # 0=成功，非0=错误
    message: str = "ok"
    data: T | None = None
    trace_id: str = ""

def ok(data=None, message="ok") -> dict:
    return {"code": 0, "message": message, "data": data}

def fail(code: int, message: str) -> dict:
    return {"code": code, "message": message, "data": None}
```

每个端点返回 `ok(data=...)` 或 `fail(code, msg)`，trace_id 由中间件/依赖注入。

#### 7.6.2 全局异常处理器

在 `api.py` 中注册：

```python
@app.exception_handler(HTTPException)
async def http_exception_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content=fail(exc.status_code, exc.detail),
    )

@app.exception_handler(Exception)
async def unhandled_exception_handler(request: Request, exc: Exception):
    return JSONResponse(
        status_code=500,
        content=fail(500, f"服务器内部错误：{exc}"),
    )
```

#### 7.6.3 Admin 鉴权改为 FastAPI Depends

把 `_require_admin()` 改成依赖注入函数：

```python
from fastapi import Depends

def require_admin(x_admin_token: str = Header(default="")) -> str:
    """写端点鉴权依赖：验证 admin token，返回 token_id。"""
    if not x_admin_token:
        raise HTTPException(401, "写端点需要 admin token：缺 X-Admin-Token 头")
    from .auth.token_exchange import STS
    token = STS().get_token(x_admin_token)
    if token is None or token.is_expired():
        raise HTTPException(401, "admin token 无效或已过期")
    if token.role != "admin":
        raise HTTPException(403, f"需要 admin 角色（当前 {token.role}）")
    return x_admin_token
```

写端点改为：
```python
@app.post("/schedule/load")
def schedule_load(admin_token: str = Depends(require_admin)):
    ...
```

#### 7.6.4 Agent 执行流程抽公共函数

`/ask` 和 `/debug/rerun` 重复的 "reset → run → 取摘要 → flush → 落看板" 流程抽成 `_run_agent_and_persist(query, thread_id=None)`：

```python
def _run_agent_and_persist(query: str, thread_id: str | None = None) -> dict:
    """执行一次 agent 交互并落观测数据，返回 {answer, tool_results, trace_id, trace, cost}。"""
    tracer.reset()
    cost_tracker.reset()
    result = run_single_agent(query, registry=_registry, thread_id=thread_id)
    trace = tracer.get_summary()
    cost = cost_tracker.get_summary()
    tracer.flush()
    _persist_dashboard(tracer.trace_id, trace, cost)
    return {
        "answer": result.get("final_answer", ""),
        "tool_results": result.get("tool_results", []),
        "trace_id": tracer.trace_id,
        "trace": trace,
        "cost": cost,
    }
```

## 10. 风险与回退

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 配置收口时某些变量的默认值与之前不一致 | 功能异常 | 逐个核对原模块的 `os.getenv("XXX", default)` 默认值，统一到 config.py |
| CacheManager 改造引入缓存逻辑 bug | Agent 回答异常 | L1 精确缓存逻辑不变（只换调用路径），L2 语义缓存保持可选开关 |
| embedding 抽公共函数后模型加载失败 | 向量库 + 语义缓存不可用 | 保持原错误处理逻辑，加载失败时给出明确报错 |
| trace_id 改造引入上下文传递问题 | 并发请求 trace 串扰 | contextvars 是 Python 标准库原生支持，线程/协程安全 |
| API 统一响应破坏前端对接 | 前端渲染失败 | 同步检查前端代码中对 API 响应的字段引用 |
| 多处小工具替换引入回归 | 各模块小 bug | 每步替换后跑冒烟测试验证 |

**回退策略**：每一步都是独立的 Git commit，出问题直接 revert 对应 commit。
