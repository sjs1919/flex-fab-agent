## 3. git 历史迁移方案（核心需求）

**结论：完全可实现。** 使用 `git filter-repo`（GitHub 官方推荐的历史重写工具）按路径过滤，保留指定路径的**全部历史提交**。

### 3.1 方案对比

| 工具 | 原理 | 是否可行 | 评价 |
|------|------|---------|------|
| **git filter-repo**（推荐） | 按路径重写历史，只保留指定路径的提交 | ✅ | 快、支持多路径一次指定、自动清理孤儿对象；会改写 commit hash |
| git subtree split | 把一个子目录历史抽为新分支 | ⚠️ | 只能一个前缀；web/docs/demo 等多路径需多次 split + 合并，繁琐 |
| git filter-branch | 旧式历史重写 | ⚠️ | 慢、已废弃（官方建议 filter-repo） |
| 全新 init（丢历史） | 新仓库从当前快照开始 | ✅ 可行但不满足需求 | 用户明确要历史，排除 |

### 3.2 filter-repo 执行命令

```bash
# 0) 前置：安装 git-filter-repo（Python 环境）
pip install git-filter-repo
# 或下载单文件脚本 git-filter-repo 放入 PATH

# 1) 新建独立仓（用 mirror 克隆拿到全量历史，filter-repo 要求 fresh clone）
git clone --mirror /c/workspace/projects/agent-training /tmp/flex-fab-agent-mirror
cd /tmp/flex-fab-agent-mirror

# 2) 按路径过滤：一次指定所有要保留的路径
git filter-repo \
  --path demo/ \
  --path web/ \
  --path docs/demo/ \
  --path Dockerfile \
  --path docker-compose.yml \
  --path requirements.txt \
  --path requirements-demo.txt \
  --path .dockerignore \
  --path .gitignore \
  --path .githooks/ \
  --force

# 3) 从 mirror 转成正常工作仓
git clone /tmp/flex-fab-agent-mirror /c/workspace/projects/flex-fab-agent
cd /c/workspace/projects/flex-fab-agent

# 4) 关联开源远程并推送
git remote add origin https://github.com/sjs1919/flex-fab-agent.git
git push -u origin main
```

> **注意事项**：
> - **会改写 commit hash**（历史重写的固有特性，独立仓无影响）。
> - 若保留 `docs/demo/` 里指向训练文档（`docs/week*`、`job-portfolio/`）的链接，迁移后这些相对链接失效——需按 §4 清理。
> - filter-repo 默认在 fresh clone 上运行；对已有仓库需 `--force`（明确接受重写）。

### 3.3 敏感信息排查（历史清理）

filter-repo 只按路径过滤，**不会自动脱敏**。历史中若出现过 `.env`、credentials、API key 明文，会随相关 commit 保留。必须排查：

```bash
# 1) 分析历史中出现的高频 blob（找出可能的敏感文件）
git filter-repo --analyze

# 2) 检查历史中是否提交过敏感文件/内容
git log --all --oneline -- .env credentials.local.md '**/credentials*'   # 应有结果则为风险
git log --all -S 'sk-[A-Za-z0-9]' --oneline                               # DeepSeek/OpenAI key 特征
git log --all -S 'DEEPSEEK_API_KEY' --oneline

# 3) 若发现敏感内容，用 --replace-text 或 --path 排除 + 重写脱敏
#    （或用 --blob-callback 剔除含 key 的 blob；详见 git-filter-repo 文档）
```

> `.env`、`docs/demo/credentials.local.md` 均为 gitignored（未入库），正常不应出现在历史；若有历史残留，脱敏后再发布。

### 4.2 失效链接清理

`docs/demo/` 当前约 20+ 处链接指向训练内容（`../docs/week*`、`../../docs/courses/`、`../../job-portfolio/`、`project-standards/`、`docs/superpowers/`）。迁移后：

- **活跃文档**（README、功能介绍、代码阅读指南 v3.0、当前规格/计划）：逐一清理失效链接，改写为独立仓内文档或删除。
- **历史归档文档**（旧 todo、旧报告、旧 plan）：可接受保留失效链接（GitHub 上仍可读，链接失效但内容完整），或用脚本批量标注「原链接指向训练仓库，已失效」。
- 建议清理优先级：README > 功能介绍 > 代码阅读指南 v3.0 > 02-specs 当前版 > 其余归档。

### 4.4 命名统一（demo → flex-fab-agent）

**用户要求（2026-08-30）**：迁移后把**内容与文件名的「demo」统一替换为项目名 flex-fab-agent**。影响面：

| 对象 | 现在 | 迁移后 |

| Python 包目录 | `demo/` | `flex_fab_agent/`（包名用下划线） |

> **决策（2026-08-30 用户拍板）**：**包名全量改** —— `demo/` → `flex_fab_agent/`，全部 `import` / CLI 命令 / pytest 收集 / Dockerfile / config / 文档正文同步改，文件名含 demo 的同步改名。**Python 包名定为 `flex_fab_agent`**（PEP 8 小写下划线；已否决 `com.flex.fab.agent` Java 逆向域名风格——Python 中 `.` 为包层级分隔，会变 4 层嵌套包、import 冗长、社区不标准）。P4 阶段用 `python run_all_tests.py` + `npm run build` + Docker 构建**全量回归**，回归通过才算完成；回归失败则回退到「包名保留 demo」方案（已备）。

## 7. 风险与权衡

| 风险 | 影响 | 缓解 |
|------|------|------|
