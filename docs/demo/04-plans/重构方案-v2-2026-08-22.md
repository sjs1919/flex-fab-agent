## 0. 决策汇总

| # | 决策 | 核实结论 |
|---|------|---------|
| 1 | **MySQL 业务库**（唯一事实来源），跑 WSL，独立 database（不碰 big-data-obj） | ✅ 现状无 MySQL，`data.py` 纯 CSV，需新建 |

| 6 | **种子数据重做非迁移** | ✅ 现状 8 台混合工艺 CSV（5 3D打印+3 CNC）≠ 目标 7 台纯 3D 打印（SLA3+MJS3+SLM1），无迁移关系，参考维度保留不迁移 |

### 0.2 V2 修订决策（本版新增，9 角色评审产出）

| # | 修订 | 内容 | 评审来源 |
|---|------|------|---------|
| R-1 | **B5 read_only 从零实现** | 现状 `read_only` 标记**未落地**——`registry.py` L98-101 docstring 声称"B5 确认入案"，但 `ToolSchema`（L23-35）/`register()`（L53-60）/`execute()`（L87-141）均无只读/写字段与分流逻辑。D3 必须按**从零实现**执行，不得视为已存在 | 安全审查 + 代码走读 |

| R-4 | **B6 prompt 版本化务实化** | v1 C8 主张 prompt 迁 `system_config` 表。数百行 prompt 进 MySQL 行难维护、难 diff。v2：prompt 保持**版本化文件**（`prompts/versions/v{n}/`），版本号记 `prompt_versions` 表，`--rollback <version>` 载入对应文件版本；版本变更与回滚仍入审计 | 架构审查 + DBA 运维 |
| R-5 | **Supervisor 硬编码订单修正** | `SupervisorAgent.orchestrate()` 硬编码 `sample_orders=["ORD001","ORD003","ORD005"]`（analyzer 确认），排产场景不真实查询。v2：接入真实订单查询（经 `query_orders`/新排产工具），删除硬编码 | 开发者 + 代码走读 |
| R-6 | **R-D1 超时透传通道** | `sandbox.run_with_retry`（L54-72）已支持 `timeout`/`max_retries` 覆盖参数，但 `registry.execute`（L134）调用时未透传。v2：`ToolSchema` 增加 `timeout_override`/`max_retries_override`，`execute()` 透传给 `run_with_retry`（solver 工具 120s / 重试 1 次） | 开发者 |
| R-7 | **API 层鉴权策略** | 现状 `api.py` `/ask`、`/threads/{id}/history` 均不校验 token，CORS 全开（analyzer 确认）。v2：只读看板端点（/schedule/*、/kpi、/order/*）可匿名或 viewer；**写端点（/sim/start|stop、配置写）强制 admin token**，接入现有 STS + audit | 安全审查 |
| R-8 | **eval multi 模式评估空洞** | `eval/runner --mode multi` 路径 `tool_results=[]`，轨迹层指标空置、语义层拿不到 RAG 上下文（analyzer 确认）。v2：supervisor 路径回传 tool_results/trajectory，M4 多 Agent 集成验收（reviewer 审批权限）才可被评估覆盖 | 测试者 |

## 4. 数据模型

### 4.1 表结构（沿用 v1 §3，schema 不变）

`customer/orders/parts/machines/material`（业务）+ `schedule_versions/batches/preprocess_tasks`（求解输出）+ `system_config`（配置）+ `sim_events/state_change_log/approvals/sim_clock`（模拟器/审批）。字段细节见 v1 §3，不重复。

### 4.2 表所有权矩阵（V2 新增 · G-12）

| 表 | 写方（唯一） | 读方 |
|----|------------|------|
| orders/parts/machines/material | `simulator/seed.py` 种子 + 模拟器 B 层（订单到达） | solver / tools / forecast（只读快照） |
| schedule_versions / batches | **solver**（run_scheduling 触发） | tools / simulator（只读） |
| batches.approval_status | **approve_schedule**（排版人） | tools / solver |
| sim_clock / state_change_log / sim_events | **simulator** | tools（query_sim_events）/ solver（不读） |
| approvals | **approve_schedule** | 审计查询 |
| system_config | 运维/配置 API | 所有层（启动读一次缓存） |

> **并行前提**：M2（solver）与 M3（simulator）并行时，按上表写方唯一，交叉只读快照——M2 可用 `--init-schedule` 在无模拟器时独立出排产表；M3 在 M1 完成后即可推进批次状态。

## 6. 模拟器（A 时钟 + B 事件）

沿用 v1 §5 全部设计（A 层每 tick +1 sim 小时推进批次/静置/设备/前道/班次；B 层 MTBF/MTTR 指数 + 到达率预排；硬性不可行告警；1min 现实心跳；测试 `SIM_TICK_SECONDS` 加速）。V2 修订：

- **R-3 联动**：每 tick 更新 `cache_scene_version`，使 L1 缓存状态相关查询失效。
- **D2 隔离**：模拟器线程与主线程 span 上下文隔离（线程局部 tracer 或锁），`/sim/start` 前完成隔离初始化。
- **写唯一**：模拟器只写 `sim_clock/state_change_log/sim_events/machine 状态`，不写 schedule_versions/batches。

## 7. 求解器（OR-Tools CP-SAT）

沿用 v1 §6 全部设计（C1-C9、装舱判定、目标函数、拆批、超尺寸预警、无可行解冲突清单、10% 产能预留）。V2 修订：

### 7.1 R-D1 求解预算三件套（细化落地）

| 件 | 落地位置 | 具体实现 |

| 1. CP-SAT 预算 | `demo/scheduler/model.py` | `max_time_in_seconds = system_config.solver_max_time_seconds`（默认 60） |
