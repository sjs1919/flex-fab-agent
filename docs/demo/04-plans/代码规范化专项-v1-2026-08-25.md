# 代码规范化专项 v1（工具函数收口 + 日志统一）

## 背景

P0/P1 公共组件改造完成后，还剩两类"收尾级规范化"工作：
1. 小工具函数各处重复实现（json_list / fmt_dt / to_float 等），但还没实际替换到调用方
2. 日志体系混乱（print 散落各处，没有统一 logger / 级别 / 格式）

两类都是"改动小、文件多、纯规范化"，合并成一个专项一次性做完。

## 范围

### A. 工具函数收口替换（低风险）

`core/utils.py` 已经建好，函数都在里面，现在要把各模块里的内联实现换成 import：

| 函数 | 替换目标模块 | 说明 |
|------|-------------|------|
| `json_list` | simulator/engine.py, tools/scheduler_tools.py | JSON 字符串→list |
| `fmt_dt` | tools/scheduler_tools.py, tools/order_tools.py, observability/dashboard.py | 时间格式化 |
| `fmt_money` | observability/cost.py | 金额格式化 |
| `to_float / to_int` | scheduler/assessment.py, scheduler/snapshot.py | 安全类型转换 |

| `cap_limit` | api.py ✅ 已完成 | 参数夹取 |
| `gen_id` | 6+ 个模块 | 统一 ID 生成（后续换雪花只改一处） |
| `CUSTOMER_LEVEL_ORDER` | tools/order_tools.py ✅, tools/resource_tools.py ✅ | 业务常量 |

**验证**：compileall + 冒烟测试 S0-S9 通过。

### B. print → logging 统一（中风险）

**目标**：所有模块用 `logging.getLogger(__name__)`，杜绝裸 print。

**改造原则**：
- 每个模块顶部 `logger = logging.getLogger(__name__)`
- 调试信息 → `logger.debug()`
- 正常流程信息 → `logger.info()`
- 警告 / 旁路失败 → `logger.warning()`
- 错误 / 异常 → `logger.error()` + `exc_info=True`
- 保留 `print` 的场景：CLI 入口的用户交互输出（main.py 的欢迎语、交互式提示）

**风险点**：
- 测试可能断言 stdout（`capsys.readouterr()`）—— 需先 grep 确认
- 某些 print 是给用户看的 CLI 输出，不是日志—— 要区分对待
- 审计日志的 `print(f"[审计] ...")` 本来就是旁路告警 —— 改 logger.warning

**涉及模块（预估）**：
- api.py（旁路失败告警 print → logger.warning）
- agents/single_agent.py
- cache/semantic_cache.py, cache/llm_cache.py
- core/llm_client.py
- rag/knowledge_base.py, rag/retriever.py
- tools/sandbox.py
- observability/cost.py, observability/exporter.py
- auth/audit_logger.py
- simulator/runner.py（已经用了 logging ✅）
- main.py（CLI 输出保留 print，内部日志改 logger）

**验证**：
1. grep 验证：除了 main.py 的 CLI 交互，其他模块无裸 print
2. 冒烟测试通过
3. 运行时日志格式统一，级别可通过 LOG_LEVEL 环境变量控制
