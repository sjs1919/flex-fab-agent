## 1. 背景与目标

**现状缺口**（demo README §17 M1）：当前 demo 对排产问题只做 LLM 文本建议（排序+说明），不计算调度可行解——无可行解保证、无目标最优、无法量化验证。

**目标**：构建排产求解核心，接收订单/零件/设备数据，输出**可执行排产表**（每个零件 → 批次 → 设备 → 开工/完成时间），并满足全部硬约束。求解结果由 LLM 做解释与交互（混合架构：求解器算、LLM 讲）。

**行业判断**：3D 打印排产的对象是**批次（batch）**而非单件——多个订单零件合并进同一构建舱并行打印。核心杠杆是**合批 + 装舱**，区别于机加工的一对一调度。

## 2. 范围

### 2.1 包含（v1）

- 排产求解：合批（同材料跨订单拼舱）→ 装舱判定（尺寸粗估）→ 时间排程（设备+开工/完成）
- 输出排产表 + 交期达成率 + 舱利用率指标
- **人工审批**：排产方案经排版人查看、点击"通过"后才上机（human-in-the-loop）
- **应急产能预留**：预留 10% 产能供坏件重打/修复/应急插单
- **新单交期承诺 CTP**：接单时按现有负载（排队/在途/可用产能）计算最短可交付时间，不扰动现有订单
- **产能负载评估**：全局看板——在途/排队分布、各订单预计完成、满负荷超期预警、T 窗口（默认 24h）消化能力、产能余缺（剩余产能 / 缺几台机器）
- **订单状态跟踪**：按订单号查询——在途预计完成；排队预计开打/完成 + 前面还有什么单据（队列顺序=交期升序→priority 降序）
- **前道·打印前人工环节**：排版审核 + 切片/装料准备（6 人、按件数人效、3班倒8h、换班30min无产出）；前道完成→打印开始
- **订单预测 + 大单承诺期**：基于历史订单轻量时序预测未来负载（不做模型训练）；客户下大单时按"现有占用 + 预测未来占用 + 可用产能"给出承诺交付日期（预测校准 CTP，更真实、不偏乐观）
- **在线效果量化复盘（B1）**：`query_kpi` 实时输出准交率 / 延期金额 / 舱利用率 / 良率 / 前道瓶颈占用，随时间曲线（模拟器驱动）
- **模型路由（B3）**：`llm_client` 按任务类型路由（简单查询→快/便宜模型、排产/复杂→强模型），成本可控
- **RAG 权限检索（B4）**：知识检索按角色过滤知识文档（保密合同），接 RBAC + tenant
- **工具执行治理（B5）**：`registry.execute` 只读/写标记校验——只读工具禁写副作用、写工具必须带有效 token + 权限
- **Prompt/工作流版本化（B6）**：prompt 配置化带版本号，`--rollback <version>` 回滚；graph 版本记入版本表
- **良率/坏件闭环（B7）**：良率按设备/批次/材料下钻 + 坏件根因归因 + LLM 工艺改善建议（query_yield）
- **可观测 Dashboard（B8）**：静态 HTML 看板——KPI 曲线/成本统计/trace 摘要（复用 report.py 先例，M5）
- **Agent 调试台界面（G 组 · M6）**：主页文本交互 + 执行链路可视化（图节点/工具调用入参出参）+ 质量打分 + good/bad case 收集（类型标注/人工标注/按 trace_id 回测重跑）
- LLM 在环：解释排产表、回答"为什么这样排/哪些会延期"
- 演示数据 + 求解器可运行 + 评估指标

### 2.2 不包含（留演进）

- **精细几何 nesting 排布**（阶段 2）
- **后处理独立资源排队**（阶段 2；v1 用固定延时）
- **动态重排**（插单/故障/缺料，阶段 3）
- **真实业务库接入**（v1 用 demo 样例数据）

## 3. 术语表

| 术语 | 含义 |
|------|------|
| 订单 order | 客户侧聚合容器，含多款零件；交付按订单整体看齐 |

| 在途订单 | 打印中的订单，已占用机器；评估时排除其机器（按其腾出时间计入可用产能） |

| 产能负载评估 | 全局产能核算：在途/排队分布、预计完成、满负荷超期预警、T 窗口消化能力、产能余缺 |

| 承诺期（预测校准 CTP） | 新大单接单时，按现有占用 + 预测未来占用 + 可用产能计算的最早可交付日期 |
| 订单状态 | 待排队（含未审核）→ 已审核 → 打印中 → 完成；"未审核"非独立状态，属待排队 |

## 4. 业务对象与数据模型

### 4.1 业务对象层次

```
order 订单 ── 含多款 ──▶ part 零件 ── 每款多件数
                            │
   part 排产单位（材料=身份，跨材料拆款=产品id不同）
   batch 批次（同材料 part 拼舱）→ machine 设备 → 时间
```

### 4.2 字段设计（真实需要，demo 字段为对照）

**order 订单**
| 字段 | demo 对照 | 说明 |
|------|----------|------|
| 订单号 | `orders.id` | 聚合容器 |
| 客户 | `orders.客户名` | 客户等级→基础分 |
| 交期 | `orders.交期` | 客户下单时确定（输入） |
| priority | 无 | 订单权重，多维度换算（客户基础分+加急等） |
| 金额 | 无 | 违约金按订单金额计（合同实测 §3.17），延期目标权重依据 |

**part 零件**
| 字段 | demo 对照 | 说明 |
|------|----------|------|
| 产品 id | 无 | 排产最小单位；跨材料拆款 id 不同 |
| 所属订单 | 无 | — |
| 款型 | `orders.产品` | — |
| 件数 | `orders.数量` | 整批优先、可拆兜底 |
| 材料 | 无 | SLA / MJS / SLM |
| 长 | 无 | 装舱判定维度之一（允许旋转） |
| 宽 | 无 | 装舱判定维度之一（允许旋转） |
| 高 | 无 | 装舱判定 + 决定单件时长（max(长,宽,高)≤舱边长） |
| 单件时长 | 无 | = Z高 ÷ 速率 |

**material 工艺**（SLA / MJS / SLM）
| 字段 | 值 | 说明 |
|------|----|------|
| 速率 | 50 / 25 / 15 mm/h | 取最大速度 |
| 后处理延时 | 1 / 3 / 12 h | POST_PROCESS_HOURS |

**machine 设备**
| 字段 | 配置 | 说明 |
|------|------|------|
| 工艺类型 | SLA / MJS / SLM | 工艺固定设备类型 |
| 机型 | 600 / 450 | 正方体舱 |
| 舱尺寸（正方体） | 600³ / 450³ mm | 容量约束（长宽高） |
| 数量 | SLA 3 + MJS 3 + SLM 1 = 7（demo 配置，2026-08-21 确认） | SLM 仅 600 |
| 日可用 | 24h | 连续生产 |

**batch 批次**（求解输出）
| 字段 | 说明 |
|------|------|
| 批内 part + 件数 | 同材料 |
| 工艺 / 机型 / 设备 | 装填判定 |
| 开工 / 完成时间 | max+准备 |
| 审批状态 | 待审核 → 通过（上机）/ 驳回（重排） |

### 4.3 订单状态流转与口径（P1-3 / P1-4 定稿）

```
待排队（含未审核）→ 已审核（排版人审批通过）→ 打印中 → 完成
```

- **待排队**：排产表已生成但未审核通过，或等待排产；**"未审核"不是独立状态，属待排队**。
- **已审核**：排版人审批通过，等待上机 / 已排期。
- **打印中**：批次已上机，正在打印。
- **CTP 产能基准（P1-4）**：现有占用 = **打印中 + 已审核 + 待排队（含未审核）**；可用 = 总产能 − 现有占用。承诺建立在全部排队需求之上（保守，防超承诺）。
- **交期粒度（P1-3）**：按天，交期 = **截止日 23:59 前完成**；24h 窗口内部按小时算。

## 5. 排产流程（v1）

```
产能负载评估（随时可查：在途/排队分布 → 预计完成 → 满负荷超期预警 → T窗口消化 → 产能余缺/缺机器）
    ↓
接单 CTP（新单 → 排队/在途/可用产能 → 承诺交期，不扰动现有订单）
    ↓
订单/零件数据 → ①合批（同材料可拼、跨订单可拼、同订单尽量同舱）
              → ②装舱判定（包络盒≤舱边长、体积/件数粗估）
              → ③时间排程（设备分配 + 开工/完成，交期→优先级）
              → 排产表 + 指标（准交率/舱利用率/延期清单）
              → 排版人审核（查看 → 通过/驳回）——归入前道人工环节
              → 通过：前道准备（审核+切片/装料，6人·件数人效·3班倒·换班30min）→ 打印开始
              → 驳回：重新排产
              → LLM 解释（为什么这样排、哪些延期、如何改）
```

## 6. 约束定义（硬约束）

| # | 约束 | 定义 |
|---|------|------|
| C1 | 材料 | 同舱必须同材料；材料=part 身份，跨材料拆款（产品 id 不同） |
| C2 | 容量 | ① 单件可旋转：`max(长,宽,高) ≤ 舱边长`（≤450→可选450/600；450<max≤600→仅600；max>600→装不下直接预警）；② 面积：`Σ max(长,宽)² ≤ 舱底面积 × 0.7` 装载系数；③ 件数 ≤ 上限（可配）；④ 承重：`Σ 件重 ≤ 舱承重` |
| C3 | 设备匹配 | SLA/MJS → 600 或 450；SLM → 仅 600 |
| C4 | 时长 | 批次时长 = `max(舱内各件单件时长)`（纯打印；装料/准备时间忽略） |
| C5 | 件数 | 整批优先、可拆兜底；拆批记录来源（同一 part 件数分布在哪些批次） |
| C6 | 设备互斥 | 一台设备一个时刻只跑一个批次；批次结束后设备在静置/后处理延时期间被占（P1-1），下一批须等静置完成 |
| C7 | 交期 | 订单完成时间 ≤ due date（**按天，截止日 23:59**，P1-3）；订单完成 = 最后到达批次完成 + 后处理延时 |
| C8 | 产能预留 | 设备日可用产能 = 24h × 90% = 21.6h，预留 10% 供应急（坏件重打/修复/插单），不参与常规排产 |
| C9 | 前道 | 前道完成 ≤ 打印开始；前道占人工池（6 人、按件数人效、3班倒8h、换班30min无产出→净22.5h/天=45人·时）；前道时长=`件数 ÷ (人 × 件人效) + 方案审核分摊`（②下机+上机准备在静置窗口内一起做，归设备周转不进前道池）；前道失败无耗材无坏件、可重来 |

## 7. 目标函数（分层）

| 层 | 目标 | 定义 |
|----|------|------|
| 主 | 按期交付（加权迟到） | `min Σ(订单金额 × 违约金日费率 × 延期天数)`；排序：**交期升序 → priority 降序** |
| 偏好 | 同订单同舱 | 同一订单多款零件尽量合并进同一构建舱（减少齐套等待） |
| 次 | 舱利用率 | 仅**设备排满 / 无排队订单**（产能宽松）时追求填满舱；产能紧张优先保交期 |
| 低 | 负载均衡 | 不作为主要优化目标（换料已删：设备工艺固定） |

## 8. 计算口径

| 口径 | 公式 |
|------|------|
| 单件时长 | `Z高 ÷ 工艺速率`（SLA 50 / MJS 25 / SLM 15 mm/h） |
| 批次时长 | `max(舱内各件单件时长)`（纯打印，装料/准备忽略） |
| 后处理延时 | `POST_PROCESS_HOURS`：SLA 1h / MJS 3h / SLM 12h；**兼作设备周转占用**（机器静置期间被占，下一批须等静置完） |
| 延期代价 | `Σ(订单金额 × 违约金日费率 × 延期天数)`（加权迟到，P0-3） |
| 违约金日费率 | S=1% / A=0.5% / B=0.3% / C=0.3%（合同实测） |
| 订单完成 | `max(该订单各批次完成时间) + 后处理延时`（最后到达为准） |
| 日可用产能 | `24h × 90% = 21.6h`（预留 10% 应急） |
| 订单权重 | `客户等级基础分(S50/A40/B25/C10) + 加急(30/0) + 价值(金额≥5万→20/0) + 违约金(费率×3000：1%→30/0.5%→15/0.3%→9)`；系数可配，同交期时降序；**默认值已确认(2026-08-21)**；**信用分/延期率不纳入**（延期率=客户历史延期比例，往回看非输入；违约金=合同逾期赔付费率，未来成本） |
| 可用产能（T 窗口） | `Σ(已腾出机器 × T) + Σ(当天腾出机器 × (T − 预计腾出时间))`，仅计 T 内能腾出的机器；正在打印的机器排除 |
| 排队需求产能 | `Σ 排队订单所需机时`（按材料/机型分群，批次模型粗算，与求解口径一致） |
| 消化判断 | `需求 ≤ 可用` → 消化完，剩余 = 可用 − 需求；`需求 > 可用` → 缺口 = 需求 − 可用 |
| 缺机器数 | `⌈缺口 ÷ 单台 T 窗口产能⌉`（按机型分别核算） |
| 三区制判定 | 满负荷 100% 判断：需求 ≤ 90% 可用 → **绿**（常规够）；90% < 需求 ≤ 100% → **黄**（常规紧张，动应急池/加班）；需求 > 100% → **红**（需加机器） |
| CTP 承诺口径 | 按常规可用产能 `24h×90%`（不含 10% 应急池）；现有占用 = 打印中+已审核+待排队(含未审核)（P1-4） |
| 前道人工净产能 | `3班×8h − 3×30min换班 = 22.5h/天`（6人=每班2人 → 45人·时/天） |
| 前道任务时长 | `件数÷(人×件人效) + 方案审核分摊(0.5h/方案)`；下机+上机准备在静置/周转窗口内一起做（P1-1），归设备周转不进前道池 |
| 前道件人效默认 | SLA/MJS 15 件/人·h；SLM 6 件/人·h；综合 12（按件活动折算；**已确认**） |
| 负载/CTP 核算 | 需同时含**前道人工池**（前道也可能成瓶颈，不能只算设备产能） |
| 排队订单预计完成 | 满负荷 + 按目标函数顺序（交期升序 → priority 降序）推算的累计完成 |
| 排序键 | `交期(升序) → priority(降序) → 舱利用` |
| 订单预测 | 统计方法（移动平均/指数平滑，**不做训练**）；按天、分材料；窗口默认 7 天（可配）；输出预测订单量 + 预测产能占用（机时） |
| 大单承诺期（预测校准 CTP） | `现有占用（打印中+已审核+待排队）+ 预测未来占用 + 设备可用产能 → 最早可交付日期`；**不影响已下单订单**（现有承诺优先，预测只作未来占用预留）；按 90% 常规口径（不含 10% 应急池） |
| KPI 实时看板（B1） | 准交率（按期完成/应完成）、延期金额（Σ金额×违约金日费率×延期天数）、舱利用率（Σ批次投影面积/舱底面积）、良率（1−坏件数/完工数）、前道瓶颈占用（6 人池负载）；从 DB 实时聚合，随时间曲线 |
| 模型路由（B3） | 按任务类型分模型：简单工具查询→快/便宜模型；排产求解/复杂分析→强模型；策略进 system_config |

## 9. 非功能需求

| 编号 | 需求 | 说明 |
|------|------|------|
| NFR-01 | 求解可行性 | CP-SAT 对 demo 规模（7 台、百级 part）秒级出解；无可行解时给出冲突订单 |
| NFR-02 | 可解释 | 求解结果可被 LLM 解读（排产表 → 自然语言），回答"为什么/哪些延期/怎么改" |
| NFR-03 | 参数可配 | 速率/延时/舱尺寸/设备数量/优先级权重均为配置项，非硬编码 |
| NFR-04 | 可验证 | 输出硬约束自检（C1-C7 全满足）+ 指标（准交率/舱利用率/延期清单） |
| NFR-05 | 与 demo 集成 | 求解器作为工具接入现有 ToolRegistry + RBAC + 观测/审计 |
| NFR-06 | 数据样例 | 提供与字段模型一致的演示数据（orders/parts/machines/materials） |

## 10. 验收标准

- [ ] 输入样例订单集合 → 求解器输出排产表（每个 part → 批次 → 设备 → 开工/完成）
- [ ] 硬约束 C1-C9 全部满足（可程序化校验）
- [ ] **超尺寸零件（max>600）直接预警**，进入预警清单（而非静默忽略）
- [ ] **装舱面积/件数/承重判定正确**：Σ投影面积×0.7、件数上限、Σ件重≤承重
- [ ] 目标函数正确执行：加权迟到（金额×违约金日费率×延期天数）、交期→priority 排序、同订单同舱偏好
- [ ] 指标输出：准交率 / 舱利用率 / 延期订单清单
- [ ] 拆批场景正确（整批优先、超舱可拆、记录来源）
- [ ] 无可行解时给出冲突订单提示（而非空结果）
- [ ] **排版人审批流程**：方案待审核 → 通过下达上机 / 驳回重新排产；审批动作入审计
- [ ] **10% 产能预留生效**：常规排产占用 ≤90% 设备产能，应急池可用
- [ ] **CTP 计算**：新单在不影响排队/在途订单前提下，算出最短可交付时间（承诺交期）
- [ ] **订单预测**：按历史订单输出未来 N 天分材料预测订单量/产能占用（统计方法，非训练）
- [ ] **大单承诺期（预测校准 CTP）**：下大单时按"现有占用 + 预测未来占用 + 可用产能"给出承诺交付日期；预测预留生效，不偏乐观
- [ ] **RAG 检索质量达标**：重构后 ragas 四指标回归不劣于基线（context_precision≥0.60 / faithfulness≥0.80 / answer_relevancy≥0.80 / context_recall≥0.90）
- [ ] **KPI 实时看板（B1）**：`query_kpi` 从 DB 实时算出准交率/延期金额/舱利用率/良率/前道瓶颈占用，模拟器 tick 后数值变化正确
- [ ] **模型路由（B3）**：简单查询走快模型、排产/复杂走强模型；路由策略可配（system_config），成本统计随调用落库
- [ ] **RAG 权限检索（B4）**：不同角色检索同一问题返回不同文档集（保密合同过滤生效）；接 RBAC 后越权角色查不到受限条款
- [ ] **工具执行治理（B5）**：写工具（run_scheduling/approve_schedule）无 token 或越权被拒；只读工具调用不含写副作用；写操作入审计
- [ ] **Prompt/工作流版本化（B6）**：prompt 从配置加载（system_config 带版本号）；`--rollback` 可回滚旧版本；版本表记录变更、回滚动作入审计
- [ ] **良率/坏件闭环（B7）**：query_yield 按设备/批次/材料下钻良率；坏件关联根因（设备故障/材料）；LLM 给出改善建议
- [ ] **可观测 Dashboard（B8）**：生成 dashboard.html，含 KPI 曲线/成本统计/trace 摘要；数据与 query_kpi/cost 口径一致
- [ ] **Agent 调试台（M6）**：主页输入 → 两级链路展示（入参/出参/耗时/成功）；执行后 judge 打分；case 自动落盘 cases.jsonl（trace_id 主键、normal/chitchat/empty 类型、good/bad 仅 normal）；人工标注优先；按 trace_id 回放/重跑/批量 bad→good 转化
- [ ] **产能负载评估**：输出在途/排队分布 + 各订单预计完成时间
- [ ] 满负荷超期预警：超期订单清单正确（含在途与排队）
- [ ] T 窗口消化判断：排除在途机器后，可用 vs 需求 → 能否消化；剩余产能 / 缺机器数正确
- [ ] **三区制判定正确**：绿 / 黄 / 红边界（需求 vs 90%、100% 可用）准确
- [ ] **前道任务正确排产**：前道完成 ≤ 打印开始；人效/班制/换班（30min无产出）口径生效；前道不堵打印
- [ ] **订单状态跟踪**：按订单号查在途预计完成；排队订单预计开打/完成时间 + 前面单据清单正确（按交期→priority 队列顺序）
- [ ] demo 规模求解时间秒级
- [ ] LLM 可解释排产表（"哪些订单会延期、为什么"）
- [ ] 单元测试 + 集成测试通过（对接 demo run_all_tests.py）
