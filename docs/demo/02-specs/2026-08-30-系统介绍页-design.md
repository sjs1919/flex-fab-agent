# 系统介绍页（demo 首页 tab）设计规格

> 版本：v1 · 2026-08-30 · 状态：待评审
>
> 需求来源：用户反馈「功能介绍文档太复杂，业务端根本看不懂，也没有那么多时间看」，需要一个打开系统第一眼就能看懂的介绍页；并明确要求**作为现有前端控制台的一个 tab，作为登录后的默认首页**（非独立 HTML 页面）。
>

## 1. 背景与目标

### 1.1 背景

- demo 前端已有 6 个功能 tab（看板 / 调试 / 审批 / 案例 / 资源 / 配置），覆盖排产控制、调试、资源查看等**操作型**功能，但没有一个面向非技术读者的**认知型**入口。
- 现有「功能介绍 v1」文档技术含量高、篇幅长（337 行），业务端读不懂、也没时间读。
- 需要一个页面回答业务方最关心的四件事：**这是什么系统、业务怎么跑通、能做什么、靠不靠谱**。

### 1.2 目标

- 30 秒建立整体认知，3 分钟理解业务闭环，5 分钟能照着演示。
- 兼顾两个场景：

| 场景 | 读者 | 关心什么 | 页面阅读路径 |
|------|------|---------|-------------|
| 管理层汇报 | 老板 / 业务负责人 | 业务价值、闭环效果、可靠性 | ① Hero → ② 痛点 → ③ 业务闭环 → ⑤ 可靠性 → ⑥ 技术亮点 |
| 业务同事培训 | 新同事 / 业务人员 | 系统干什么、怎么用 | ③ 业务闭环 → ④ 能力速览 → ⑤ 演示示例 → ⑦ 去各 tab 试用 |

- **纯静态内容、零后端依赖**：后端没启动也能完整阅读，保证汇报/培训现场永远不翻车。

### 1.3 非目标（YAGNI）

- 不做独立登录页改造——demo 当前无登录流程（auth 为 admin token 自动签发，无用户体系），「登录后的首页」即 `PortalView` 的默认 tab，本次不引入登录页。
- 不拉实时数据——介绍页数据内联（静态），实时数据交给现有 6 个 tab。
- 不罗列全部 28 个端点 / 18 个工具——页面只挑业务最相关的 4 类能力，细节留给功能介绍文档。
- 不做文档搬家——本文档只负责新页面规格，不涉及 demo 文档目录迁移。

## 2. 方案权衡（为什么选「首页 tab」而非独立 HTML）

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| A. 独立单 HTML 文件 | 双击打开、零部署 | 与现有控制台割裂，无法跳转各功能 tab，风格不统一 | 否 |
| B. 前端控制台新增「首页」tab（本方案） | 融入现有 UI，可一键跳转各功能 tab，作为默认首页无缝接入 | 需随 web 构建 | ✅ 选此 |

结论：用户已指出系统已有排产页面体系，介绍页应作为**第一个 tab** 融入现有 `PortalView`，登录后默认看到。

---

## 3. 设计原则

1. **先结论后细节**——每节大标题是一句人话结论，细节用卡片/折叠承载，不强制读完。
2. **业务语言优先**——技术词首次出现配一句白话注释（例：CP-SAT →「用数学方法算出最优排单方案」），不出现代码。
3. **3 秒一个信息点**——大数字、卡片、流程图为载体，替代长段落。
4. **可交互引导**——每张能力卡片配一个可直接粘贴的自然语言提问，并带「去试试」按钮跳转对应 tab，实现从「看懂」到「上手」。

## 4. 页面整体结构

- 新增组件：`web/src/views/OverviewView.vue`
- Tab 定义：`label="首页"`、`name="overview"`，作为 `PortalView` 的**第一个** `el-tab-pane`
- 默认激活：`activeTab` 默认值由 `'dashboard'` 改为 `'overview'`
- 布局：垂直滚动，`padding: 24px; max-width: 1200px; margin: 0 auto`，沿用现有 `el-card shadow="never"` 风格

### 4.1 区块清单

| # | 区块 | 一句话内容 | 可视化载体 | 主要面向 |
|---|------|-----------|-----------|---------|
| ① | Hero | 这是什么系统 | 定位语 + 4 个大数字卡 | 所有人 |
| ② | 业务痛点 | 解决什么问题 | 3 张痛点卡片 | 汇报 / 培训 |
| ③ | 业务闭环 | 业务怎么跑通（核心区） | 6 步 CSS 泳道流程图 | 所有人 |
| ④ | 能力速览 | 能做什么 | 4 张能力卡片 + 提问示例 + 跳转按钮 | 培训 |
| ⑤ | 可靠性证明 | 靠不靠谱 | 3 个数字格 + 折叠演示主线 | 汇报 |
| ⑥ | 技术架构 | 技术底座长什么样 | 6 层 CSS 分层图 + 3 个设计亮点 | 汇报 |

## 5. 各区块详细规格

### 5.1 Hero（定位 + 4 数字）

- 主标题一句话：「面向 3D 打印柔性制造的智能排产系统」。
- 副标题一句话：「订单进来自动排队、电脑算出最优排单方案、全程不用人盯，从下单到打印完成自动闭环」。
- 4 个大数字卡（数字已与源码核对，见 §7）：

| 数字 | 值 | 人话注释 |
|------|----|---------|
| 订单 | 20 | 种子订单，模拟真实排产压力 |
| 设备 | 7 | 打印设备，排产就是排这些机器的活 |
| 操作页 | 6 | 除本介绍页外的 6 个功能页（看板/调试/审批/案例/资源/配置） |
| 智能工具 | 18 | 系统自己会用的 18 种能力（查单、排产、审批等） |

### 5.2 业务痛点（3 卡片）

| 痛点 | 一句话说明 |
|------|-----------|
| 手工排产慢 | 订单一多靠 Excel 排，排一轮要半天 |
| 插单就打乱 | 来张急单或设备故障，整张排产表推倒重来 |
| 交期拍脑袋 | 什么时候能交付说不准，客户追问只能估 |

### 5.3 业务闭环（6 步流程图，核心区）

CSS 横向泳道卡片 + 箭头，每步含：步骤名 + 一句话 + 谁来负责：

| 步骤 | 一句话 | 谁来做 |
|------|--------|--------|
| ① 下单 | 客户订单进入系统，先排队 | 客户 |
| ② 待排队 | 系统按交期和优先级排好队 | 系统自动 |
| ③ 自动排产 | 算出每件货在哪台设备、什么时候做（数学规划，不是猜） | 系统自动 |
| ④ 审批 | 排产方案先通过审批再执行 | 排版人（可自动批） |
| ⑤ 上机打印 | 订单进入打印中，占用设备 | 系统 + 设备 |
| ⑥ 完成 | 打印完成、设备释放、看板数据更新 | 系统自动 |

### 5.4 能力速览（4 卡片）

每卡：能力名 + 一句话 + 可直接粘贴的提问 + 「去试试」按钮（跳转对应 tab）。

| 能力 | 一句话 | 提问示例 | 跳转 |
|------|--------|----------|------|
| 对话问订单 | 用大白话查订单、设备、库存、客户 | 「现在有哪些紧急订单？」 | 调试 tab |
| 自动排产 | 一键跑排产，给出批次和交期 | 「帮我跑一轮排产」 | 调试 tab |
| 审批决策 | 排产方案一键通过或驳回 | 「审批通过最新排产版本」 | 审批 tab |
| 监控看板 | KPI、准交率、延期金额、良率一屏看 | 「当前准交率和良率是多少」 | 看板 tab |

### 5.5 可靠性证明

三个数字格：

| 指标 | 值 | 人话 |
|------|----|------|
| 自动化测试 | 61 个测试文件 | 一键全绿，不花钱（mock LLM） |
| 冒烟测试 | S0-S11 十二步 | 部署后分层自检，验证系统没跑偏 |
| 评估门禁 | ≥7/10 | 三层评估（工具/轨迹/语义）达标才放行 |

折叠区「现场 15 分钟演示」：演示主线 `A1 → A4 → B1 → D1 → E1 → C1 → H2 → G1 → I1 → F1 → J1 → K1 → L2`，每步对应一句可直接粘贴的提问（内容取自调试台测试用例 v1，含实测回填数值）。

### 5.6 技术架构（点到为止）

CSS 6 层分层图（自底向上），每层含中文名 + 白话注释：

| 层 | 白话注释 |
|----|---------|
| 数据层（订单/设备/库存/客户） | 所有业务数据的家 |
| 求解层 | 数学规划引擎，算最优排单方案 |
| 模拟层 | 生产流程仿真，跑「如果」看结果 |
| 智能体层 | 听懂人话、会自己调用工具干活 |
| 服务层 | 把能力变成接口，供界面调用 |
| 界面层 | Web 控制台，人看的窗口 |

3 个设计亮点（每点一句话 + 白话括号）：

1. **数学规划排产**——不是拍脑袋，是用约束求解算全局最优（CP-SAT 数学规划引擎）。
2. **全链路自动化**——从下单到完成无人值守，同一订单只被打印一次（幂等防重复）。
3. **对话式智能体**——用自然语言就能查数据、跑排产、批版本（18 种工具自动调度）。

### 5.7 从哪开始

- 4 个引导按钮：试试调试台 / 查看审批 / 看资源 / 看配置（跳转对应 tab）。
- 版本演进时间线：v1 对话助手（2026-08-04）→ v2 制造业主线（2026-08-25）→ v3 自动化 + 前端（2026-08-30）。

## 6. 技术实现

### 6.1 改动文件

| 文件 | 改动 | 风险 |
|------|------|------|
| `web/src/views/OverviewView.vue` | **新增**，介绍页组件（全部内容与样式） | 低 |
| `web/src/views/PortalView.vue` | import OverviewView；`activeTab` 默认值 `'dashboard'` → `'overview'`；插入第一个 `el-tab-pane` | 低（3 处小改） |

不改 `router`、`App.vue`、其他 6 个 View（`/` 已指向 PortalView，首页 tab 在聚合层实现，无需新路由）。

### 6.2 技术要点

- **纯静态**：所有数据内联在组件中，不 import 任何 `api/*`，不产生网络请求；后端未启动时页面完整可读。
- **图表策略**：优先 CSS（大数字、卡片、条形、时间线）与内联 SVG（流程箭头）；架构分层用 CSS 层叠卡片。尽量避免 ECharts——现有 `PortalView.onTabChange` 仅为 dashboard 做 `resizeCharts`，介绍页若引入 ECharts 需新增 resize 分支；用 CSS 图表可完全规避该问题。
- **lazy 渲染**：`el-tabs` 已开启 `lazy`，首 tab 激活即渲染，无并发竞态；介绍页作为首 tab 天然首屏展示。
- **样式**：`<style scoped>`，复用现有间距/卡片风格；不做暗色模式适配（现有页面均为浅色 Element Plus 默认）。
- **TS 红线**：组件类型完备，禁止 `any` 兜底；提问示例等静态数据抽为本地 `const` 数组。

### 6.3 不做的事

- 不新增路由、不加深链（现有看板/资源 tab 也无深链，保持一致）。
- 不改登录/鉴权逻辑。
- 不改其他 tab 组件，避免回归。

## 8. 验收标准（门禁）

1. **构建通过**：`web/` 在 WSL 下 `npm run build` 成功，TS 无类型错误。
2. **默认首页**：浏览器打开 `/`，无需任何点击即显示「首页」tab（介绍页）。
3. **零 API 调用**：DevTools Network 面板无 `/ask`、`/kpi` 等业务请求，介绍页纯静态。
4. **后端不启动可读**：仅启动前端（或静态托管 web 构建产物）时，介绍页内容完整渲染。
5. **数字一致性**：页面所有数字与 §7 来源逐条一致。
6. **跳转正确**：「去试试」等引导按钮切换到对应 tab，`activeTab` 正确更新。
7. **回归**：其余 6 个 tab 功能不受影响。
8. **全量测试**：`python run_all_tests.py` 全绿（后端未改动，应为零影响）。
