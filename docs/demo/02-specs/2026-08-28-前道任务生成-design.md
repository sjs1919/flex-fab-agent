# 前道任务生成 · 设计规格

> **日期**：2026-08-28 · **状态**：待评审 · **关联**：[rq-排程排产需求.md §3.15](../01-requirements/rq-排程排产需求.md)

## Context

### 现象

批次审批通过后，对应机器仍保持「空闲」，生产推进不到打印环节。

### 根因（已定位，证据链完整）

`solver.persist` 写排产表时只落 `schedule_versions` + `batches` 两张表，批次 `status` 硬编码为 `'前道'`，**从不生成 `preprocess_tasks`**。模拟器的状态机无法把批次从「前道」推进到「待上机」，机器占用只发生在「待上机 → 打印中」，于是机器永不占用。

| 环节 | 代码位置 | 现状 |
|------|----------|------|
| 排产落库 | `solver.py:101-128` `persist()` | 只写 versions + batches，`'前道'` 硬编码 |
| 前道推进 | `engine.py:125-139` `advance_preprocess()` | 查 `preprocess_tasks.end_time <= sim_time`，无任务则永远空转 |
| 机器占用 | `engine.py:68-86` `advance_batches()` | 仅「待上机 → 打印中」占用设备 |

诊断数据佐证：最新版本（53）125 个批次全 `status='前道'`，7 台机器空闲，`preprocess_tasks` 仅有 14 条旧数据（属于版本 1），sim_time（2026-09-17）已越过最早批次 start_time（2026-08-31）。

> 调用链经 codegraph 验证：`auto_scheduler → run_scheduling → solve + persist`；`engine.advance_preprocess` 消费 `preprocess_tasks`。

## 需求口径（§3.15，已确认）

| 项 | 值 |
|----|-----|
| 前道任务归属 | solver（schema 注释已写明「所有权：solver」） |
| 每批次前道任务 | 1 道（每批次打印前一道人工任务） |
| 前道时长公式 | `件数 ÷ (分配人数 × 件人效) + 方案审核分摊` |
| 件人效 | SLA/MJS **15** 件/人·h、SLM **6** 件/人·h、混合综合 **12**（兜底） |
| 方案审核 | 每次排产 **0.5h**，按方案内批次**分摊** |
| 硬约束 | **前道完成 → 打印开始**（C9） |
| 人工池 | 6 人，3 班 × 8h，换班 30min/次 → 净 **22.5h/天** |
| 前道失败 | 无耗材无坏件、可重来（本规格不涉及失败分支，v1 全成功） |

## 范围

**本次做**：
1. `solver.persist` 在**同一事务**内为每个批次生成 1 条 `preprocess_tasks`（与批次同生同灭）。
2. 字段按 §3.15 公式计算，`end_time = 批次 start_time`（满足 C9）。
3. 单元测试 + 集成验证：批次能推进到「待上机 → 打印中」，机器被占用。

**本次不做（后续/待定）**：
- 人工池并发排程（P2-4 待定：前道是否进求解器）——v1 只生成任务，不做池内并发调度。
- 前道失败/坏件/可重来分支。
- 审批联动（见 §风险与待确认项 A）。
- `preprocess_load` 负载评估逻辑（已有功能，本次不改，仅保证生成数据其可读）。

## 设计

### 1. 生成时机与位置

在 `solver.persist`（`solver.py:101-128`）现有事务内、批次 INSERT 之后，为每个批次 INSERT 一条 `preprocess_tasks`。与批次同事务 → 同生同灭，无孤儿任务。

### 2. 字段计算规则

`preprocess_tasks` 表结构（`schema.sql:164-177`）：

| 字段 | 规则 | 来源 |
|------|------|------|
| `batch_id` | `{version_id}-{原批次id}`（与 batches.id 一致） | persist 内已有 |
| `part_count` | `Σ parts.quantity` | 批次 `parts_json` |
| `man_hours` | `round(件数/(assigned_workers×件人效) + 方案审核分摊, 2)` | 复用 `assessment.preprocess_task_hours` |
| `assigned_workers` | **v1 默认 1**（待确认项 B） | system_config「前道」组 |
| `start_time` | `end_time − 日历时长`（见下） | 计算 |
| `end_time` | **= 批次 start_time**（C9 硬约束） | 批次行 |

**件人效**：按批次工艺取 `SLA/MJS→15`、`SLM→6`（复用 `assessment._per_part_eff(process)`）。

**方案审核分摊**：`0.5h ÷ 方案内批次数`。一个排产方案（一个 version）N 个批次，0.5h 平摊到每批次 `share = 0.5 / N`，加入该批次 man_hours。

**日历时长折算**（人·时 → 日历小时，含换班损耗 22.5/24）：

```
日历时长 = man_hours × 24 / (assigned_workers × 22.5)
start_time = end_time − timedelta(hours=日历时长)
```

与 `engine.SHIFT_FACTOR`（22.5/24）、`effective_man_hours`（`engine.py:24-29`）口径一致，保证模拟器日志折算自洽。例：SLM 批次 100 件、1 人、件人效 6 → man_hours≈16.67，日历时长≈17.8h，前道从打印前 17.8h 开始。

**无可行解批次**（`start_time` 为 None）：无法对齐 C9，**跳过**该批次的前道任务生成（该批次本身无排程，不生成也合理）。

### 3. 与模拟器推进的关系

生成后状态机闭环：

```
persist 生成前道任务(end=批次 start) → 审批通过
→ advance_preprocess: end_time ≤ sim_time → 批次 前道→待上机
→ advance_batches: start_time ≤ sim_time 且设备空闲 → 待上机→打印中（机器占用）
```

### 4. 实现改动点

- `demo/scheduler/solver.py`：`persist()` 批次循环内增加前道任务 INSERT；顶部或函数内 import `assessment.preprocess_task_hours`、`_per_part_eff`（`assessment` 不依赖 solver，无循环 import）。
- `demo/scheduler/assessment.py`：**不改**。仅复用现有纯函数（保持外科手术原则）。
- `demo/schema/schema.sql`：**不改**。表已存在，注释已声明所有权 solver。

### 5. 测试与验收

| 层 | 验证 |
|----|------|
| 单测 | `test_solver_persist.py` 增补：persist 后 `preprocess_tasks` 行数 = 批次行数；每任务 `batch_id` 对应存在；`man_hours` 公式正确（含方案审核分摊）；`end_time ≤ 批次 start_time`（C9）；start_time 折算正确 |
| 集成 | 模拟器推进：给定批次 start_time，sim_time 越过 end_time 后批次 前道→待上机→打印中，机器 status 变「打印中」 |
| 门禁 | `python run_all_tests.py` 全绿 |

## 风险与待确认项

| # | 项 | 说明 | 建议 |
|---|----|------|------|
| A | **审批联动** | 模拟器 `advance_preprocess` 不校验 `approval_status`。若批次「驳回」，前道任务仍在，sim_time 到时可能被推进 | v1 不阻塞（自动审批 FIFO 很快通过）；「驳回后任务是否清理/重排」另立计划 |
| B | **assigned_workers 取值** | v1 默认 1（旧样例一致、最简单）；6 人池如何分配到具体任务待定 | 默认 1，人工池排程留待 P2-4 |
| C | **方案审核分摊语义** | 「每次排产 0.5h 平摊到方案内批次」——0.5h 是否含排版人逐方案一次（而非逐批次）已按需求理解 | 按需求「÷ 方案内批次」实现 |
| D | **方案审核分摊基数** | 分摊基数取「该版本批次总数」还是「已审批批次」 | 取生成时版本内全部批次（同事务一致） |
