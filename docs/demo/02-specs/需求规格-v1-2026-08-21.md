## 1. 背景与目标

**背景**：本项目是企业级 Agent 开发加速训练（7 周 35 天）的实践载体。训练目标是从「Vibe Coding」进阶到「Agent Developer」，即具备工程化思维——Agent 不能只"能回答"，还要"可观测、可限权、可评估、可维护"。

**目标**：构建一个面向**制造业排程排产**的多 Agent 助手，用自然语言回答生产相关问题，并演示一套贴近生产实践的工程化底座（Harness 三层：编排 / 权限 / 观测）。Demo 同时承担三重角色：

1. **技术展示**：向行业/面试官证明具备企业级 Agent 工程化能力（而非纯调 API）。
2. **训练载体**：每周训练成果在同一载体上叠加演进（week1-5 整合 + R1-R8 缺陷修复）。
3. **发展基线**：作为后续按行业推荐方案补齐差距（M1-M13）的固定基准。

**原则**：demo 载体锁定制造业排程排产，不跨行业（能力可升、场景不换）。

## 2. 术语表

| 术语 | 含义 |
|------|------|
| Agent | 能自主决策调用工具的智能体 |
| 工具（Tool） | 以"函数 + 描述"暴露给 LLM 的数据/检索能力 |
| LangGraph | 基于状态图的 Agent 编排框架（节点 + 条件边） |
| Supervisor | 多 Agent 模式的主管：路由 + 分派 + 汇总 |
| RAG | 检索增强生成，本 demo 为合同知识库混合检索 |
| RBAC | 基于角色的访问控制（5 角色令牌） |
| STS | 安全令牌服务：签发受限子令牌（RFC 8693，5min TTL） |
| MCP | Model Context Protocol，工具协议化（本 demo 展示形态） |
| Harness 三层 | 编排层（graph/agents）+ 权限层（auth）+ 观测层（observability） |

## 3. 范围

### 3.1 包含（v1）

- 排产业务问答：订单排期 / 订单详情 / 紧急订单与瓶颈 / 客户评估 / 库存影响
- 合同知识库问答（RAG 混合检索）
- 两种运行模式：单 Agent（LangGraph 自循环）与多 Agent（Supervisor + 子 Agent）
- 工程化底座：观测导出、状态持久化、语义缓存、成本监控、审计日志、RBAC 鉴权、工具沙箱、输出护栏、上下文压缩、MCP 展示、三层评估、回测、一键自动化测试

### 3.2 不包含（v1，留待演进）

- **真实排产算法**：无 APS 约束求解（OR-Tools/启发式），排产为 LLM 文本建议（→ M1）
- **真实业务数据源**：数据为本地 CSV 只读快照，非 MySQL/MES/ERP（→ M2）
- **生产级加固**：无 API 限流、JWT 签名、CI 评估流水线、多环境隔离（→ M5/M6/M7/M13）
- **前端可视化**：无排产看板/Web 界面（CLI + FastAPI 网关，→ M9）

## 4. 用户与典型场景

| 角色 | 使用方式 | 典型诉求 |
|------|---------|---------|
| 排产员/主管 | CLI 或网关 HTTP 提问 | "今天先做哪些订单？" |
| 评估/面试官 | 跑预设场景 + 看 trace/审计/评估报告 | 验证工程化深度 |
| 训练学习者 | 逐层读代码 + 跑通验证 | 理解 Agent 工程化演进 |

**示例问答**（对表 README §1）：
- 订单排期：`今天先做哪些订单？`（综合交期、客户等级、库存、设备负载排序）
- 订单详情：`ORD001 能按时交付吗？`（查状态、材料、设备）
- 紧急与瓶颈：`有哪些紧急订单？哪些设备和材料是瓶颈？`
- 客户评估：`东莞模具厂订单总体情况？信用如何？`
- 库存影响：`PEEK 材料库存够吗？不够会影响哪些订单？`
- 合同知识库：`广州航天合同有什么特殊条款？`（RAG 命中合同原文）

## 5. 功能需求

### 5.1 业务功能（P0 · 核心问答能力）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-01 | 订单排期问答 | 综合交期、客户等级、库存、设备负载对订单排序作答 |
| FR-02 | 订单详情追踪 | 查询订单状态、材料、设备，判断能否按时交付 |
| FR-03 | 紧急订单与瓶颈识别 | 识别紧急订单及瓶颈设备/材料 |
| FR-04 | 客户评估 | 按客户汇总订单总体情况与信用 |
| FR-05 | 库存影响分析 | 材料库存是否充足，不足时影响哪些订单 |
| FR-06 | 合同知识库 RAG | 检索合同特殊条款并引用原文（向量 + BM25 + RRF + 重排） |

### 5.2 运行模式（P0 · 架构能力）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-07 | 单 Agent 模式 | LangGraph 状态图：分析→选工具执行→评估结果→生成答案，5 轮安全阀防死循环 |
| FR-08 | 多 Agent 模式（Supervisor） | 主管路由到订单评审/生产评估子 Agent，子 Agent 持受限令牌调工具，主管 LLM 汇总并出审计报告 |
| FR-09 | 工具注册中心 | ToolRegistry：O(1) 查找 + 参数白名单 + RBAC 强制 + tracer 接入 |

### 5.3 工程化能力（P1 · 生产底座）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-10 | 多轮对话与状态持久化 | LangGraph checkpointer（SQLite 默认落盘），`--chat` 多轮、`--thread` 跨进程恢复 |
| FR-11 | 上下文压缩 | summarization buffer：超阈值转摘要，保留 system + 最近 N 条 |
| FR-12 | 语义缓存 | Chroma cosine 近义改写命中（阈值可调），多轮场景自动跳过 |
| FR-13 | 精确缓存（L1） | 相同 prompt SQLite 命中 <1ms、0 token |
| FR-14 | 观测导出 | tracer 全链路 span；`OTEL_EXPORTER` 选 console/otel/otlp（可接 Jaeger） |
| FR-15 | 成本监控与熔断 | LLM 自动计费 + 预算熔断 + 费用摘要 |
| FR-16 | RBAC 鉴权 + STS | 令牌签发→交换受限子令牌（5min TTL）→工具层权限校验（洋葱三层） |
| FR-17 | 审计日志 | JSONL 即时落盘，trace_id 贯穿，记录每次鉴权决策 |
| FR-18 | 工具沙箱 | 超时控制 + 指数退避重试（TOOL_TIMEOUT/TOOL_MAX_RETRIES 可配） |
| FR-19 | 输出护栏 | 越权指令/敏感信息检测 + 缺失段落检查，block/warn/off 三模式 |
| FR-20 | MCP 架构展示 | MCP_MODE=local/mcp，子进程 stdio 通信演示协议化形态 |
| FR-21 | 多租户隔离 | Token + tenant_id，数据层租户过滤，FORCE_TENANT 强制模式 |
| FR-22 | 三层评估 | 10 组 ground truth；工具(0.5)+轨迹(0.3)+语义(0.2) 聚合；LLM-as-Judge 可跳过降级 |
| FR-23 | 历史回测 | 5 个历史延期案例，Agent 复盘 vs 人工结论覆盖度评分 |
| FR-24 | 一键自动化测试 | `run_all_tests.py` 全量单测+集成（mock LLM 零成本）+ 可选评估/报告 |

## 6. 非功能需求

| 编号 | 需求 | 指标/说明 |
|------|------|----------|
| NFR-01 | 主备 Provider 降级 | 火山豆包主 + DeepSeek 备，主失败自动切换；连接池 keep-alive 60s |
| NFR-02 | 安全 | STS 子令牌权限 ≤ 父令牌，防权限升级；工具执行前 RBAC 校验 |
| NFR-03 | 性能 | L1 缓存命中 <1ms；语义缓存命中 ~50ms；RAG 重排器常驻秒级响应 |
| NFR-04 | 成本 | 计费 + 熔断 + 语义缓存省 token；评估可 `--no-judge` 降级 |
| NFR-05 | Windows 兼容 | 输出重配 UTF-8（GBK 显示修复）；LLM 直连绕过系统死代理（trust_env=False） |
| NFR-06 | 离线能力 | 向量/重排模型本地缓存，HF 离线防坑（patch constants） |
| NFR-07 | 数据层 | 本地 CSV 只读快照 + tenant_id 租户过滤；运行会话数据（checkpoints/cache_db）gitignore |
| NFR-08 | 可维护性 | 中文注释标注设计意图；分层清晰（基座/工具/编排/Agent/鉴权/观测/评估）；TypeScript 严格类型同源规范 |
| NFR-09 | 环境隔离 | API Key 走 .env 不提交 Git；Provider 由统一 PROVIDERS 列表管理 |

## 7. 验收标准

**验收基线**（以 `demo/README.md` §验收清单 为可执行源，逐项已打勾）：

| 类别 | 标准 |
|------|------|
| 地基 | `python -m demo.main --check` 通过（config/LLM/工具三层连通） |
| 业务 | 单 Agent 订单问题多工具调用 + 综合回答；RAG 命中合同（rerank 分 >0.9） |
| 多 Agent | Supervisor 分派 + RBAC 拒绝越权 + 审计报告 |
| 工程化 | R1-R8 + #1-#7 全部验收项打勾（沙箱/护栏/评估/租户/缓存/持久化/观测/成本/审计/连接池/MCP） |
| 自动化 | `python run_all_tests.py`：全量单测+集成 **128 passed** |
| 评估 | 三层评估回归基线 **≥7/10**（case ≥0.6 判 pass） |
| 回测 | 5 个历史延期复盘场景跑通 |

> v1 评审通过后，验收标准拆出为独立 `docs/demo/验收清单.md`，作为后续逐项跟踪与回归的执行表。
