# 资源聚合页 设计

> **日期**：2026-08-26 · **状态**：已批准（用户 2026-08-26）

## Context

前端已做单页 tab 聚合（看板/调试/审批/案例/配置）。用户需要**聚合查看资源**：设备、客户、订单、库存、批次、前道任务，列表统一 id 倒序。强调**前端界面完整展示**（非仅接口）。系统已有这些数据表（machines/customer/orders/inventory/batches/preprocess_tasks），但无资源列表 REST 端点与前端页面。

**范围外（独立计划）**：人员模块（personnel 表 + 状态 + 模拟器 leave 联动 + 前端）。模拟器 `_fire_leave`（engine.py:311）已实现"前道工人池"请假/回岗，但非具体人员名单；personnel 具体化 + 联动需单独计划，本次不纳入。

## 范围

本次：6 类资源只读聚合展示：
1. **设备** machines（id/name/process/model_type/cabin_size/max_weight/status/current_batch_id）
2. **客户** customer（id/客户名/等级/信用分/违约金率等）
3. **订单** orders（id/客户/工艺/交期/数量/状态/优先级等，经 load_orders 归一）
4. **库存** inventory（id/名称/材料名/库存量/单位/安全库存/单价）——material 表为工艺速率配置（rate_mm_h 等），非资源展示，不入本次
5. **批次** batches（id/版本/工艺/机型/设备/起止/状态/审批）
6. **前道任务** preprocess_tasks（id/批次/件数/人时/分配人数/起止）

## 架构

### 后端：`GET /resources/{category}`

- category ∈ `machines | customers | orders | inventory | batches | preprocess`
- 复用 `demo/tools/data.py` 的 `load_*`（mysql 路径已就绪，返回 `list[dict]`，key=列名）：
  - `load_machines()` / `load_customers()` / `load_orders()` / `load_inventory()` / `load_batches()` / `load_preprocess_tasks()`
- 返回 `{"items": [...]}`，统一 **id 倒序**（`items[::-1]`，因 load_* 按 id 正序）
- 只读，无写操作；无需鉴权（只读看板端点，对齐 R-7 匿名可读）

### 前端：PortalView 加「资源」tab

- 聚合页新增 tab「资源」（name=`resources`），内部 6 子 tab（`el-tabs`）：设备/客户/订单/库存/批次/前道
- 各子 tab 一个 `el-table` 展示该表字段（列名即表列，`prop` 对齐 load_* 返回 key），右上角刷新按钮
- 新建 `web/src/api/resources.ts`：`fetchResources(category)` → `GET /resources/{category}`，返回 `items`
- 复用现有 axios 模式（参考 `api/schedule.ts`）；`el-tabs lazy` 首激活渲染

### 排序

统一按 id 倒序：订单/设备/客户按 id desc；库存按 id；批次/前道按 id desc（自增/字符 id 即时间序反向，满足用户"时间倒序或 id 倒序"）。

## 数据流

```
前端资源 tab 挂载/切换子 tab → GET /resources/{category} → data.py load_*（mysql）→ {"items": [...]} → el-table
```

## 人员（独立计划）
