# MySQL 外键删除顺序坑（1451）

> 日期：2026-08-27 · 触发：自动排产调度器 FIFO 自动审批 + 测试清理排产版本

## 现象

`DELETE FROM schedule_versions` 报 `pymysql.err.IntegrityError: (1451, 'Cannot delete or update a parent row: a foreign key constraint fails (approvals fk_approvals_version REFERENCES schedule_versions)')`。

## 根因

MySQL 外键约束：**删除父表行时，若子表仍有引用则拒绝（1451）**。`approvals`（`fk_approvals_version → schedule_versions.id`）、`batches`（`fk_batches_version → schedule_versions.id`）都是 schedule_versions 的子表。

触发面扩大：2026-08-27 新增**自动排产调度器的 FIFO 自动审批**——对"早于最近 top20"的待审核版本自动 `approve_schedule`（写 `approvals` 表，approver=system）。从此 `approvals` 表有大量系统审批记录引用版本，测试/工具清理 `schedule_versions` 时频繁触发 1451。

## 修复（必须按顺序删：子表 → 父表）

```sql
-- 正确顺序：先删引用子表，再删父表
DELETE FROM approvals WHERE schedule_version_id = <vid>;        -- 子表（FK 引用）
DELETE FROM batches   WHERE schedule_version_id = <vid>;        -- 子表（FK 引用）
DELETE FROM schedule_versions WHERE id = <vid>;                 -- 父表
```

- 清全表同理：`approvals → batches → preprocess_tasks → schedule_versions → ...`
