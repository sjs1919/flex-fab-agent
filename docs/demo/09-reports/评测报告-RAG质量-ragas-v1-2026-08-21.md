## 3. 问题清单（三类，逐一对应修改点）

### 3.1 context_precision 最弱（均值 0.60）— 检索噪声

- **表现**：Q3/Q4/Q5 的 top_k 检索 chunk 各只有 1/3 相关（relevance 数组多为 [true, false, false]）。
- **根因**：混合检索 RRF 融合对 demo 短文档场景区分度低、top_k 偏大；重排后未精取。
- **修改点** → 重构方案 §7.7 **E5-a**：`rag/retriever.py` 调参——top_k 收敛（3→按需 1-2）、重排后精取、短文档场景提高 BM25 权重。

### 3.2 faithfulness 系统性扣分 = "来源标注"（Q1/Q2/Q5）

- **表现**：三题 LLM 回答首句"约定依据是 xxx.txt / 来源于 xxx"全部 `supported: false`——上下文 chunk 不含来源文件名，LLM 却习惯性声称来源。
- **根因**：`rag/knowledge_base.py` 分块未携带 source 元数据；LLM 无来源可依据却仍写"来源"。
- **修改点** → 重构方案 §7.7 **E5-b**：chunk 注入 source 元数据 + prompt 禁止声称无依据来源。

### 3.3 answer_relevancy 摘要不全 + 推理冒充原文（Q3/Q4/Q5）

- **表现**：
  - Q3：反向问题"折扣与加急费能否叠加"未匹配（答案漏"不与加急费叠加"）。
  - Q4：致密度 ≥99.5% 未检索到（context_recall 0.67）→ 关键 chunk 丢失。
  - Q5："总共赔付 51000 元"（=36000 报废 + 15000 赔付的**计算**）被写成原文事实 → faithfulness 扣分。
- **修改点** → 重构方案 §7.7 **E5-c**：prompt 要求覆盖要点全量；**区分"原文事实"与"我的计算/推断"**（Q5 应写"报废 3.6 万 + 赔付 1.5 万，合计 5.1 万（计算）"）。
