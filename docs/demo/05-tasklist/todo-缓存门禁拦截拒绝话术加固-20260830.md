# 缓存门禁加固：拦截「拒绝/无法完成」类话术入语义缓存 待办

> 日期：2026-08-30 · 优先级：P1 · 状态：✅ 已完成（拒绝话术 + 汇总兜底前缀拦截，单测 + 全量 + 冒烟全绿）
> 背景：`todo-待排产查询汇总步拒绝话术修复-20260830.md` 复测中发现——修复前的拒绝话术（「抱歉，我无法完成这个查询…工具已不可用」）被语义缓存门禁放行，写入缓存后重复命中（trace `73d6c8e16bf24dc1` cache:lookup hit）。已靠清缓存 + 源头（NUDGE）修复解决，但**缓存门禁仍会放行拒绝话术**，属投毒变体，需加固。

## 事项（缓存投毒变体）

当前缓存写入门禁（`demo/agents/single_agent.py` store_semantic 前）：
```python
if (not _looks_like_tool_markup(fa)
        and fa != _GRACEFUL_FALLBACK
        and not fa.startswith(LOOP_GUARD_FALLBACK_PREFIX)):
    cache_manager.store_semantic(query, fa, ...)
```
只拦截：DSML 标记文本 / 生成异常兜底 / 循环守卫 dump。**不拦截「拒绝/无法完成」类话术**——LLM 因系统提示误导或其它原因输出的拒绝话术会被当正常答案缓存，后续重问一直命中垃圾。

## 修复方案

**方案 A（推荐·缓存门禁拦截）**：新增 `_looks_like_rejection(text)` 辅助，识别拒绝/故障话术特征词（如「无法完成」「工具已不可用」「请重新发送」「系统提示表明」），命中则**不入缓存**。放在现有缓存写入门禁处。

**方案 B（可选·源头兜底）**：`generate_answer` 检测 LLM 输出含拒绝特征 → 降级为基于工具结果拼接兜底（拒绝话术根本不产生）。更治本，但改动面大、可能误伤合理拒绝回答。

**决策**：本轮做 A（缓存门禁，防线）+ 观望是否需要 B。A 改动最小、直接封堵投毒入口。

> 说明：拒绝话术特征词难穷举，A 采用「窄特征集」（只收本次 trace 实证的 + 高频拒绝词），宁可漏不可误伤（避免合法回答不入缓存）。
