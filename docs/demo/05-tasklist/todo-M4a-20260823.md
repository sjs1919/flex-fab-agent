## 关键设计

### 工具清单（11 个）

| 工具 | M4a 状态 | read_only | 说明 |
|------|---------|-----------|------|
| run_scheduling | ✅ 实装 | false | load_snapshot -> solve -> persist（triggered_by=agent）+ solver span + 审计 |
| query_schedule | ✅ 实装 | true | 最新版本排产表（schedule_versions + batches，参数 version_id 可选） |
| query_sim_events | ✅ 实装 | true | 查 sim_events（参数 event_type/status/时间窗/limit） |
| approve_schedule | ✅ 实装 | false | 版本 待审核->已审核/已驳回 + batches.approval_status + approvals 表 + 审计（reviewer 专属） |
| query_ctp / query_load_assessment / query_order_tracking / query_preprocess_load / query_kpi | 📦 占位 | true | 返回「M4b 提供」 |
| query_forecast / query_yield | 📦 占位 | true | 返回「M5 提供」 |

### 治理链路（D3，洋葱校验顺序）

`token 校验 -> RBAC（can_access）-> 写工具分支（无 token 拒绝 R-2 + 配额 R-D2）-> execute（超时/重试透传 R-6）`
- 配额：内存计数（subject+tool 维度，5min 滑窗，写工具 >3 拒绝），拒绝写审计 `quota_exceeded` + tracer span
- 单 Agent 无鉴权模式兼容：只读工具无 token 放行（现状）；**写工具无 token 一律拒绝**（R-7 验收依据）

### Prompt 版本化（R-4）

`demo/prompts/versions/v1/system_prompt.txt`（从 system_prompts.py 现内容拆出）+ `versions.json`（版本清单+当前生效）+ 加载器 `load_system_prompt()`；`--rollback <version>` 改 versions.json 当前版本 + 审计。v1 内容不变（纯搬家），保证回归。

### API（FastAPI 已有 /ask /health）

新增：`POST /sim/start|stop`、`GET /sim/status`、`GET /schedule/latest`、`POST /schedule/load`（触发 solve+persist，admin token）；`/health` 补 sim 运行态。写端点无 admin token 被拒（R-7）。

### 踩坑记录（T4a.6）
1. **run_scheduling 经 sandbox 120s 超时**：CP-SAT 按工艺分组（SLA/MJS/SLM）各自 `max_time_in_seconds=60` 串行求解 → 实际墙钟可达 ~180s（实测 188.7s），v2 §7.1 的 timeout_override=120 按"总预算 60s"假设设定 → 沙箱先杀。修正：`timeout_override=240` + `max_retries_override=1`（v2 §6 solver 重试降为 1），并在 test_registry_gov 注明偏离依据。
2. **approve_schedule 的 approver 注入失效**：schema 未暴露 `approver` 参数，注入条件（`"approver" in valid_keys`）不成立 → 审批人恒为默认 "reviewer"。修正：schema 补 `approver` 字段（标注自动注入），且 token 存在时**无条件以 token.subject 为准**（防 LLM 伪造审批人）。
3. **main() 读 sys.argv**：测试直接 `main([...])` 抛 TypeError，须 monkeypatch `sys.argv` 后再调。
