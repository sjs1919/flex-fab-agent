## 关键设计

### 计算口径（需求规格 §8，M4b 全部依据）

| 口径 | 公式 | 数据来源 |
|------|------|---------|
| 日可用产能 | `24h × 90% = 21.6h`（预留 10% 应急池，不参与常规排产） | material + machines |
| T 窗口可用产能 | `Σ(已腾出机器 × T) + Σ(当天腾出机器 × (T − 预计腾出时间))`，仅计 T 内能腾出的；正在打印排除；T 默认 24h | machines.status + batches |
| 排队需求产能 | `Σ 排队订单所需机时`（按工艺分群，批次模型粗算 = Σ件数×单件时长） | orders(status=待排队) + parts |
| 消化判断 | 需求 ≤ 可用 → 剩余 = 可用−需求；需求 > 可用 → 缺口 = 需求−可用 | — |
| 缺机器数 | `⌈缺口 ÷ 单台 T 窗口产能⌉`（按工艺分群） | — |
| 三区制 | 需求 ≤ 90% 可用 → **绿**；90% < 需求 ≤ 100% → **黄**；> 100% → **红** | — |
| CTP | 按常规可用 `24h×90%`；现有占用 = 打印中+已审核+待排队(含未审核)；承诺建立在全部排队需求之上（不扰动现有订单）；**同时含前道人池** | orders + parts + preprocess_tasks |
| 前道净产能 | `3班×8h − 3×30min换班 = 22.5h/天`（6人 → 45人·时/天） | system_config 前道 |
| 前道任务时长 | `件数÷(人×件人效) + 方案审核分摊(0.5h/方案)`；SLA/MJS 15 件/人·h、SLM 6、综合 12 | preprocess_tasks |
| 排队订单预计完成 | 满负荷 + 按目标函数顺序（交期升序 → priority 降序）推算累计完成 | orders + batches |
| KPI 5 项 | 准交率=按期完成/应完成；延期金额=Σ金额×违约金日费率×延期天数；舱利用率=Σ批次投影面积/舱底面积；良率=1−坏件数/完工数；前道瓶颈占用=6 人池负载 | orders + batches + sim_events(scrap) + preprocess_tasks |

### 工具清单（5 个占位 → 实装）

| 工具 | 输入 | 输出要点 | read_only |
|------|------|---------|-----------|
| query_load_assessment | 无（全量） | 四段报告：在途/排队分布 → 各订单预计完成 → 满负荷超期预警清单 → T 窗口消化（剩余产能/缺机器数）+ 三区制（绿/黄/红）+ 前道人池双瓶颈 | true |
| query_ctp | material/quantity/height_mm/due_date? | 最短可交付时间（现有占用全排完 + 新单机时，取 max(设备序列, 前道池)；due_date 给"能否按期"） | true |
| query_order_tracking | order_id | 在途→预计完成；排队→预计开打/完成 + 前面单据清单（交期升序→priority 降序） | true |
| query_preprocess_load | 无（全量） | 前道人池负载：任务排队/在途、池占用率、预计清空时刻、是否成瓶颈 | true |
| query_kpi | 无（全量） | 5 项指标（准交率/延期金额/舱利用率/良率/前道瓶颈）+ 指标口径说明 | true |

### B3 模型路由（v2 C7）

- `call_llm()` 加 `task_type: str = "complex"` 参数（默认 complex 保主用强模型，不破坏现有调用）；`call_llm_simple()` 透传
- 路由策略：`system_config`（category=`路由`，key=`routing_policy`，value=JSON `{"simple": "<provider名>", "complex": "<provider名>"}`）；未配置/不可用回落默认顺序（保持主备降级）
- 调用点标记：主 Agent 工具轮按"本轮 tools 是否含复杂工具"判定（run_scheduling/query_load_assessment/query_ctp/query_order_tracking/query_preprocess_load/query_kpi → complex；纯只读简单查询 → simple）；generate_answer/supervisor/production_agent/review_agent → complex；eval/judge → simple
- 成本统计随调用落库：**复用 cost_tracker**（call_llm 内已 record，无需新增）；tracer span 加 `task_type` 属性
- 语义：B3 是成本可控手段——简单查询走便宜模型降熔断概率（v2 G-19 保持 BudgetExceededError 中断语义）
