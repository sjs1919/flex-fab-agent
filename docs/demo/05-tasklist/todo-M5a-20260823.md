## 关键设计（用户 2026-08-23 确认口径）

### 预测口径（rq §3.19）

| 项 | 口径 |
|----|------|
| 时间维度 | **orders 新增 `order_date` 字段**（下单日；schema + seed 同步）；按 order_date 按天聚合 |
| 聚合粒度 | 分材料（SLA/MJS/SLM）：件数 = Σparts.quantity；机时 = Σ(height÷rate×quantity)（批次模型粗算同 load_assessment） |
| 方法 | **指数平滑**（默认，α 可配）+ 移动平均备选；`forecast_method` 进 system_config |
| 窗口 | **5 天**（用户指定，替代 rq 推荐 7；`forecast_window` 可配） |
| 大单阈值 | **金额 ≥ 5 万**（`large_order_amount` 可配）；query_ctp 文案对大单提示预测校准承诺 |
| 输出 | 未来 N 天逐日：预测订单量（件）+ 预测产能占用（机时），分材料 |

### 预测校准 CTP（大单承诺期）

```
承诺期 = 现有占用（打印中+已审核+待排队，§3.12 原口径）
       + 预测未来占用（预测窗口 5 天内预测机时，按 90% 常规日产能折算预留天数）
       + 新大单自身机时
       -> 最早可交付日期
```
- 不影响已下单订单（预测只作预留，不插入现有队列）；承诺比常规 CTP 更保守
- `compute_ctp_from_db` 返回增加 `calibrated_ctp`；query_ctp 文案同时给常规与校准承诺，大单（金额≥5万）标注

### 良率/坏件闭环（B5/B7，rq §3.23）

| 项 | 设计 |
|----|------|
| `bad_parts` 表（新） | id / batch_id / machine_id / material / part_count / related_event_id（关联 sim_events）/ sim_time / tenant_id |
| 落库点 | engine.py `_scrap_inspect`（L89，现有 scrap 事件触发处）：scrap 发生时同事务写 bad_parts，带设备/批次/材料根因维度 |
| query_kpi 口径统一 | 坏件数改从 bad_parts 统计（`COUNT`），与 query_yield 同源；sim_events scrap 事件保留（时间线用途） |
| query_yield 输出 | 良率总览 -> 按设备下钻（哪台良率低+关联 MTBF 故障）-> 按批次（哪批坏件多）-> 按材料（坏件率对比）-> LLM 改善建议（烂设备->检修、材料->换料）；LLM 失败降级规则模板 |

### RAG 权限检索（E6，rq §3.20 B4）

### 踩坑预判（T5a.15 记录区）
1. **assessment<->forecast 循环依赖**：forecast 不得 import assessment（assessment 延迟 import forecast）
2. **存量 chroma_db 无 permission meta**：权限过滤按 source 文件名映射，不重建向量库
3. **query_kpi 口径切换兼容**：旧库无 bad_parts 数据时回落 sim_events 计数，避免良率显示异常
4. **bad_parts 件数口径**：scrap 是整批抽检坏件（件数取批次件数的抽样量，非整批）
5. **tick 联动测试耗时**：tick 推进用 engine 快进接口，勿真实跑 wall-clock
