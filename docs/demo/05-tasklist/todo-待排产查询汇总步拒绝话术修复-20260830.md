## 事项

问题「帮我查一下所有待排产的订单」产出答非所问（「抱歉，我无法完成这个查询…工具已不可用」），真实 trace `8516ffd28bfa4789`、复现 trace `231d41428f7e4482`。根因链：

1. **决策轮**：LLM 调 `query_orders(status=待排队, limit=0)` → 空结果「未找到匹配的订单。」（evaluate 空结果拦截 → `ready_for_answer`）
2. **汇总步**：`generate_answer` 第一次 LLM 输出 DSML 标记文本（想再调工具确认，解析失败）→ `ToolMarkupOutput` 捕获
3. **注入 `_SUMMARY_NUDGE`**（`single_agent_graph.py`）：措辞含「**工具已不可用**，请勿输出任何工具调用语法…」
4. **LLM 误读为系统故障** → 输出「抱歉，我无法完成这个查询…工具已不可用」拒绝话术
5. **护栏放行**：段落缺失仅告警不拦截（`guardrails/__init__.py:61`），无「禁止内容」→ 拒绝话术成为 `final_answer`

**核心缺陷**：`_SUMMARY_NUDGE` 措辞「工具已不可用」被 LLM 理解为故障状态，诱导拒绝任务而非基于已有工具结果作答。

**是否本次 A/B 引入？** 否——generate_answer / NUDGE 未动，空结果拦截正常，是汇总步既有措辞缺陷（2026-08-26「汇总步标记防护」埋下）。

## 修复方案（A+B，用户确认）

**方案 A**：改 `_SUMMARY_NUDGE` 措辞——去掉「工具已不可用」，改为「工具结果已收集齐全，请勿再次调用工具，直接基于上述工具查询结果用中文给出最终回答」。

**方案 B**：重试时附已收集工具结果摘要（`tool_results` 前 200 字符/条），引导 LLM 基于数据作答（不信「未找到」时不再盲目再查）。
