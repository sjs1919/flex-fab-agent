> 背景：问题「帮我把待审核的排产版本审核通过」产出兜底道歉（trace `0e5cddd0b8b7451b` / 复现 `dd8d8fcd07d84aa4`）。

## 事项（审核意图缺失 + 汇总兜底道歉）

根因链：
1. **app_intent 漏「审核」**（`demo/graph/single_agent_graph.py:310`）：`app_intent = any(k in user_text for k in ("审批", "驳回"))`——用户说「**审核**通过」不含「审批/驳回」→ 审批意图未识别 → evaluate 不强制 `approve_schedule`
2. **直接进汇总**：`has_schedule_context=True`（决策轮查了 `query_schedule`）→ `ready_for_answer` → generate_answer
3. **汇总步 LLM 仍想审批**：写操作未执行，LLM 在汇总步尝试输出 `approve_schedule` 工具调用语法 → 连续 3 次标记文本 → `MAX_RETRIES` 耗尽 → 降级 `_GRACEFUL_FALLBACK`（「抱歉，本次回答生成异常」）

**核心缺陷**：审批意图关键词不全（「审核」漏收），且汇总步标记文本重试耗尽后只道歉、不利用已有工具结果。

## 修复方案（A+B，用户确认）

**方案 A（根因）**：`app_intent` 补「审核」→ `("审批", "驳回", "审核")`。「审核通过」触发审批意图检查 → evaluate 发现 `approve_schedule` 未执行 → `needs_more` 继续工具轮 → LLM 调写工具审批落地。
- 副作用可控：含「审核」的非审批查询（如「查审核记录」）多走一轮工具轮，LLM 会判断不调写工具正常回答，无实际危害。

**方案 B（防御）**：`generate_answer` 标记文本重试耗尽（`MAX_RETRIES` 后）不再降级 `_GRACEFUL_FALLBACK`，改为**用已收集工具结果拼接兜底**（带前缀 `_SUMMARY_FALLBACK_PREFIX`），并在 `single_agent.py` 缓存门禁拦截该前缀（不入缓存，防投毒）。
