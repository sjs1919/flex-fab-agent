## Phase 1 — Model 层：config 扩展 → schema / 迁移 / 种子

> **顺序修正（5 角色评估发现）**：migrate.py（T1.2）与 seed.py（T1.3）连库都需要 `get_mysql_dsn()`，故 config 最小扩展为 Phase 1 **第一任务**（原 T2.1 提前为 T1.0），消除 Phase 2→Phase 1 反向依赖。

### T1.0 `config.py` — 最小扩展（DEMO_DATA_SOURCE / MYSQL_DSN 合成）
**变更点**：
1. 读 `DEMO_DATA_SOURCE`（env，默认 csv）
2. `MYSQL_DSN` 从 credentials.local.md 读真实口令 + `.env` 占位符合成（`mysql+pymysql://demo_sched:****@127.0.0.1:3306/demo_scheduling`）；缺口令给明确报错提示（验收清单第 1 条「缺连接串时报错」）
3. 暴露 `get_mysql_dsn()` / `get_data_source()`；**system_config 表的 get_config 全量读取留 M4（C4），本轮不做**

**验收 checklist**：

### T1.1 `demo/schema/schema.sql` — 建表脚本（单一文件）
**变更点**：
1. 建全部表：业务（customer/orders/parts/machines/material/**inventory**）+ 求解输出（schedule_versions/batches/preprocess_tasks）+ 配置（system_config）+ 模拟器/审批（sim_events/state_change_log/approvals/sim_clock）
2. **库存表决策（2026-08-22 用户确认）**：增建独立 `inventory` 表（沿用现有 10 种材料 + 库存字段：id/名称/材料名/库存量/单位/安全库存/采购周期天/单价/tenant_id），`material` 工艺表（SLA/MJS/SLM→rate_mm_h/post_process_hours）保持独立；`load_inventory`/`query_inventory` 走 mysql 不退化
3. 字段类型对齐 v2 §4.1 → v1 §3（id CHAR PK / amount DECIMAL(12,2) / urgent TINYINT / priority INT / due_date DATE / status ENUM / penalty_rate DECIMAL(4,3) / tenant_id VARCHAR）
4. 编码 utf8mb4 + 必要 FK/索引（orders→customer、parts→orders、batches→schedule_versions）

**验收 checklist**：
- [ ] 全部表 CREATE 语句可在 WSL MySQL 执行，无语法错误
- [ ] orders 含 amount/urgent/priority/due_date/status；parts 含包络盒三边/件重；machines 含 process/model_type/cabin_size/max_weight；customers 含 penalty_rate
- [ ] 表所有权符合 v2 §4.2（写方唯一标注于注释）

**验收 checklist**：
- [ ] mysql 路径返回 list[dict]，key=列名，工具层无需改签名
