## 建模方案（A 时钟层 + B 事件层）

### A 层每 tick（+1 sim 小时，单事务）

1. `sim_clock.current_sim_time += 1h`（单行表 id=1）
2. **推进批次**：`待上机` 且 sim_time ≥ start_time 且设备空闲 → `打印中`（设备占用）；`打印中` 且 end_time ≤ sim_time → `静置中`（设备仍被占 C6）；`静置中` 且 post_process_end ≤ sim_time → `完成`（设备释放 status=空闲 current_batch_id=NULL）
3. **推进设备**：打印中/静置中的设备批次状态联动（随批次完成释放）
4. **推进前道**：preprocess_tasks end_time ≤ sim_time → 批次 `前道→待上机`；人效累积速率 × 班次系数（3 班倒 8h+30min 换班 → 净 22.5h/天 = ×22.5/24）
5. **订单到期**：sim 时间过 due_date 截止（当天 23:59）且未完成 → 标记逾期（state_change_log，供负载评估超期预警）

### B 层事件（预排→触发）

事件生成：**开工/触发时按分布预排下次事件时间戳**，插 `sim_events`（status=scheduled，payload_json 含明细）；A 层每 tick 检查到点事件 → 触发（status=fired）→ 写 `state_change_log`。

| 事件 | 分布/参数（system_config，缺省常量） | 触发效果 |
|------|-------------------------------------|---------|
| machine_failure | MTBF 指数（默认 ~96 sim h） | 设备→故障；在跑批次**中断**；若设备无法在批次交期前恢复 → **硬性不可行 → 强「需重排」告警**（sim_events）；预排 repair_done |
| repair_done | MTTR 指数（默认 ~2 sim h） | 维修中→空闲（可再分配）；该设备在跑批次若中断则恢复打印或待重排 |
| new_order | 到达率 Poisson（默认 ~2 单/天） | **插入 1~10 单随机订单**（随机数量/材料/体积/交期/金额，含加急概率）+ 对应 parts → 待排队（软扰动，agent 判断是否重排） |
| order_change | 到达率 | 改交期（更新 orders.due_date）+ 日志；撤单/数量变更留 M4（枚举限制） |
| leave / back | 到达率（前道工人） | 请假→人效下降（6 人池减员，state_change_log personnel）；预排自动回岗 |
| restock | 到达率 | 材料库存到货（inventory 库存量增加）+ 日志 |
| scrap | 批次完成时按坏件率抽检（默认 5%） | 坏件→触发 scrap 事件 + 日志（重打批次生成留 M4，硬性提示） |

### 硬性不可行检测（C 兜底）

每 tick 检查：在跑批次所在设备 status=故障，且**维修完成时刻 > 批次交期（post_process_end/due）** → 该批次标记受影响，生成强「需重排」告警（sim_events，status=fired，event_type=machine_failure payload 含 alert），agent 经工具可见。软性扰动（插单/请假/改交期）不自动重排。

### R-3 scene_version（缓存失效）

`llm_cache.py` 模块级 `_scene_version`（默认 0）：`_cache_key` payload 附 `scene_version`；模拟器每 tick 调 `bump_scene_version()`。同 prompt 在模拟器推进前后 key 不同 → 状态相关查询自动失效。现有测试不受影响（默认版本 0 自洽）。

### D2 span 隔离

模拟器线程用**独立 `Tracer()` 实例**（tracer 模块级单例非线程安全，v2 D2），`runner.py` 内部持有，不碰全局 `tracer`。solver 工具 span 记录 `simulator:tick`（name=`simulator:tick`，attrs 含 sim_time/duration_ms/事件数）。

### 写唯一 + 单事务

- 模拟器写：sim_clock / state_change_log / sim_events / machines(status,current_batch_id) / batches(status 推进) / orders+parts（new_order）/ inventory（restock）
- **单事务原子提交**：每 tick 的多次写入（时钟→批次→设备→状态日志→事件触发）作为一个 `transaction()`；失败整体 rollback（无半写）。连接池复用 data.py `get_connection()`（PooledDB，池 5-10）。业务代码禁裸 pymysql.connect（seed.py 运维豁免已存在）。
