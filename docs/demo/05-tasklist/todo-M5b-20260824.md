## 关键设计（用户 2026-08-24 确认口径）

### 持久化：migration v3 三表

| 表 | 列 | 写入挂点 |
|----|----|---------|
| `kpi_snapshot` | id / sim_time DATETIME / metrics_json TEXT（kpi_metrics 全量）/ tenant_id；KEY idx_ks_time | `simulator/runner.py` `run_tick` 事务提交后（快照反映刚提交的 tick 状态）；写失败仅日志不熔断 tick |
| `cost_record` | id / trace_id / created_at / total_cost / total_tokens / total_calls / by_provider JSON / by_model JSON | `/ask` 调 `cost_tracker.get_summary()` 后 → `dashboard.record_cost(summary)` |

- **口径一致**：kpi_snapshot.metrics_json = kpi_metrics()（与 query_kpi 同源计算）；cost_record = cost_tracker.get_summary()；trace_record = tracer.get_summary()

### kpi_metrics() 抽取（scheduler_tools.py）

- query_kpi() 调 kpi_metrics() + 原格式化（**输出 Markdown 不变**，防验收条 72 回归）

### 只读端点 + 静态 HTML 共用查询层

- `observability/dashboard.py`：`record_kpi_snapshot(metrics)` / `record_cost(summary)` / `record_trace(summary)`（落库）+ `kpi_history()` / `cost_by_model()` / `trace_summary()`（查询，api 端点与静态 HTML 共用）
- 端点返回 `{items:[...]}`；只读端点 viewer/匿名可访问（R-7）

### 踩坑预判（T5b.11 记录区）
1. **JSON 列演进**：kpi_snapshot 用 metrics_json 单列（指标集易演进，避免每加指标就 migration）；前端按 metrics dict 渲染
2. **query_kpi 抽取回归**：kpi_metrics 抽取后 markdown 输出必须与 M5a 完全一致（E2E 断言形状），防验收条 72 回归
3. **快照写失败不熔断**：record_kpi_snapshot 抛错仅日志（观测旁路）；但要带上下文日志，非静默吞
4. **ECharts 体积**：按需引入（echarts/core + LineChart/BarChart），不整包
5. **前端构建 WSL**：Windows npm EPERM；npm install/build 全 WSL
6. **Vite proxy vs CORS**：dev 用 proxy 指 :8000 避免 CORS；生产构建静态托管 + 后端同源
7. **静态 HTML 离线**：不依赖 CDN（内联数据 + SVG），离线可开
8. **by_model 新增回归**：get_summary 加 by_model 不破坏既有 by_provider/预算字段（test_observability 全绿）
9. **csv 模式下 kpi_metrics KeyError 'id'（存量 bug，非 M5b 引入）**：DEMO_DATA_SOURCE=csv 时 load_machines() 返回中文键（machine_id/型号）无 'id'，`{m["id"]:...}` 报错——query_kpi 在 csv 模式从未可用。部署容器未设 DEMO_DATA_SOURCE（默认 csv），M5b 测试一律置 mysql。已记待修（不属本任务范围）
10. **GIL 饿死冷导入**：daemon 线程内重型 import（scheduler_tools → pandas）被主线程忙等饿死，冷导入永不完成 → 超时。修复：import 移到 runner.py 模块顶层
11. **ECharts init 于 v-show 隐藏 div → 0 尺寸图**：`await nextTick()` 后再 init 才拿到真实尺寸
12. **yield_rate Decimal → str 序列化坑（T5b.11 门禁修复）**：`_kpi_yield_rate` 返回 `round(Decimal,4)`，`json.dumps(default=str)` 后快照里 yield_rate 变字符串 "0.9507"，与 on_time_rate(float) 类型不一致，前端若渲染良率会拿到字符串。修复：kpi_metrics() 出口 `float(yield_rate)`（与 delay_total 同模式），E2E 断言随之通过
