## 关键设计

### G1 case_collector（observability/case_collector.py ⭐ 新文件）

- **记录结构**：`{"trace_id", "created_at", "query", "answer", "type", "good", "tools", "judge"}`；type ∈ normal/chitchat/empty；good 三态（true/false/null 未标注，**仅 normal 可标注**）；judge 为 {} 或分数 dict
- **分类规则**：strip 后空串 -> empty；寒暄词表命中（你好/您好/谢谢/再见/早上好 等，独立词表常量）-> chitchat；否则 normal
- **开关**（system_config 类别「调试台」，`get_config` 读，缺省值代码内给）：
  - `case_collection_enabled`：默认 `on`；生产 `off`
  - `sample_rate`：默认 `1.0`；生产 `0.1`（random.random() < rate 才落盘）
  - `judge_enabled`：默认 `off`（on 时落 case 顺带跑 judge）
- 落盘：JSONL 追加写（`open(..., "a", encoding="utf-8")`），进程内加锁防并发写交错（threading.Lock）
- 纯数据层：不 import api/agents；由 /ask 调用（旁路，失败不改变 /ask 响应，同 M5b `_persist_dashboard` 模式）

### G2 tracer 父子树（observability/tracer.py）

- `Span` 增 `parent: Span | None = None`
- `Tracer` 增 `_stack: list[Span]`；`span()` 进入时 parent=栈顶并入栈，退出出栈 -> **嵌套 with 自动成树**；`record()` 无栈语义（parent=None）
- `get_summary()` 的 spans 每项增 `"parent"`（父 span name，顶层为 None）--平铺+父子引用，前端建树；**既有字段不破坏**（trace_record 落库/M5b 测试兼容）

### G3 两级轨迹

- `registry.execute` 的 tool span 增属性：`arguments`（str 截断 200）、`result`（str 截断 200）--链路展示的入参/出参
- `supervisor.orchestrate` 用 `with tracer.span("supervisor:orchestrate")` 包全流程；dispatch_review/dispatch_production 各包 `tracer.span("supervisor:dispatch", agent=...)` -> supervisor 级（一级）与工具调用（二级）
- 单 Agent 模式：llm:call / tool:* 平级时间线（树退化为一层），前端兼容两种形态

6. **cases.jsonl 不入库**：运行时生成（含 query 内容），gitignore
7. **backtest 场景映射保守**：cases 只补可跑通场景，覆盖度断言仍以原场景文件为准，防回归基线（60%）被稀释
8. **GIL 复发**：M5b 教训--测试轮询必须带 sleep；supervisor span 不进 worker 线程，无此问题
9. **⚠️ SPA 路由 vs API 代理前缀冲突（联调实测）**：页面路由 /debug /config 与 vite proxy（/debug /config 前缀）撞，直连返回 FastAPI {"detail":"Not Found"}、/config 返回 API JSON 而非页面。**修法**：页面路由挪到 /portal/*（/portal/debug /portal/cases /portal/config），API 前缀不动（/config 为 API 精确路径无法同路径共存）。**部署注意**：nginx 需对 /portal/* 做 SPA fallback（try_files $uri /index.html）
10. **⚠️ csv 模式订单/评估数据（联调实测根因）**：用户浏览器提问「有哪些订单在排队」→ 无内容。根因三处：① orders.csv 用 M1 T3.1 前旧列名（状态/交期）+ 旧状态枚举（生产中/排期中/待排产）→ query_orders 字段全空、status 过滤全不中 → load_orders 归一为 schema 键 + 新枚举（生产中/即将完成/紧急→打印中，排期中/待排产→待排队）；② machines.csv 无 process 列 → assessment.load_assessment KeyError（重试 4 次，同 T6.1 降级：无工艺不分群回落 n=1，t_window_availability 无 process 跳过）；③ _enrich 空 customer_id 把 csv 自带客户名覆盖为空 → 守卫保留。前端 DebugView 链路树 data.attrs 加 `?.` 防护（防缺 attrs 白屏）。修复后 query_orders(status=待排队) 返 7 单、load_assessment 在途 8/排队 7/完成 0。
