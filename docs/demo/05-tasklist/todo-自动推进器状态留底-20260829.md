## Phase 2 · run_scheduling 可选排除（其他入口不变的前提）

| 任务 | 文件 | 变更点 | 验收 |
|------|------|--------|------|
| T2.1 | `demo/tools/scheduler_tools.py` | `run_scheduling(triggered_by, exclude_order_ids=None)`：load_snapshot 后按 id 集合过滤 `snapshot["orders"]` + `snapshot["parts"]`（order_id 命中即滤），其余照常 solve/persist；不传时行为与现状完全一致 | 单测：传 exclude → 求解输入不含被排除订单、persist 不锁定它们（保持待排队）、版本不关联；不传 → 与现状一致（快照全量进求解） |

**Phase 2 门禁**：`compileall demo` + test_scheduler_tools 全绿。

## Phase 3 · auto_scheduler 守卫（核心）

| 任务 | 文件 | 变更点 | 验收 |
|------|------|--------|------|
| T3.1 | `demo/scheduler/auto_scheduler.py` | `_auto_schedule`：先查待排队订单数（`SELECT id FROM orders WHERE status='待排队' ORDER BY id DESC`）；**≤ top_n** → 跳过本轮排产（log，不调 run_scheduling）；**> top_n** → 取最新 top_n 的 id 列表传 `run_scheduling(exclude_order_ids=...)` | 单测：待排队 ≤ top_n → 本轮不建新版本；待排队 > top_n → 排产后待排队保留 top_n 单（最新 id） |
| T3.2 | `demo/scheduler/auto_scheduler.py` | `_fifo_approve`：审批前查已审核订单数，**≤ top_n** → 跳过本轮审批（版本继续待审核） | 单测：已审核 ≤ top_n → 无版本被通过；> top_n → 照常 FIFO 审批 |

**Phase 3 门禁**：`compileall demo` + test_auto_scheduler 全绿。
