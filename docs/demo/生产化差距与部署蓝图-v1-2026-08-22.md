## 1. 评审发现：需回填重构方案的设计冲突（2 处）

> 这两处是**文档级缺陷**，不补会在 M2/M4 实施时直接撞上，建议进重构方案 §7.7 与 §9。

### R-D1 求解器会被工具沙箱杀死 🔴

- **冲突**：`run_scheduling` 注册进 ToolRegistry 后自动继承 sandbox 超时控制（`TOOL_TIMEOUT` 默认 10s）+ 指数退避重试 3 次；而 CP-SAT 求解 30-50 订单 + 数百 part 的合批问题求解时间无上界。
- **后果**：大概率超时被杀 -> 重试 3 次 -> 每次从头求解 -> 最终工具失败，agent 报"排产失败"。
- **补法**（三件套，进 B1 求解器设计）：
  1. CP-SAT `max_time_in_seconds` 求解预算（如 60s，进 system_config）
  2. 工具级超时覆盖机制（registry 支持单工具覆盖默认 TOOL_TIMEOUT，solver 工具如 120s）
  3. "超时返回当前最优可行解"策略（CP-SAT 支持取 intermediate solution），不报错、报"次优解 + 求解耗时"

### R-D2 无提示注入威胁模型 🟡

- **冲突**：guardrails 管输出、RBAC 管权限，但「用户输入 -> LLM -> 工具调用」链路无威胁分析。合法角色被恶意诱导**高频触发 run_scheduling**，RBAC 挡不住（权限合法），会烧求解预算。
- **补法**（轻量，进 D3 工具治理）：写工具加触发频率/配额约束（如同一角色 5min 内最多 N 次重排，超限拒绝并审计），prompt 注入风险至少在 threat model 文档里成文。

## 2. 部署架构（蓝图）

### 2.1 目标拓扑（生产态）

```
                        ┌────────────────────────────┐
                        │  负载均衡 / API 网关（TLS）   │
                        └──────┬─────────────────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
      ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
      │ api 实例 ×N   │ │ api 实例 ×N   │ │（无状态，可横扩）│
      │ FastAPI 网关  │ │ + Agent 图    │ │               │
      └──────┬───────┘ └──────┬───────┘ └───────────────┘
             │                │
             └───────┬────────┘
                     ▼
      ┌──────────────────────────────┐
      │ 模拟器独立进程（单例 + watchdog） │  ← demo 的 --sim 同进程模式在生产不可用
      │ systemd / K8s CronJob 守护     │
      └──────────────┬───────────────┘
                     ▼
      ┌──────────────────────────────┐      ┌──────────────┐
      │ MySQL（主从，业务库）           │      │ LLM Provider  │
      │ 从库读 / 主库写 / 每日备份      │      │ 主备 fallback │
      └──────────────────────────────┘      └──────────────┘
```

### 2.2 关键架构决策（demo 现状 -> 生产态）

| # | 决策点 | demo 现状 | 生产态 | 理由 |
|---|--------|----------|--------|------|
| D1 | 模拟器进程模型 | `--sim` 与 api 同进程线程 | **独立进程 + watchdog**（systemd Restart=always 或 K8s liveness） | 模拟器线程死 = 世界冻结且无人知；生产必须独立存活 + 心跳监控 |
| D2 | api 无状态化 | checkpoints.db 本地 SQLite | 共享存储（MySQL checkpointer 或 Redis） | api 实例横扩的前提是会话状态不在本地盘 |
| D3 | MySQL 部署 | 本地 3306 单库 | 独立实例 + 主从 + 每日全备 + binlog 增备 | 业务数据唯一事实来源，无备份=不可部署 |
| D4 | 求解器进程内 | CP-SAT 在 api 进程内跑 | 独立 worker（队列触发）或至少独立线程池 + 预算（见 R-D1） | 求解 CPU 密集，阻塞 api 事件循环会拖垮全部请求 |
| D5 | 观测导出 | console JSONL | OTLP -> 常驻 collector（Jaeger/Loki） | 生产需要集中查询，本地文件不可聚合 |
| D6 | 密钥 | `.env` | 环境变量注入（K8s Secret / Vault），**代码与配置分离不变** | .env 只适合单机 demo |

### 2.3 不可用清单（demo 形态直接上生产的硬伤）

1. 单进程线程模拟器（D1）
2. 本地 SQLite 会话状态（D2）
3. 无认证 HTTP 端点（见 §5 安全）
4. 无连接池的 pymysql（评审角色二发现）
5. 追加写无 rotation 的 audit.jsonl / checkpoints.db / cases.jsonl

## 3. 环境规划

| 环境 | 用途 | 数据 | 密钥 |
|------|------|------|------|
| dev | 本地开发 | 种子数据重生成（seed.py） | 个人 key |
| staging | 集成验证 + eval 回归 | 匿名化/仿真数据 | 测试 key（限额） |
| prod | 真实运行 | 主从 MySQL | 生产 key（预算熔断强制开启） |

对应 v2-13（多环境隔离）。**配置差异全部走 system_config + 环境变量，代码零分支**（现有 `config.py` 单入口设计可直接承接）。

## 4. CI/CD（蓝图）

```
commit -> lint(ruff/mypy) -> 单测(mock LLM) -> 集成测试 -> eval 回归(≥7/10 门禁)
      -> build 镜像(WSL/Docker) -> 部署 staging -> 冒烟(/health + /kpi 采样)
      -> 人工审批 -> 部署 prod（滚动）-> 冒烟失败自动回滚
```

- 对应 v2-07（评估接 CI）；`run_all_tests.py` 已是现成 CI 入口
- schema 迁移：**先迁库后发码**（向后兼容两版），回滚见 §7
- 镜像复用现有 Dockerfile/compose（健康检查已有）

## 5. 安全与 SLA（蓝图）

### 5.1 安全（v2-05/06 落地态）

| 层 | 措施 |
|----|------|
| 传输 | TLS 终结于网关 |
| 认证 | HTTP 层 JWT（v2-06）+ 现有 STS/RBAC 不变（工具层纵深） |
| 限流 | 网关 rate limit 按 token 限 QPS（v2-05）+ 写工具配额（R-D2） |
| 注入 | prompt 注入威胁模型成文 + guardrails 输出侧不变 |
| 密钥 | §2.2 D6 |

### 5.2 SLA / 容量（v1 文档缺失，此处定义目标值）

| 指标 | demo 现状 | 生产目标 | 备注 |
|------|----------|---------|------|
| 只读问答 p95 | 未测 | < 8s（LLM 主导，缓存命中 <100ms） | |
| 排产求解预算 | 无上界 🔴 | 60s 预算 + 次优解降级 | R-D1 |
| QPS | 未测 | 10 QPS/实例（起步） | 压测定 |
| MySQL 容量 | 30-50 订单 | 无压力；事件表按月分区 | sim_events 增长最快 |
| 可用性 | 无定义 | 99.5%（单区，允许模拟器延迟追 tick） | 不追 99.99（成本不匹配收益） |

## 6. 监控告警（v2-08 落地态）

| 告警 | 阈值（初值） | 承接 |
|------|-------------|------|
| LLM provider 失败率 | >10%/5min 或连续 3 次降级 | tracer 已有数据 |
| 模拟器心跳丢失 | >2 tick 未心跳 | D1 watchdog 产出 |
| 求解超时率 | >20%/日 | solver span（R-D1 落地后） |
| eval 回归 | <7/10 | CI 门禁 |
| 预算熔断触发 | 即告警 | CostTracker 已有 |
| MySQL 慢查询 | >1s | DB 侧 |

数据源全部已在 demo 埋好（tracer/cost/audit）--这是"埋点先行"设计的前瞻收益，生产只加 collector 与规则，不加代码。
