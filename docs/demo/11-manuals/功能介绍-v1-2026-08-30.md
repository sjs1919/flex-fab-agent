## 一、可用功能

系统围绕「制造业 3D 打印排程排产」的完整业务闭环，分四个能力域：

### 1. 对话式 Agent 助手（v1）

| 功能 | 说明 |
|------|------|
| 单 Agent 问答 | 自然语言提问，Agent 自主调用工具、循环收集信息后综合回答（LangGraph 编排，5 轮安全阀） |
| 多 Agent 协作 | Supervisor 分派到订单评审/生产评估子 Agent，各持受限令牌，RBAC 鉴权 + 审计报告 |
| 合同知识库（RAG） | 向量 + BM25 + RRF 融合 + Cross-Encoder 重排，命中合同原文（含权限过滤） |
| 多轮对话 | 状态持久化（sqlite checkpointer），重启可恢复，`/new` `/switch` 切换会话 |

### 2. 排产求解与模拟（v2，M1-M5b）

| 功能 | 说明 |
|------|------|
| 排产求解器（M2） | OR-Tools CP-SAT 约束规划 + 装箱模型，C1-C9 九大约束校验，产出结构化批次表 + 准交率指标 |
| 生产模拟器（M3） | 事件驱动引擎，订单到达 → 前道 → 打印 → 完成全流程，心跳线程推进仿真时间，设备故障/插单随机事件 |
| 排产工具链（M4a） | Agent 可触发求解、查询排产版本、查模拟事件、审批版本（写工具需权限） |
| 产能评估（M4b） | 负载评估（三区制）、可承诺交期（CTP）、订单跟踪、前道负载、KPI |
| 统计预测（M5a） | 指数平滑 + 移动平均，逐日分材料预测（件数 + 机时） |
| KPI 看板（M5b） | KPI 快照落库 + 只读查询端点 + 零 CDN 静态 HTML 兜底 |

### 3. 自动化闭环（v3，2026-08-25 之后）

| 功能 | 说明 |
|------|------|
| 自动排产调度器 | 容器内后台线程，随模拟器 tick 周期自动排产 + FIFO 自动审批；设备故障/插单事件触发即时重排 |
| 全链路无人值守 | 下单 → 待排队 → 自动生成批次 → 自动审批 → 上机打印 → 完成，同一订单只被打印一次 |
| 订单状态机 | 待排队 → 已审核 → 打印中 → 完成，版本驳回自动回退待排队（带状态守卫） |
| 前道任务生成 | solver 同事务生成前道任务，C9 硬约束前道完成 ≤ 打印开始，前道人池占用率正确统计 |
| 排产幂等 | persist 事务开头原子锁定订单，受影响行数不足整体回滚，防跨轮重复打印 |
| 审批门禁 | 模拟器只推进已通过版本，驳回版本批次永不被推进，前道负载自然回落 |

### 4. Web 控制台 + 调试台（v3）

| 页面 | 路由 | 功能 |
|------|------|------|
| 排产看板 | `/` | KPI 走势（准交率/延期金额双 Y 轴）+ LLM 成本分模型 + Trace 摘要表 |
| 排产调试台 | `/portal/debug` | 自然语言提问 → 两级链路树（工具入参/出参/耗时/成功）+ LLM-as-Judge 打分 |
| 排产审批 | `/portal/schedule` | 排产版本列表 + 通过/驳回（admin token 自动签发） |
| 案例台 | `/portal/cases` | case 统计 + 标注 good/bad + 回放/重跑 + bad→good 转化率 |
| 资源聚合 | `/portal/resources` | 设备/客户/订单/库存/批次/前道/人员 7 类资源 + 人员状态切换 |
| 配置页 | `/portal/config` | 数据源 / 模拟时钟 / 求解器预算 / 调试台三开关 |

## 二、工具集合（18 个）

Agent 能调用的全部工具，注册于 `demo/tools/registry.py`（`build_default_registry`）。

### 订单域（3 个）

| 工具 | 参数 | 说明 |
|------|------|------|
| `query_orders` | status / customer_name / customer_level / process / due_before / due_after / sort_by / limit | 订单列表，8 字段 AND 组合筛选 + 排序 + limit |
| `get_order_detail` | order_id | 单个订单完整信息 |
| `get_production_status` | order_id | 订单当前生产环节/状态 |

### 资源域（3 个）

| 工具 | 参数 | 说明 |
|------|------|------|
| `query_inventory` | material_name / category / stock_below / sort_by | 材料库存（可筛低于阈值） |
| `query_machine_load` | - | 设备负载（运行/空闲/预计释放） |
| `query_customer` | customer_id / customer_name / min_level / sort_by | 客户信息（等级/信用分/延期率） |

### RAG 域（1 个）

| 工具 | 参数 | 说明 |
|------|------|------|
| `search_knowledge_base` | query / top_k | 合同知识库混合检索 + 重排 + 权限过滤 |

### 排产域（11 个）

| 工具 | 参数 | 说明 | 写操作 |
|------|------|------|--------|
| `run_scheduling` | triggered_by | 触发排产求解并落库（幂等锁定待排队订单） | ✅ |
| `query_schedule` | version_id | 查最新/指定版本批次排布 | |
| `query_sim_events` | event_type / status / limit | 查模拟器事件流（插单/故障/请假/坏件） | |
| `approve_schedule` | version_id / action / note | 审批版本：通过/驳回（驳回回退订单） | ✅ |
| `query_ctp` | material / quantity / height_mm / due_date / amount | 最短可交付交期 + 预测校准 + 能否按期 | |
| `query_load_assessment` | - | 产能负载评估（四段报告 + 三区制 + 前道人池） | |
| `query_order_tracking` | order_id | 订单所处环节 + 关联批次 + 前面单据队列 | |
| `query_preprocess_load` | - | 前道人池负载（排队/在途/瓶颈） | |
| `query_kpi` | - | 准交率/延期金额/舱利用率/良率/前道瓶颈 | |
| `query_forecast` | days | 订单量统计预测（分材料件数/机时） | |
| `query_yield` | - | 打印良率（总览→设备→批次→材料 + 改善建议） | |

> 写工具（`run_scheduling` / `approve_schedule`）需 admin token，受 RBAC + 写配额（5min 内最多 3 次）双重治理；graph 执行写工具时自动注入 token。
> 人员/员工无独立 LLM 工具，经 `query_preprocess_load` / `query_load_assessment` + HTTP `GET /resources/personnel`、`PUT /resources/personnel/{pid}/status` 覆盖。

## 三、技术架构

### 3.1 分层架构（自底向上）

| 层 | 模块 | 职责 |
|----|------|------|
| 数据基建 | `schema/` | 19 张表 DDL + 幂等迁移（v1-v4，写方唯一原则） |
| 数据访问 | `tools/data.py` | CSV / MySQL 双模式 + 连接池 + 事务 + 租户过滤 |
| 求解层 | `scheduler/` | CP-SAT 约束求解 + 自动排产调度器 + 产能评估 |
| 模拟层 | `simulator/` | 事件驱动生产模拟器（心跳线程 + 审批门禁） |
| 预测层 | `forecast/` | 指数平滑 + 移动平均需求预测 |
| 工具层 | `tools/` | 18 个工具 + ToolRegistry（O(1) 查找 + 参数白名单 + RBAC） |
| 编排层 | `graph/` + `agents/` | LangGraph 状态图 + 单/多 Agent |
| 知识库层 | `rag/` | 合同混合检索 |
| 权限层 | `auth/` | STS 令牌 + RBAC 守卫 + 写配额 + 审计 |
| 观测层 | `observability/` | Trace + 成本 + KPI 看板 + case 收集 |
| 网关层 | `api.py` | FastAPI 28 端点 + 前端托管 + 自动调度启动 |
| 前端层 | `web/` | Vue3 控制台（6 tab） |

### 3.2 Harness 三层（横切关注点）

```
权限层（auth/）          编排层（graph/ + agents/）      观测层（observability/）
STS 签发/交换令牌        LangGraph 状态图               Span/Tracer 全链路
RBAC 洋葱防御          单 Agent 5 轮安全阀            成本计费 + 预算熔断
写配额滑窗              Supervisor 多 Agent 分派        KPI 快照 + trace 落库
审计日志 JSONL          上下文压缩 + 循环守卫           case 收集治理
```

### 3.3 核心数据流（全链路自动化闭环）

```
tick0   seed 20 订单 → 待排队；7 设备空闲
tickN   AutoScheduler._loop 累计 interval_ticks → run_scheduling
   ├ load_snapshot 只取待排队 + parts 按待排队过滤
   ├ solve 贪心装箱 + CP-SAT 分配 machine_id/start_time
   └ persist 写 versions + batches + preprocess_tasks + 原子锁定 待排队→已审核
            + 全不可行跳过建版本 + 写建版 sim 时刻快照
   → _fifo_approve：早于 topN 自动通过 + 最早待审版本超龄兜底
tick+1  engine.advance_tick：advance_preprocess（前道→待上机，释放人时）
   ├ advance_batches step3（待上机→打印中，锁设备，仅已通过版本）→ 订单→打印中
   ├ advance_batches step1/2（打印中→静置中→完成，释放设备）→ 订单→完成
   └ fire_events：插单/故障 → request_rerun 即时重排
订单完成 → KPI 准交率正确统计 → Dashboard 落库 → Web 看板展示
```

### 3.4 关键设计决策

| 决策 | 为什么 |
|------|--------|
| CP-SAT 而非 LLM 排产 | 精确约束满足是数学规划的地盘；LLM 做定性分析、CP-SAT 做定量求解 |
| 写方唯一原则 | 每张表只有一个写入者，避免并发写冲突和数据不一致 |
| 事件驱动模拟器 | 稀疏事件场景 O(事件数) 远快于逐帧 O(时间×实体数) |
| 排产幂等（事务开头原子锁定） | 同一订单只被打印一次，跨轮/重跑/升级场景不重复打印 |
| 审批门禁 | 模拟器只推进已通过版本，驳回版本不产生生产动作 |
| 两级缓存 | L1 精确命中 <1ms + L2 语义命中 ~50ms，阈值 0.10 防跨实体误命中 |
| 主备 Provider 降级 | DeepSeek 主用，失败自动切火山豆包，调用方无感 |

## 五、可直接使用的例子

### 5.1 快速上手（本地）

```bash
cd projects/agent-training
pip install -r requirements-demo.txt        # 或按 README §2 按需安装
cp .env.example .env                        # 填 DEEPSEEK_API_KEY / VOLC_API_KEY / MYSQL_*

python -m demo.schema.migrate --up          # 0. 建表
python -m demo.main --check                 # 1. 地基自检
python -m demo.main "今天先做哪些订单？"      # 2. 单 Agent 提问
python -m demo.main --init-schedule          # 3. 跑一轮排产
python -m demo.main --sim                    # 4. 启动模拟器（Ctrl+C 停止）
uvicorn demo.api:app --host 0.0.0.0 --port 8000   # 5. 起 API（自动排产调度随启动）
```

### 5.2 浏览器演示（Web 控制台）

```bash
# 后端 + 前端同源托管
uvicorn demo.api:app --host 0.0.0.0 --port 8000
# 浏览器打开 http://localhost:8000/
#   Tab1 看板：KPI 走势 + 成本 + trace
#   Tab2 调试台：输入"帮我查一下所有还在排队的订单"→ 看工具链路树
#   Tab3 审批：G1 跑排产后对版本点「通过」
#   Tab5 资源：7 类资源浏览 + 人员「请假/回岗」
```

### 5.3 HTTP API 例子（curl）

```bash
# 健康检查
curl http://localhost:8000/health

# 提问（单次）
curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" \
  -d '{"query": "现在有哪些紧急订单？"}'

# 多轮对话（带 thread_id）
curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" \
  -d '{"query": "ORD001 能按时交付吗？", "thread_id": "demo-session-1"}'

# 最新排产版本 + 批次
curl http://localhost:8000/schedule/latest

# 排产版本列表
curl http://localhost:8000/schedule/versions

# 自动排产调度器状态
curl http://localhost:8000/scheduler/status

# KPI / 订单跟踪 / 资源
curl http://localhost:8000/kpi
curl http://localhost:8000/order/ORD001/tracking
curl http://localhost:8000/resources/machines

# 写操作（需 admin token）
TOKEN=$(curl -s http://localhost:8000/debug/admin-token | python -c "import sys,json;print(json.load(sys.stdin)['token'])")
curl -X POST http://localhost:8000/schedule/load -H "X-Admin-Token: $TOKEN"
curl -X POST http://localhost:8000/schedule/approve -H "X-Admin-Token: $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"version_id": 1, "action": "通过"}'
```
