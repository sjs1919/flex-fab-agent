## 一、这是什么？

**Understand-Anything** 是一套**多 Agent 流水线**，自动通读整个项目的代码+文档，输出一张结构化的**知识图谱**。它不是简单的调用图，而是带"分层+巡览"的理解结果——从顶层架构到底层实现，一共 10 层、9 步巡览路径，702 个节点、1,569 条边，**全中文**。

简单说：你把项目丢给它，它帮你"读完、整理好、画成图"，你按图索骥就能快速上手。

### 在 flex-fab-agent 项目里的规模

| 指标 | 值 |
|------|-----|
| 节点数 | 702 |
| 边数 | 1,569 |
| 分层 | 10 层 |
| 巡览步骤 | 9 步 |
| 语言 | 中文 |
| 生成日期 | 2026-09-03 |

### 产物位置

| 位置 | 说明 |
|------|------|
| `projects/flex-fab-agent/.understand-anything/` | **主产物目录**（知识图谱 + 配置 + 指纹 + 元数据） |

## 二、三种打开方式（从简到繁）

### ✅ 方式一：单文件 HTML（零环境，推荐新手）

**最省事，啥都不用装。**

1. 打开文件管理器，找到：
   ```
   projects/flex-fab-agent/graphs/viewers/understand-anything.html
   ```
2. 双击，浏览器自动打开（推荐 Chrome / Edge）
3. 你会看到一张可交互的力导向图：
   - **顶部**：最大节点数滑块（防卡顿）、搜索框、图例
   - **左侧**：节点列表
   - **中间**：图谱可视化区
   - **右侧**：点击节点后显示详情

> 💡 小贴士：整个 HTML 是自包含的（ECharts 库+数据全内联），可以单独拷给别人、传网盘、发邮件，对方收到双击就能看，**不需要任何环境**。

### ✅ 方式二：Claude Code 交互看板（边聊边看）

如果你正在用 Claude Code 读这个项目，直接用斜杠命令：

| 命令 | 作用 |
|------|------|
| `/understand-dashboard` | 打开交互看板，看图 + 提问一体化 |
| `/understand-chat <你的问题>` | 针对知识图谱提问，比如 "排产求解的入口在哪？" |
| `/understand --auto-update` | 开启增量自动更新（改代码后图谱自动刷新） |
| `/understand --no-auto-update` | 关闭自动更新 |

**适合场景**：你正在和 Claude 聊代码，想快速定位某个模块、某条调用链，不用自己翻图。

### ✅ 方式三：原始 JSON + 自己处理（高级）

原始数据在 `.understand-anything/knowledge-graph.json`，结构大致是：

```json
{
  "nodes": [   // 702 个节点
    {
      "id": "...",
      "label": "模块名/函数名/概念名",
      "layer": 3,        // 第几层（0=顶层，9=底层）
      "category": "...",  // 分类
      "description": "中文描述",
      "children": [...]   // 子节点
    }
  ],
  "edges": [...],  // 1569 条边
  "tours": [...]   // 9 步巡览路径
}
```

你可以喂给任何图工具（Gephi、D3、networkx）做自定义分析。

## 三、新手怎么读这张图？

### 3.1 先看分层（10 层 = 从宏观到微观）

知识图谱是**分层**的，越靠上越抽象，越靠下越具体：

| 层级 | 大概内容 | 你会看到 |
|------|---------|---------|
| 第 0 层 | 项目顶层定位 | "制造业3D打印智能排产系统" 这类总览 |
| 第 1-2 层 | 核心模块划分 | 数据层 / 求解层 / 模拟层 / 智能体层 / 服务层 / 界面层 |
| 第 3-4 层 | 模块内部组件 | 比如求解层下面有 CP-SAT 求解器、约束、目标函数 |
| 第 5-6 层 | 关键类与函数 | 具体的类名、函数名、核心算法 |
| 第 7-9 层 | 实现细节 | 具体函数、数据结构、配置项 |

**新手建议**：从第 0-2 层开始看，建立整体认知后再往下钻。不要一上来就看第 9 层，会迷路。

### 3.2 跟着巡览走（9 步 = 官方推荐路径）

图谱自带 **9 步巡览（tour）**，是 Understand-Anything 自动规划的"最佳阅读路径"。

在单文件 HTML 的**右侧面板**里找到 "巡览" / "Tour"，按顺序点：

1. **项目定位** — 这东西干嘛的？
2. **整体架构** — 分哪几层？
3. **核心数据流** — 数据怎么流？
4. **关键入口** — 从哪开始跑？
5. **……（依次往下）**

跟着巡览走完一遍，你对项目的理解就有框架了。

### 3.3 常用操作

| 你想做什么 | 怎么操作 |
|-----------|---------|
| 找某个函数/模块 | 顶部搜索框输入关键词，模糊匹配 |
| 只看某一类节点 | 点顶部图例里的颜色，筛选 |
| 节点太多看不清 | 顶部滑块调小"最大节点数" |
| 看节点详细说明 | 点图中的节点 → 右侧面板 |
| 看这个节点连了谁 | 点节点后，图中会高亮相邻节点 |

## 四、结合 Claude Code 的高效用法

### 场景 1："我想快速理解这个项目"

```
/understand-chat 用 3 分钟给我讲清楚这个项目的架构，用中文
```

Claude 会基于知识图谱给你一个精炼的总览，比自己读文档快得多。

### 场景 2："排产求解的入口在哪？我想改它"

```
/understand-chat 排产求解的入口函数是哪个？调用链是什么样的？
```

直接定位到具体文件和行号，不用 grep 半天。

### 场景 3："我改了 xxx 函数，会影响哪些地方？"

```
/understand-chat 我改了 scheduler/solver.py 里的 solve 函数，
哪些地方会受到影响？帮我列出来
```

知识图谱里有调用关系，可以反向推导影响面。

### 场景 4："代码改了，图谱要更新吗？"

- **小改动**（改了几个函数）：不用手动更新，`/understand --auto-update` 会自动增量刷新
- **大改动**（加了新模块、重构了目录）：建议重跑一次，确保图谱准确

> 💡 提示：图谱是**理解工具**，不是实时镜像。稍微旧一点也能用，只要架构没变就行。

## 五、常见问题

### Q1：图谱和实际代码对不上怎么办？

这是正常的——代码一直在改，图谱是某个时间点的快照。

- 如果只是小改动，直接问 Claude `/understand-chat` 它会结合最新代码回答
- 如果改动很大，重跑一次流水线：在项目根目录执行 `/understand` 相关命令

### Q2：702 个节点太多了，我看不过来

几个办法：
1. **先看巡览**（9 步），跟着官方路径走
2. **用搜索**，直接搜你关心的关键词
3. **调最大节点数**滑块，只显示最重要的节点
4. **按层筛选**，先只看 0-3 层建立框架

### Q3：和 codegraph / VibeGraph 有什么区别？

| 工具 | 生成方式 | 内容侧重 | 适合做什么 |
|------|---------|---------|-----------|
| **Understand-Anything** | 多 Agent 理解+总结 | 架构分层、概念、中文描述、巡览路径 | 快速理解项目、入门、宏观视角 |
| **codegraph** | tree-sitter 确定性解析 | 函数/类/变量的精确调用关系 | 精确查找调用链、影响面分析 |
| **VibeGraph** | AST 静态分析 | React Flow 格式的调用图 | 交互式探索调用关系 |

**新手推荐顺序**：先用 Understand-Anything 建立整体认知 → 再用 codegraph 精确定位 → 最后用 VibeGraph 交互式探索。

### Q4：能用来读其他项目吗？

可以。Understand-Anything 是通用工具，在任何项目根目录跑 `/understand` 相关命令都会生成对应图谱（产物默认在项目根的 `.understand-anything/` 下）。
