# 调试台测试用例提示词（v1 · 2026-08-29）

> **用途**：一份可直接粘贴到「排产调试台」提问框的自然语言测试用例集，覆盖当前 demo 支持的全部可测能力（查订单 / 查设备 / 查员工 / 查批次 / 排产下单 / 订单预测 / 审批 / KPI / 良率 / RAG / 仿真 / 调试台自身）。
>
> **前置**：后端已 `DEMO_DATA_SOURCE=mysql` 启动（见 `demo/README.md` / `部署指南-v1`）；写操作（排产/审批/judge/重跑/标注）需 admin token（调试台自动签发，1h 有效）。

## 一、调试台能测什么（摘要）

### 1. 入口与页面

| 入口 | 路由 | 能力 |
|------|------|------|
| **排产调试台** | `/portal/debug` | 自然语言提问 → 触发工具 → 答案 + 两级链路树（入参/出参/耗时/成功）+ judge 打分 |
| **Case 台** | `/portal/cases` | case 列表 / 人工标注 good·bad / 回放 / 重跑 / bad→good 转化率 |
| **配置页** | `/portal/config` | 读写数据源、仿真时钟速率、求解器预算、调试台三开关 |
| **排产控制台** | `/portal/schedule` | 排产版本审批、批次排布查看 |
| **聚合主页** | `/` | 看板 / 调试 / 审批 / 案例 / 配置 tab 聚合 |

### 3. 调试台自身的测试功能（M6 交付）

- **两级链路树**：每次提问后可见 span 树，节点含工具名 / 入参 / 出参 / 耗时 / 成功标记，可定位「LLM 传参对不对、工具是否执行失败」。
- **judge 打分**：对答案语义相关度打分（`answer_relevancy`），点「judge 打分」按钮（需 token）。
- **case 治理**：每次 `/ask` 自动落盘 `cases.jsonl`（分类 normal/chitchat/empty），可人工标注 good/bad、按 trace_id 回放/重跑、统计 bad→good 转化率。
- **配置读写**：数据源 / `SIM_TICK_SECONDS` / 求解器预算 / 调试台三开关。

## 三、使用注意事项

1. **清缓存**：改代码/数据后必须删 `demo/data/cache_db` 并重启，否则语义缓存命中旧答案（换 embedding 模型尤其要清）。
2. **数据源**：确认后端 `DEMO_DATA_SOURCE=mysql`（种子 20 单），csv 模式字段不全会导致「查订单无内容」。
3. **admin token**：写操作（`run_scheduling`/`approve_schedule`）、judge/重跑/标注均需 token；调试台打开时自动签发，失效可手输。
4. **审批门禁**：新排产版本默认「待审核」，`query_schedule`/模拟器推进只认 `approval_status=通过` 的批次——G1 跑完排产后要先 I1 审批，后续负载/KPI 才有数据。
5. **状态枚举**：统一用新枚举（待排队/已审核/打印中/静置中/完成/已驳回）；口吻词（排队/排队中/排产中）会被 `normalize_order_status` 归一，提问用自然语言即可。
