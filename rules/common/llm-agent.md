# LLM 提示词 / Agent 编排规则

## 红线 1：提示词措辞不得暗示系统故障

给 LLM 的系统提示 / 纠错话术 / NUDGE，**禁止使用「工具不可用」「无法完成」「系统故障」等会被模型理解为故障状态的表述**。

- **后果**：模型会据此拒绝任务（「抱歉，我无法完成这个查询…工具已不可用」），而不是纠正行为——答非所问 + 浪费重试 token。
- **反例**：`「工具已不可用，请勿输出任何工具调用语法」` → LLM 误读为工具坏了，拒绝作答。
- **正例**：`「工具结果已收集齐全，请勿再次调用工具，直接基于上述工具查询结果用中文给出最终回答」` → 正向引导基于已有数据作答。
- **通用原则**：纠错话术只描述「该怎么做」，不描述「系统怎么了」。

> 来源：`docs/pitfalls/20260830-汇总步NUDGE措辞误导.md`（trace 8516ffd）

## 红线 2：重试/纠错时附已收集上下文

LLM 输出未解析工具标记等触发重试时，纠错消息应**附上已收集的工具结果摘要**（如 `tool_results` 前 200 字符/条），引导模型基于已有数据作答，避免它「不信结果想再查一次」再次输出工具调用语法。

> 来源：同上

## 红线 3：护栏「必要段落」检查只告警不拦截

`guardrails` 的排产必要段落缺失检查（`缺少必要段落`）仅打印告警、`is_valid=True` 放行。**依赖此检查拦截 LLM 拒绝话术 / 答非所问文本是无效的**——需要拦截的文本必须进「禁止内容」级校验或在编排层（generate_answer）显式处理。

## 适用

- 所有 Agent 系统提示词 / NUDGE / 纠错话术
- LLM 输出重试链路
- 输出护栏规则设计
